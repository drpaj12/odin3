# Odin III: v1.0.5 core options for Loki III L1

Spec: `docs/specs/2026-10-21-v105-core-options-design.md`. Plan:
`docs/plans/2026-10-21-v105-core-options-plan.md`. No ABI change; no version bump (V105-10).

**Goal (Peter, 2026-10-21).** `cone_check` and `raise` take `-const PORT=V` and `submod` takes
`-bus BUSKEY`, so Loki III L1 raises `A == 13` and `Q + 1` cones to word cells and commits buses as
vector ports through the unchanged Python binding.

## Decisions log

1. (Agent default) V105-1 One option name for both passes, `-const PORT=V`, parsed once in `cc_parse_args` (fact 1); `raise -const` exists because `raise` replays the proof's options.
2. (Agent default) V105-2 Whole ports only. A partly constant port (`B[3:1]` constant, `B[0]` a net) is not supported; no L1 claim needs it (the enable counter binds `B_WIDTH=1`).
3. (Agent default) V105-3 Value syntax: decimal or `0b` binary, zero-extended, no truncation, no `x`/`z`. Verilog sized literals (`4'd13`) are not accepted (the `'` would need quoting in scripts).
4. (Agent default) V105-4 The constant spelling is part of `odin3:cone_cell` as given (K-5), like `-param` values; `raise` does not normalise `13` and `0b1101` to one text.
5. (Agent default) V105-5 `raise` reuses a `$_CONST0_`/`$_CONST1_` node outside the group, else makes one (K-6). It never reuses a constant `$sop` (a BLIF zero-input `.names`), which may belong to another group that a later `raise` deletes.
6. (Agent default) V105-6 cone_check and raise change in one PR (`feat/cone-const`) although rule 1 says one pass per PR: `raise` has no new code path that can be reviewed or tested without the `cone_check` change, and shipping one without the other leaves proofs `raise` refuses. `submod -bus` is its own PR (`feat/submod-bus`).
7. (Agent default) V105-7 Option name `-bus BUSKEY` (short, matches `-attr KEY`).
8. (Agent default) V105-8 A malformed `NAME[BIT]` text is an error (B-4) because the attributes come from a tool that should write them right; an incomplete bus is data, so it falls back with a WARN (B-3).
9. (Agent default) V105-9 The new bus code lives in a new file `src/passes/submod/busattr.c` with its functions in `submod_int.h` (the `SM_*` net states move there from `submod.c:26`), so it has a unit test of its own and `submod.c` (746 lines) does not grow much.
10. (Agent default) V105-10 No version bump in these PRs: `CHANGELOG.md` gets the entries under `[Unreleased]`; the release step of v1.0.5 (after v1.0.1 to v1.0.4) moves them and bumps `project(... VERSION)` and `pyproject.toml`.
