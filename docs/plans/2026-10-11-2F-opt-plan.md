# 2F `opt` — Implementation Plan (v1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Yosys 0.55's `opt` family onto the IR, so that on the same input Odin III gives Yosys's cells: `opt_expr`, `opt_merge`, `opt_muxtree`, `opt_reduce`, `opt_share`, `opt_dff`, `opt_clean` and the driver `opt`, with their options, loop and modes.
- They run in Parmys's order (mode P): `opt_expr; opt_clean; opt -nodffe -nosdff; proc; opt`, with `$proc` nodes opaque.
- They export `odin3_opt_expr_run` for `proc`'s step F, and give 2H the S-P splice script.
- The evidence: refinement after every sub-pass call, the same-input differential `opt-diff`, per-rule goldens, sweeps, fuzzing and `bench_opt`.
- Not here: §1's exclusions (`wreduce`, `fsm`, `memory*`, `techmap`, `opt_dff -sat`, …).

**Architecture:** `src/passes/opt/` holds one kit and one file per sub-pass.
- The kit (`kit.c`) does what Yosys's sub-passes do with `connect`/`setPort`, as IR operations: the opt context, constant canonicalisation, `kit_connect` (delete and merge), `kit_rebuild_node` (fresh output nets, then merge back), `kit_new_cell`, the invert map and topological order. Every rewrite is one provenance operation.
- `fold.c` maps a cell onto 2D's `odin3_cval` operators (Yosys `const_*`).
- `ff.c` ports `FfData`. The sub-passes are explicit-stack ports of Yosys's workers.
- The driver `opt` mirrors 0.55's loop. Only `opt_expr` is incremental (a dirty set); everything else is a full O(pins) sweep.
- `$proc` nodes are opaque to every sub-pass, and `opt_muxtree`/`opt_clean` skip modules that hold them.
- Tools live in `tools/opt-check/`.

**Tech Stack:** C17, `src/util`, `src/ir` with IR change D; 2D-2's `cval.h`; 2E-1's `ffinit.[ch]`, `budget.[ch]`, `opt.h` types and `proc_build.[ch]`; `write_rtlil`; Unity; Python 3 stdlib; Yosys 0.55 (`ODIN3_YOSYS055`, `YOSYS_COVER_DIR`, the Parmys plugin for S-P); ABC through `tools/equiv-check`; `tools/heavy-run` (2E point (p)).

**Spec points made exact here** (agent defaults, reversible; Task 19 logs them in PHASE2):

- (a) **Entry-point names.** The fixed hand-off is the module-scope `odin3_opt_expr_run(ctx, module, opts, counts)` (§4.8). The design-scope sub-pass functions of §18 take `odin3_opt_counts *` (point (b)):
  - `odin3_opt_merge_run`, `odin3_opt_muxtree_run`, `odin3_opt_reduce_run`, `odin3_opt_share_run`, `odin3_opt_dff_run` and `odin3_opt_clean_run`;
  - `odin3_opt_expr_design` for `opt_expr`, whose `_run` name is taken.
- (b) **One counts aggregate.** `odin3_opt_counts` holds `odin3_opt_expr_counts expr` (the type 2E-1 froze) plus the other sub-passes' counters and `opt_dff`'s per-action counters. Each sub-pass adds into it, and `--opt-stats` prints from it.
- (c) **Options.**
  - Yosys spellings, plus a `--` spelling of each (`--full` for `-full`).
  - Per pass:
    - `opt_expr`: `-mux_undef -mux_bool -undriven -noclkinv -fine -full -keepdc`;
    - `opt_merge`: `-nomux -keepdc`;
    - `opt_muxtree`: none;
    - `opt_reduce`: `-fine -full`;
    - `opt_share`: none;
    - `opt_dff`: `-nodffe -nosdff -keepdc`;
    - `opt_clean`: `-purge`;
    - `opt`: all of these plus `-fast -noff`.
  - `-full` on `opt_expr` implies `-mux_undef -mux_bool -undriven -fine`, and on `opt_reduce` `-fine`, as in Yosys.
  - `-share_all` and `-sat` are refused as unknown arguments.
  - `--opt-stats` is accepted by all eight; `--opt-full-rescan` by `opt` and `opt_expr`.
  - `--opt-snapshot DIR` spans a script, so it is a CLI option (`main.c`) that calls `odin3_opt_set_snapshot_dir`.
- (d) **The budget message names the running pass** (2E point (d)): `opt needs more than N bytes (the design's budget is 60% of physical memory)` inside `opt`, `opt_expr needs …` for a standalone `opt_expr`, and `proc needs …` inside step F. It is logged unlocated, with `ODIN3_ERR_PARSE`.
- (e) **Pending sub-passes keep `main` green.** Task 4 registers all eight. Until its task lands, a sub-pass is a stub that logs `<pass>: not available yet (2F)` and returns `ODIN3_ERR_INVALID_ARG`, without running. `opt_clean` is real from Task 3. Each later task removes its stub.
- (f) **Per-rule goldens from Verilog move to 2F-6 Task 16.** They need `read_verilog` to IR (2D-5) and, for FF rules, `proc` (2D-6 + 2E-3). Each PR covers every rule it adds with unit tests on RTLIL text through `pb_build`. Each such test records the command that re-derives its expectation: `yosys -p "read_rtlil t.il; <sub-pass> <opts>; write_rtlil -"`, Yosys 0.55.
- (g) **`opt-rules` uses the same input.** Odin III runs `read_verilog -nolatches R.v; proc --noopt; write_rtlil in.il; <sub-pass> --opt-stats; write_rtlil out.il`; Yosys 0.55 runs `read_rtlil in.il; <sub-pass>` under `YOSYS_COVER_DIR`. §20.1's `proc; opt_expr -keepdc` prefix would fire most `opt_expr` rules before the sub-pass under test.
- (h) **Compact point.** `opt` ends with `odin3_design_compact` (IR-6, OP-14). Sub-passes and standalone sub-pass runs never compact.
- (i) **Scripts.**
  - The Phase 2 script is `tools/opt-check/phase2.script`: one line, `opt_expr; opt_clean; opt -nodffe -nosdff; proc; opt`.
  - S-P is `tools/opt-check/sp-splice` (Python), which runs §3's two halves verbatim.
  - While step F is unwired (2E point (f)), both spell `proc; opt_expr -keepdc` for `proc`.
- (j) **Rule counters.**
  - `odin3_opt_rule` lists §4's rules under their Yosys cover names (`const_and`, `eqneq.cmpzero`, `mul_shift.swapped`, …); `const.$<type>` gets one counter per foldable type.
  - A static assert keeps the count ≤ `ODIN3_OPT_EXPR_MAX_RULES` (128).
  - `--opt-stats` prints `opt: rule <name> N` per non-zero counter, then `opt: rule opt_dff.<action> N` for `opt_dff`'s, sorted by name.
- (k) **`opt_dff` actions** are `odin3_opt_dff_action`, in §16's order: `removing never-active <port>`, `handling always-active <port>`, `handling const clock`, `handling D = Q`, `adding SRST`, `adding EN`, `setting constant <v> at bit K`. Each `<port>` value is its own counter: `never_active_en`, `always_active_arst`, ….
- (l) **constbits sees no tie made in the same call.** A D or AD pin that a Q tie in the same `opt_dff` call moved onto a constant net is non-constant for that call. The tie records the pins it moves, mirroring Yosys's `SigMap`, which is built once per worker. A constant set by a rule (e.g. D := the reset value) is constant at once. So a constant pipeline collapses one stage per call (mcml.v: 31 iterations).
- (m) **The in-process 1E check** (§20.2) runs on a module only if it has:
  - no net that `odin3_net_const_value` reads as x or z and that has readers;
  - no word flip-flop or latch (IR change D: no hooks);
  - no `$shiftx`, `$pow` or `$mem`;
  - no `$proc`.
- (n) **lenet.v under the heavy-run caps.** Yosys's lenet.v `opt` side may pass the 5 GiB inner cap (2E point (p); 7.1 GB measured for the whole script). `tests/opt/vtr_expect_fail.txt` pre-lists it as a candidate `out of memory (cap 5G)`, removed if it passes.
- (o) **`order-probe.sh`** reproduces §3's evidence table under `heavy-run`. It is CTest `opt_order_probe` (labels `sweep` and `nightly`), and its output is quoted in the PHASE2 entry.
- (p) **CSE survivors are rebuilt in place** (§25 item 4): `odin3_node_create` with the same type, parameters and pins, then `odin3_node_replace`, with a DERIVED record [survivor, drops…]. `kit_rebuild_node` does that whenever the port signature is unchanged. Otherwise it uses fresh output nets merged back into the old ones.
- (q) **The loop-cap warning names a module.** `opt` loops per design, so the §16 warning names the first module (creation order) that changed in the last iteration.
- (r) **`opt_muxtree`'s budget** counts `eval_mux` calls per module (Yosys's `glob_evals_left`). At 0 the module's results are discarded: warning, no change.

## Global Constraints

- **Code standard:** as the 2E plan's Global Constraints (C17, `-Werror`, lizard limits, no VLA, only `cleanup:`, no `NOLINT`, named constants, `src/util` containers), with `odin3_opt_*`/`odin3_kit_*` exported names. **No recursion in `src/`**: `opt_muxtree`'s `eval_mux`/`eval_mux_port`, `opt_reduce`'s inlining, `opt_dff`'s feedback search and `opt_clean`'s liveness use explicit stacks.
- **Determinism (OP-14):** ID order, topological ties by node ID, no hash-map order reaching the IR; two runs give byte-identical `write_rtlil`.
- **IR discipline (OP-2):** each rewrite builds everything before its first destructive step (`NO_MEMORY` leaves it undone, the IR valid); constants are pins on the canonical constant nets; names are never dropped (IR-2); `$proc` nodes are never evaluated, merged or deleted; every test that builds IR runs `odin3_check_design` FULL.
- **Correctness (OP-13).** Every sub-pass call refines its input; `-keepdc` gives equivalence.
- **Oracle:** Yosys 0.55 for every expectation (commands recorded); 0.69 only nightly.
- **Diagnostics.** §16's exact texts: INFO for pass lines, DEBUG for per-rewrite lines, WARN and ERROR as listed. Every diagnostic test asserts the whole line through a capturing sink.
- **Caps** (named in `src/passes/opt/opt.h`, lowered through `odin3_opt_test_set_limits` in `opt_test.h`):

  | Cap | Value |
  |---|---|
  | `ODIN3_OPT_MAX_ITERATIONS` | 10,000 per `opt` invocation |
  | `ODIN3_OPT_MUXTREE_MAX_EVALS` | 100,000 per module |
  | `ODIN3_OPT_BUDGET_PINS` | a budget check every 2^16 created pins |
  | the design budget | 60% of physical memory, through `odin3_budget_check` (2E-1) |

- **Tests first.**
  - Unity under ASan/UBSan, plus an OOM sweep over each allocating entry point.
  - The gate: `cmake --build --preset debug -j6 && ctest --preset debug -j4`, without `sweep`.
  - `/lint` before each commit; a read-only critique per task; a **Fable** whole-branch review per PR.
- **Heavy runs** (standing rule; 2E point (p)).
  - Every corpus, benchmark, fuzz or differential sweep is a `sweep` CTest run through `tools/heavy-run`: one machine-wide `flock`, a 6 GiB scope, and `memcap` inner caps of 4 GiB (5 GiB for lenet.v, last and alone).
  - Sweeps run smallest input first, after the gate, and never during a build.
  - Implementers run small samples only; the report names the sweeps deferred to the controller.
- **Python**: stdlib only, `ruff check`, `mypy --strict`, `unittest`.

## Review Focus

1. **x in user designs.**
   - Users write `y = s ? a : 4'bx` and `case` defaults of x, and expect Yosys's choices:
     - S = x picks A (the conservative `$mux` rule);
     - `and` with an x bit gives 0 and `or` gives 1 (`bitwise_logic_one_const`);
     - `xor` with x stays x;
     - `-keepdc` touches none of them.
   - The result must refine the source.
   - Pinned in Task 6 (`mux_s_x_picks_a`, `bitwise_and_x`, `bitwise_xor_x`, `keepdc_keeps_x`) and Task 17 (`opt_equiv_probe`: `s ? a : 4'bx` → `a` passes; the reverse fails).
2. **Registers with enables and resets as written.**
   - `if (en) q <= d` gives `$dffe`.
   - `if (rst) q <= 0; else if (en) q <= d;` gives `$sdffe`.
   - `if (en) begin if (rst) q <= 0; else q <= d; end` gives `$sdffce`.
   - `-nodffe -nosdff` (the pre-`proc` run) gives none of them.
   - Pinned in Task 12 (`dff_en_merge`, `dff_srst_then_en`, `dff_en_then_srst`, `dff_nodffe_nosdff`).
3. **Unused sub-module instances and `keep`.**
   - An instance whose outputs the parent ignores is removed, as Yosys does.
   - One with `(* keep *)`, or whose module contains a `keep` wire, stays.
   - Pinned in Task 3 (`clean_unused_instance_removed`, `clean_keep_instance_kept`, `clean_keep_inside_child`).
4. **Constant register pipelines.** Each `opt` iteration removes one stage, as in Yosys (mcml.v: 31 iterations), the loop stops at its fixed point, and the cap is never reached on the corpus. Pinned in Task 11 (`dff_constbits_one_stage`), Task 13 (`loop_pipeline_iterations`) and Task 18 (the corpus's maximum iteration count is logged and stays below the cap).
5. **The pre-`proc` passes on modules with processes (mode P).**
   - `opt -nodffe -nosdff` on a design that still has processes neither crashes nor touches a `$proc`.
   - `opt_muxtree` and `opt_clean` skip such a module with their info lines.
   - The other sub-passes still rewrite the cells around it.
   - Pinned in Task 13 (`opacity_mode_p`), Task 3 (`clean_skips_processes`) and Task 10 (`muxtree_skips_processes`).
