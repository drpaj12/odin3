# 2C Verilog-2005 lexer and parser — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn every Verilog file of a read run, as the 2B stream, into one `UNIT` of the parsed-form 2A AST in one store: a reentrant Flex lexer, a pure LALR(1) Bison grammar for the synthesizable Verilog-2005 subset plus the REJECT forms (zero reported conflicts, a committed allowlist of resolved ones), the `read_verilog [--parse-only]` pass with `-v`/`-y` library resolution, and the oracles that prove it: one case per coverage row through parse → check → print → re-parse → equal plus hand-written trees, a location oracle, every micro and VTR benchmark, fuzzing, and a tree-checking generator compared against Yosys. No elaboration.

**Architecture:** `src/frontends/verilog/verilog.l` (Flex, `reentrant bison-bridge bison-locations`, prefix `odin3_vp_`) scans the stream text with a source-manager segment cursor and hands tokens with `{loc, end, off}` to `verilog.y` (Bison, `api.pure full`, `lr.type lalr`, `%expect 0`). Every grammar action is one `VP(...)`/`VP_ERR(...)` statement around a `vp_*` function in `actions*.c`, which builds the tree bottom-up through the 2A builders (`make`, `mark`/`push`/`make_marked`, `pending_span` for the three reordered kinds) and becomes inert after the first syntax error. `parser.c` drives one stream to one `UNIT` with located errors, recovery at `;`/`endmodule` and a cap of 20; a per-run read context carries the `` `begin_keywords `` stack and the error count across the run's streams. `read_verilog.c` runs the 2B preprocessor per file, parses, resolves libraries, checks `duplicate_module` and unnamed instances, seals and checks the store, and hands it to the design (`--parse-only`) or to 2D's entry (a stub until 2D). Bison and Flex output is generated into `build/<preset>/generated/verilog` and compiled as members of `odin3_core`.

**Tech Stack:** C17, Bison 3.8.2, Flex 2.6.4, `src/util`, `src/ir` (design, strtab), `src/ast` (srcman, store, builders, check, print, dump, equal), `src/frontends/project` (record, 2B-1), `src/frontends/verilog/preproc.h` (2B-2), the 1D pass manager and CLI, Unity, Python 3 stdlib (allowlist comparator, corpus driver, generator), libFuzzer (clang, optional), Yosys (generator comparison, local and CI).

## Global Constraints

- All earlier constraints: C17 with the `-Werror` flag set; functions ≤ 60 lines, CCN ≤ 15, ≤ 5 parameters, no adjacent convertible parameters (use spec structs); no recursion in `src/` (tests may recurse for reference models); no VLA, no `goto` but `cleanup:`; `abort` only in IR check; no `NOLINT`, no `.clang-tidy` or lizard change; `odin3_` snake_case (`vp_*`/`vl_*` for file-static and grammar-internal helpers); named constants; only `src/util` containers; deterministic output; single-threaded.
- **Tools and generated code**: `find_package(BISON 3.8 REQUIRED)`, `find_package(FLEX 2.6.4 REQUIRED)`; Bison `COMPILE_FLAGS "-Wall -Wcounterexamples -Werror"`, Flex `--warn`; outputs only in `${CMAKE_CURRENT_BINARY_DIR}/generated/verilog` (`verilog_parser.{c,h}`, `verilog_lexer.{c,h}`), never committed, compiled as `odin3_core` sources with the measured per-file `-Wno-*` list (expected `-Wno-conversion -Wno-sign-conversion -Wno-sign-compare -Wno-unused-parameter -Wno-missing-prototypes`, each with a CMake comment naming the skeleton construct) and nothing else relaxed.
- **Grammar form**: `%define api.pure full`, `%define api.prefix {odin3_vp_}`, `%locations`, `%define parse.error detailed`, `%define parse.lac full`, `%define lr.type lalr`, `%expect 0`, no `%expect-rr`, points (a) and (d). **Lexer form**: `%option reentrant bison-bridge bison-locations noyywrap nounput noinput never-interactive nodefault warn 8bit`, prefix `odin3_vp_`, `yy_scan_bytes`, one `yyless(0)` (the `BASED` exit), no `yymore`/`unput`.
- **Generated-file hygiene** (checked by `tools/check_rules.py`): every `.y` action is exactly one `VP(` or `VP_ERR(` statement; no `.y`/`.l` action spans more than three lines; `%{ %}`/`%code` blocks hold only `#include` lines and the `YY_USER_ACTION`, `YYLLOC_DEFAULT`, `YYMAXDEPTH`, `YYINITDEPTH`, `YYSTACK_USE_ALLOCA` macros; every `.l` action is one call into `lexer_support.c`.
- Left recursion for every list and operator chain; right recursion only where the language is (`else if`, parentheses, blocks), bounded by §5. Conflicts: zero reported, and the resolved ones equal `tests/verilog/solved_conflicts.txt` (operator lines and two `else` lines, nothing else).
- **Errors**: recoverable errors go through `odin3_vl_report` (located `odin3_diag`, counted, error mode), and lexing and parsing continue; fatal ones (`NO_MEMORY`, `odin3_ast_make`'s depth or child cap, Bison's stack) are reported once and stop the run. A stream with any error yields no `UNIT`; a run with any error destroys the store and returns `ODIN3_ERR_PARSE`. A builder `INVALID_ARG` on user input is a 2C bug, and so is a `check` failure.
- **Caps, exact**: `ODIN3_VP_YYMAXDEPTH` = 8 × `ODIN3_AST_MAX_DEPTH` = 262144 (`YYINITDEPTH` 256, `YYSTACK_USE_ALLOCA 0`); `ODIN3_VP_MAX_ERRORS` 20; `ODIN3_VL_MAX_KEYWORD_DEPTH` 64; `ODIN3_VL_MAX_COMMENT_BYTES` 2^20 (cut, no diagnostic); `ODIN3_VL_MAX_DIRECTIVE_BYTES` 4096; 2A's `ODIN3_AST_MAX_IDENT_BYTES` 4096, `_STRING_BYTES` 2^17, `_TEXT_BYTES` 2^20 checked by the lexer **before** it allocates; `_MAX_DEPTH` 32768, `_MAX_CHILDREN` 2^24, `_MAX_NUMBER_BITS` 2^20, `_MAX_DECIMAL_DIGITS` 4096 through the builders. Each is a located `PARSE` naming the cap, lowered in tests through `odin3_verilog_test_set_limits`.
- Every store built in a test or by Debug `read_verilog` passes `odin3_ast_check(FULL)`. No ABI change in 2C (`odin3_ast_get_library_units_from` lands with 2D's ABI additions).
- Every task: tests first (Unity under ASan/UBSan); every located-error test asserts the exact `file:line:col: error: …` string through a capturing log sink; an OOM sweep (`odin3_util_set_alloc_fail_after`) over each allocating entry point it adds; `ctest --preset debug` green; `/lint` before each commit; commit and push at each green checkpoint; a read-only critique before each PR. Python (`tools/`, `tests/tools/`): stdlib only, `ruff check` and `mypy --strict` clean, `unittest`. Every corpus or benchmark sweep runs smallest input first.

## Review Focus

1. **Netlists Odin III and Yosys write**: structural Verilog from our own 1F `write_verilog` and from Yosys/Parmys is full of escaped names such as `\u1/q[3] `, `\$auto$alumacc.cc:474$12 ` and an escaped name followed by a select (`\a.b [3]`). A user expects them all to read back. Pinned in Task 10 (`verilog_writer_parse`: every `tests/golden/blif/*.blif` → `odin3-write --verilog` → `odin3-parse-check`) and Task 3 (lexer cases for each spelling).
2. **CRLF sources**: Windows-edited files must lex exactly like their LF copies. A `//` comment's text excludes the `\r`, `\r` ends an escaped identifier, and `line:col` is unchanged. Pinned in Task 3 (CRLF twins of the comment, escaped-identifier and string cases, asserting the same tokens, texts and columns).
3. **Edge-of-file shapes**: an empty file, a comment-only file, a file whose last line is `endmodule`, `// c` or `\abc` with no newline, and a file holding only `` `timescale ``. A user expects these to parse: zero, one or several `UNIT` children, no error, and "unexpected end of file" only for a missing `endmodule`. Pinned in Task 3 (tokens and comment ranges) and Task 4 (`UNIT` shapes and the missing-`endmodule` location).
4. **Words reserved only in later standards**: Verilog-2005 code that names signals `logic`, `bit`, `int`, `byte` or `interface` (SystemVerilog keywords), or `uwire`/`generate`/`config` under an older `` `begin_keywords `` set. A user expects these to be identifiers. Pinned in Task 3 (token class) and Task 4 (`wire logic, bit, int;` parses to three declarators).
5. **Non-ASCII input**: a UTF-8 BOM, Latin-1 or UTF-8 bytes in comments and strings, and a non-ASCII byte in code or in an escaped identifier. A user expects comments and strings to be kept verbatim. Bytes elsewhere should give one located error per run of bytes, never a crash or a cascade. Pinned in Task 3 (each case with its exact message) and Task 11 (the raw-byte fuzz mode seeds include a BOM file).

### Task 11: Crash fuzzer, generator and tree oracle against Yosys (§7.5)
**Files:** Create `tests/fuzz/fuzz_verilog.c`, `tools/verilog-gen/verilog_gen.py`, `tools/verilog-gen/compare.py`, `tests/tools/test_verilog_gen.py`; Modify `CMakeLists.txt` (the `ODIN3_FUZZ` option and clang `-fsanitize=fuzzer` block, created here when 2B-3 has not landed it; `fuzz_verilog` target and a 10 s CTest smoke `fuzz_verilog_smoke` with the seeds; CTest `verilog_gen_vs_yosys` with 200 seeds when `ODIN3_YOSYS` is found, label `verilog`).

**Produces:** `fuzz_verilog.c` (`LLVMFuzzerTestOneInput`). The first byte selects the mode: **raw** feeds the remaining bytes as one file through the preprocessor and parser; **token stream** maps each further byte to one of a 64-entry alphabet of spellings (keywords, operators, three `IDENT`s, literals of each form, `(*`, `*)`, `@*`, a `//` comment, a metacomment, `` `timescale 1ns/1ps ``, `;`, `begin`, `end`) joined by blanks.
