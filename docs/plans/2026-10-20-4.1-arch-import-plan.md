# 4.1 VPR-XML import (`read_arch`) Implementation Plan (v1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

v1 (2026-10-20). **Do not start code until the controller approves the spec**
(`docs/specs/2026-10-20-4.1-arch-import-design.md`, questions 1 and 2 in particular). Rule IDs
(X, M, P, L, C, T) are the spec's. Choices the spec leaves open are agent defaults and are logged in
PHASE4 by Task 7.

**Goal:** `read_arch <file.xml>` imports a VPR architecture: the `<models>` become `.o3lib`-model
cell types (the four VTR primitives exactly as `lib/vtr.o3lib`, other models as black boxes), the
pb_type hierarchy becomes an `odin3_arch` fact record (leaves with paths, K, interconnect and
directlist facts), and `write_techlib` dumps the generated `.o3lib` text. No mapping change.

**Architecture:** `src/frontends/arch/`. The XML tree comes from the existing
`src/frontends/project/xml.[ch]` (no new dependency). The importer walks the tree with explicit
stacks (no recursion), fills `odin3_arch`, generates `.o3lib` text and calls
`odin3_techlib_read_text`. The record hangs off the design like the project record.

**Tech stack:** C17, `src/util`, `src/ir` (one container hook), `src/techlib` (unchanged),
`src/frontends/project/xml.h` (unchanged), Unity; shell for the CLI tests.

## Global constraints

- All 1A/1B/1G constraints: C17 `-Werror`, function limits (60 lines, complexity 15, 5 params), no
  recursion, no VLA, no `goto` but one `cleanup:`, no `NOLINT`, `odin3_` snake_case, util-only
  containers, reserve-before-mutate, deterministic output, located `file:line` errors as
  `ODIN3_ERR_PARSE`.
- Never write under `~/odin3-ws/external`; tests read `$VTR_ROOT` and skip (exit 77) when it is
  unset. Test temp files under `/tmp/claude-1000/`.
- No change to `hardmap`, `lib/vtr.o3lib`, the `.o3lib` grammar or any script.
- One PR for the whole item (the pieces share one record type); commit and push after each task.

## Review focus (for the critique agent)

1. A template cell equals the `vtr.o3lib` cell, in port order and parameter names, because
   `hardmap` compares by index (spec section 0 item 2): Task 5 and 6.
2. Width of a model port is the maximum over leaves, not the first or last: Task 3.
3. An arch with no `<models>`, and models with non-identifier names, import without error: Task 2 and 6.
4. A failed import leaves no record and no registered type: Task 5.
5. No recursion in the XML walk on a deeply nested pb_type tree (depth 10,000 fixture): Task 3.

### Task 1: The arch record and the design hook
**Files:** Create `src/frontends/arch/arch.h`, `src/frontends/arch/arch.c`, `tests/unit/test_arch_record.c`; Modify `src/ir/design.h`, `src/ir/design.c` (`odin3_design_get_arch`, `odin3_design_arch`, `odin3_design_drop_arch`, destroy with the design), `CMakeLists.txt` (sources, test).
**Produces:** the types of spec C-1 (`odin3_arch`, `odin3_arch_model`, `odin3_arch_port`, `odin3_arch_leaf`, `odin3_arch_level`, `odin3_arch_ic`, `odin3_arch_direct`) all in one arena; `odin3_arch_create/destroy`; the const accessors of C-2 over empty and hand-built records.
**Tests (first):** create, fill by hand, query every accessor; the design destroys the record; `get` twice returns the same record; `drop` then `arch` is NULL; OOM sweep on create.
**Acceptance:** `test_arch_record` passes under ASan/UBSan; `git diff src/ir` is only the three hook functions and the destroy call.

### Task 2: XML to models (M-1 … M-4)
**Files:** Create `src/frontends/arch/arch_models.c`, `src/frontends/arch/arch_read.h` (internal), `tests/unit/test_arch_models.c`, `tests/unit/data/arch/{models_ok,models_dup,models_sink,no_models,bad_root,unsupported_child}.xml`; Modify `CMakeLists.txt`.
**Produces:** `odin3_status odin3_arch_read_text(odin3_design *design, const odin3_arch_src *src)` (name + bytes; this task fills only the models and returns the record via the design hook after Task 5 wires registration; before that a test entry point `odin3_arch_parse_models` fills a caller-owned record). Parses `<models>`: names, ports in XML order, `is_clock`, `is_non_clock_global`, `clock`, `combinational_sink_ports`; the VPR checks (duplicate model, duplicate port, both flags, unknown sink, sink on an output); unsupported children of `<models>`.
**Tests (first):** the reference model list of `models_ok.xml` field by field; one test per error with the exact `file:line` message of spec section 8; root not `architecture`; BOM and single-quoted declaration; node cap error text.
**Acceptance:** all message texts equal the spec's table; no XML tree node survives past the call (leak check under ASan).

### Task 3: pb_type walk (P-1 … P-4, P-7)
**Files:** Create `src/frontends/arch/arch_pb.c`, `tests/unit/test_arch_pb.c`, `tests/unit/data/arch/{pb_ok,pb_unknown_model,pb_port_dir,pb_deep,pb_k}.xml`; Modify `arch_read.h`, `CMakeLists.txt`.
**Produces:** an iterative walk of every top-level `<pb_type>` under `<complexblocklist>` recording leaves with their paths (pb name, mode name, `num_pb`), ports (`num_pins`, `port_class`), `class`, `num_pb`, lines; LUT K and min K (P-2); model port max/min widths (P-4); `<interconnect>` children with names, `input`, `output`, `<pack_pattern>` children; `<directlist>` entries; `has_adder` (P-7). The checks of P-1 (unknown model, unknown port, direction or clock-ness mismatch).
**Tests (first):** a hand-made hierarchy with two modes, nested `num_pb`, a `.names` of 5 and 6 pins (K 6, min 5), three `multiply` leaves of 9, 18, 36 (model `a` max 36, min 9), two `single_port_ram` leaves (addr 9 and 15); each P-1 error; a 10,000-deep nested pb_type fixture (generated at test time into `/tmp/claude-1000/`) imports without stack growth; an arch with no `<complexblocklist>` (no leaves, K 0).
**Acceptance:** Review focus 2 and 5 pass; leaf order is document order.

### Task 4: Library text (L-1 … L-6)
**Files:** Create `src/frontends/arch/arch_lib.c`, `src/frontends/arch/arch_templates.c` (the four template cell texts and their port signatures), `tests/unit/test_arch_lib.c`; Modify `arch_read.h`, `CMakeLists.txt`.
**Produces:** `odin3_arch_make_library(const odin3_arch *arch, odin3_strbuf *out)`: header comments, `library NAME` (L-1), one cell per registered model in XML order: template when name and port signature match (L-2), else blackbox with maximum widths and `clock` modifiers (L-4); the L-3 warning on mismatch; the M-4 INFO; the M-5 skip with one counted WARNING.
**Tests (first):** (a) each template text read with `odin3_techlib_read_text` into one design and `lib/vtr.o3lib` into another: equal kinds, parameter names/defaults, ports (names, directions, order, clock flags), width expressions, `fn`/`memory` counts (Review focus 1); this test needs no `$VTR_ROOT`; (b) a `multiply` model with a renamed port becomes a black box plus a warning; (c) a model `pcie` with ports of widths 3 and 70 gets exactly those widths; (d) an unused model port is width 1 plus INFO; (e) a non-identifier model name is skipped, counted, and a port named `x` makes its model skipped; (f) the generated text of every fixture parses with the `.o3lib` reader.
**Acceptance:** the template cell stanzas are byte-identical to the stanzas in `lib/vtr.o3lib` after removing comments and blank lines (a string test in this task reads the file).

### Task 5: Registration, `read_arch`, `write_techlib`
**Files:** Create `src/passes/arch_pass.c`, `tests/unit/test_arch_pass.c`, `tests/cli/arch_cli.sh`; Modify `src/passes/builtin.c` and `builtin.h` (two table rows), `src/frontends/arch/arch.c` (`odin3_arch_read` from a path, `odin3_arch_read_text` end to end), `CMakeLists.txt`, `docs/PASSES.md` (two rows).
**Produces:** `read_arch <file>`: `.xml` imports (record + `odin3_techlib_read_text`), `.o3lib` is `read_techlib`'s code path, else the C-4 error; the INFO line of C-4. `write_techlib <file|->` (C-5). A failed import frees the record and registers nothing (C-3, Review focus 4); a second import hits the L-7 error and leaves the first intact.
**Tests (first):** through the pass manager on a fixture: types registered, record present, INFO text; `write_techlib` writes text that `read_techlib` accepts in a fresh design (same types); `write_techlib` with no arch gives the C-5 error; `.o3lib` argument path; bad extension; a failing fixture leaves the design unchanged (type count before and after); `read_techlib lib/vtr.o3lib` then `read_arch` of a fixture with `adder` gives the L-7 error; OOM sweep over the whole import. CLI test: `odin3` script `read_arch <fixture>; write_techlib -` exits 0 and prints `library`.
**Acceptance:** `ctest -R 'arch'` green in the debug preset; `docs/PASSES.md` rows added in the existing column format.
