# 2B Project readers and the Verilog-2005 preprocessor — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a project description (`.o3proj`, `-f`/`-F` lists, Quartus `.qpf`/`.qsf`/`.qip`, Odin II XML last) into the one design-owned project record, byte-identical to the corpus oracle through `read_project; dump_project`, and turn each project Verilog file into the expanded stream plus 2A segment map that 2C's lexer consumes. No Verilog parser.

**Architecture:** `src/frontends/project/` holds the record (`project.[ch]`, PRJ-1..4), the shared word splitter and lexical path resolver, one reader per format (each `read_<fmt>(proj, file, state)`, stop at the first error, one `odin3_diag`), the entry dispatcher and the JSON dump; every project file is a source-manager `FILE` buffer so errors print `file:line:col` plus `included from` chains. `src/frontends/verilog/` holds the preprocessor (PP-1..12): one `odin3_pp` per `read_verilog` run built from a narrow config, a byte scanner over a stack of run-list frames (no text copies), whole-file output per stream, one `EXPANSION` per use and one `MACRO_ARG` per spelled run, segments emitted by the single loc-continuity rule, recursion judged on the spelling ancestry, every §9 cap checked before it allocates. Three passes (`read_project`, `dump_project`, `preprocess`) and CLI flags wire both into 1D's pass manager.

**Tech Stack:** C17, `src/util` (+ `odin3_file_read_all`), `src/ir` (design, strtab), `src/ast/srcman.*` (2A Task 1), 1D pass manager and CLI, Unity, Python 3 stdlib (oracle, corpus harness, pp-diff, pp-fuzz), libFuzzer (clang, optional), Icarus Verilog and Yosys (local differential only).

**Spec:** `docs/specs/2026-10-10-2B-project-preproc-design.md` (binding, including its §6 PR ordering; PRJ-n, PP-n and § numbers below refer to it); `docs/PHASE2.md` #6–#9; `docs/specs/2026-10-09-2A-ast-design.md` §3 (AST-1..3, the srcman contract) and `src/ast/srcman.h` as implemented at `feat/2A-ast` 38080f2; corpus contract `tests/golden/projects/README.md`; oracle `tools/project-fixtures/project_fixtures.py` (normative for the record; amended in Task 2); `docs/DESIGN.md` §4.0, §4.1.

## Global Constraints

- All earlier constraints: C17 `-Werror` flag set; functions ≤ 60 lines, CCN ≤ 15, ≤ 5 parameters, no adjacent convertible parameters (use spec structs); no recursion in `src/` (tests may recurse for reference models); no VLA, no `goto` but `cleanup:`; `abort` only in IR check; no `NOLINT`; `odin3_` snake_case; named constants; only `src/util` containers; deterministic output; single-threaded.
- Every rejection is `ODIN3_ERR_PARSE` after exactly one `odin3_diag` with `<kind>: <detail>` (`kind` one of the thirteen §8 kinds); file-level errors `<file>: error: …` and unlocated ones `odin3: error: …` through `odin3_log`; `IO` only for an existing unreadable file; `INVALID_ARG` for misuse; `NO_MEMORY` drops the record or abandons the run. Readers stop at the first error, arity before semantics, in the oracle's order.
- Every project file and source file is read whole (`odin3_file_read_all`, cap `ODIN3_SRC_MAX_FILE_BYTES`) and registered as a `FILE` buffer with its lines as it is split; LF and CRLF only (a lone `\r` is a character). Nothing resolves against the working directory except the entry (point (i)); paths are lexical, existence by `stat`.
- Strings and paths are design-strtab IDs; `""` is ID 0, so every field that may be empty carries its `has_*`/`present` flag. Values stay text. Counts are ASCII digits, `uint32_t`, else `syntax` "count too large".
- The preprocessor never copies text into frames (run lists only), copies macro bodies and defaults into its arena, caches file bytes by resolved path, and creates buffers exactly per AST-2/§3.1; 2B never creates a `SCRATCH` buffer.
- Every §9 cap is a named constant (`ODIN3_PP_*` in `preproc.h`, `ODIN3_PROJ_*` in `project.h`) checked **before** the allocation or buffer creation it guards, reported as a located `PARSE` naming the cap, lowered in tests through a hidden struct hook (`odin3_pp_test_set_limits`, `odin3_project_test_set_limits`, like `odin3_srcman_test_set_limits`).
- Python (`tools/`, `tests/tools/`): stdlib only, `ruff check` and `mypy --strict` clean, `unittest`. Every corpus or benchmark sweep runs smallest input first.
- Every task: tests first (Unity under ASan/UBSan, `tests/unit/test_project_*.c` / `test_pp_*.c`); every located-error test asserts the exact `file:line:col: error: kind: detail` string through a capturing log sink; an OOM sweep (`odin3_util_set_alloc_fail_after`) over each allocating entry point it adds; `ctest --preset debug` green; `/lint` before each commit; commit and push at each green checkpoint; a read-only critique per PR before it opens.

## Review Focus

1. **Segment and run bookkeeping**: a `MACRO_ARG` run that should split at a buffer boundary but does not, or a return-to-body segment one byte off, puts diagnostics on the wrong column; the §3.1 `OUTER`/`INNER` buffers and segments are asserted exactly and traced by hand by the reviewer — Task 8.
2. **Oracle drift in the small**: word splitting, Tcl continuation, `..` folding (and `//`), `;` lists in `SEARCH_PATH`, `anchored`, `names` order — each tested against the oracle's own behaviour — Tasks 1, 3, 4, 5; the corpus comparison in Task 11.
3. **Directive boundaries**: token-based conditionals mid-line (`wire a = 1 `ifdef X + 1 `else + 2 `endif;`), the end of a `define` text with `//`, `/* */`, strings and continuations, CRLF inside bodies, `translate_off` as opaque text — Tasks 6, 7.
4. **Bombs and caps**: exponential macros stop at `MAX_STREAM_BYTES`, `MAX_BUFFERS_PER_STREAM`, `MAX_LOC_BYTES_PER_STREAM`, `MAX_LIVE_RUNS` or `MAX_EXPANSION_CHAIN` within the fuzzer's timeout; recursion is caught on the spelling ancestry before any cap; every cap precedes its allocation; frames list runs, never copy actuals — Tasks 8, 9, 13.
5. **Error locations and ordering**: where a `-f` cycle, a `qip_cycle`, an `unknown_revision` or a `set_parameter -entity` error is located, and that each reader stops at the first error in the oracle's order; every negative case runs in every format — Tasks 3, 4, 5, 11.
