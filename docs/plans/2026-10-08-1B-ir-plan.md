# 1B IR core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/IR.md` v2 in `src/ir/`: typed IDs, values, cell-type registry and built-in cells, design/module/node/pin/net/wire with names, aliases and attributes, provenance lineage, `check`, `compact`, and a 2M-node benchmark.

**Architecture:** Handles (`odin3_design *`, `odin3_module *`) are opaque pointers; every IR object is a typed 32-bit ID into per-module `odin3_pagevec` stores (1A). Nets own partitioned pin arrays from a per-module size-class pool. Provenance records are design-global, hash-consed through `odin3_idindex`, keyed by pass run and operation.

**Tech Stack:** C17, CMake presets (`debug` = ASan+UBSan), Unity, `src/util/` (arena, vec, pagevec, hash, u64map, idindex, str, log).

**Spec:** `docs/IR.md` (semantics, authoritative) and `docs/specs/2026-10-08-1B-ir-design.md` (files, names, tests). Read both before any task.

## Global Constraints

- All 1A global constraints apply (C17 `-Werror` flags; complexity ≤ 15, ≤ 60 lines, ≤ 5 params; no adjacent convertible params; no abort/exit/goto/VLA/recursion; never NOLINT; `odin3_` snake_case; i/j/k only; all heap via `odin3_util_*` or util containers; file header comments; deterministic).
- Every IR object reference is a typed ID (IR-5); no pointer to an IR object escapes an accessor's statement (pagevec addresses are stable, but callers hold IDs).
- No code outside `src/ir/` writes an IR struct field (IR-15); structs are defined only in `src/ir/*.c` or a private `src/ir/ir_internal.h`.
- Slot 0 of every store is a reserved dummy; `.v == 0` means none.
- Fallible calls return `odin3_status`; on failure the IR is unchanged.
- Misuse detectable in O(1) → `ODIN3_ERR_INVALID_ARG` + `odin3_log(ODIN3_LOG_ERROR, …)`.
- Iteration over a store is ID order, skipping dead objects (IR-16).
- Tests: `tests/unit/test_ir_<area>.c` via `odin3_add_unit_test`; test-only corruption hooks live in `src/ir/ir_test.h` (hidden, never exported; `abi_exports` checks).

## Review Focus

1. A net whose only driver is deleted, then a new driver connected: partition boundary and `driver_count` stay right — test in Task 3.
2. `odin3_net_merge(keep, drop)` where `drop` is a port net (`$port_out` sink) and both have names: names become aliases, port stays connected, `check` clean — test in Task 4.
3. Provenance of 100 `$add`s from the same source location, each lowered in its own operation: 100 distinct `DERIVED` records; gates of one `$add` share one record — test in Task 5.
4. `compact` after deleting every second node: output (ID) order of live objects preserved, name maps rebuilt, tombstones written, `check` clean — test in Task 7.
5. A BLIF-style `.blackbox adder` redeclared after a `hard` `adder` is registered: compatible → reused; port width mismatch → `ODIN3_ERR_INVALID_ARG` — test in Task 2.
