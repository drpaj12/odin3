# 1C BLIF reader/writer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read every golden BLIF into the IR and write it back identical under `netlist-compare`, with every name and the model/port/cell order kept.

**Architecture:** A line-oriented lexer yields directives with line numbers; a two-pass reader (headers, then bodies) builds modules, ports, black boxes and cells through the `src/ir` API with `IMPORTED` provenance; a writer walks modules and nodes in ID order. A C driver plus a script runs the round trip over the golden tree.

**Tech Stack:** C17, `src/util`, `src/ir` (1B), Unity, `tools/netlist-compare` (Python).

**Spec:** `docs/specs/2026-10-08-1C-blif-design.md`; IR semantics `docs/IR.md`.

## Global Constraints

- All 1A/1B global constraints apply (see `.superpowers/sdd/<plan>/context.md` written by the controller: C17 `-Werror`, function size/complexity/params limits, no adjacent convertible params, no abort/exit/goto/VLA/recursion, no NOLINT, `odin3_` snake_case, util-only containers, deterministic).
- The reader and writer use only `src/ir` functions (IR-15); no IR struct field access.
- Errors are `file:line: message` via `odin3_log`, returned as `ODIN3_ERR_PARSE`.
- Large inputs: the largest golden is ~150 MB; read in buffered chunks, never quadratic in file size, peak memory proportional to the IR.

## Review Focus

1. A `.subckt` naming a model that is defined later in the file — test in Task 3.
2. Port names like `a[0] b a[1]` (non-consecutive bits) stay three scalar ports in order — test in Task 2.
3. A `.names` with zero inputs and an empty cover (constant 0) and with a `1` row (constant 1) round-trips — test in Task 4.
4. A continuation line in the middle of a `.subckt` formal list and a `#` comment after a cover row — test in Task 1.
5. A net that is both a primary input and a primary output (`.inputs x`, `.outputs x`) — test in Task 4.

### Task 1: Parse status and lexer
**Files:** Modify `include/odin3/odin3.h` (`ODIN3_ERR_PARSE`, status count, `ODIN3_ABI_VERSION` 2), `src/api/version.c`, CLI version test regex; Create `src/frontends/blif/lexer.h`, `lexer.c`, `tests/unit/test_blif_lexer.c`.
**Produces:**
```c
typedef struct odin3_blif_lexer odin3_blif_lexer;          /* opaque */
typedef struct odin3_blif_line { const odin3_bytes *tokens; uint32_t count; uint32_t line; } odin3_blif_line;
odin3_blif_lexer *odin3_blif_lexer_open(const char *path);  /* NULL + log on I/O error */
/* next logical line (continuations joined, comments stripped, blank lines skipped);
   returns false at EOF; tokens valid until the next call */
bool odin3_blif_lexer_next(odin3_blif_lexer *lx, odin3_blif_line *out);
odin3_status odin3_blif_lexer_status(const odin3_blif_lexer *lx);   /* OK, IO, NO_MEMORY */
void odin3_blif_lexer_close(odin3_blif_lexer *lx);
```
Tests: tokens and line numbers (line = first physical line of the logical line); `\` continuation incl. mid-`.subckt` (Review Focus 4); `#` comments anywhere incl. after a cover row; tabs; CRLF; a 2 MB single logical line; a file without trailing newline; missing file → NULL + logged error; OOM sweep.

### Task 2: Reader pass 1 — models, ports, black boxes
**Files:** Create `src/frontends/blif/reader.h`, `reader.c` (pass 1 part), `tests/unit/test_blif_reader.c`; fixtures under `tests/golden/blif/` as needed.
**Produces:** `odin3_status odin3_blif_read(odin3_design *design, const char *path);` (Task 3 completes it). Pass 1: modules in file order (first = top), ports via `odin3_module_add_port` with the grouping rule (consecutive `a[0..w-1]` → vector port, else scalar, never reordered — Review Focus 2), black boxes via `odin3_celltype_declare_blackbox` (formals grouped the same way), `.clock` names kept as a module attribute. Errors: duplicate model, `.end` missing, port declared twice.

### Task 3: Reader pass 2 — bodies and provenance
**Files:** Modify `reader.c`; tests in `test_blif_reader.c`.
`.names` → `$sop` via `odin3_node_create_connected` (nets created on first reference); `.latch` → `$_DFF_P_`/`$_DFF_N_`/`$_DLATCH_P_`/`$_DLATCH_N_`/`$_FF_` with `INIT` (default 3; `as` and unknown types → parse error); `.subckt` → node of the named type (module or black box), formals by name or `name[k]`, unlisted formals unconnected, unknown formal → parse error; `.cname`/`.attr`/`.param` on the previous cell. Provenance: one pass run `read_blif`; `IMPORTED` record per object with `{file, line}`. Tests: every construct, Review Focus 1 (forward model reference), cover row width mismatch → parse error at that line, multiple drivers allowed (check flags them later), `odin3_check_design` FULL is clean after reading every fixture.

### Task 4: Writer
**Files:** Create `src/backends/blif/writer.h`, `writer.c`, `tests/unit/test_blif_writer.c`.
**Produces:** `odin3_status odin3_blif_write(const odin3_design *design, const char *path);` Per spec "Writer". Tests: read→write→read of every fixture gives the same module/port/node/net counts and names; Review Focus 3 and 5; generated names for unnamed nets are stable and unique; long lines wrap; write failure (unwritable path) → `ODIN3_ERR_IO`.

### Task 5: Round-trip driver, fixtures, golden run
**Files:** Create `tools/blif-roundtrip/odin3-blif-rt.c` (built as target `odin3-blif-rt`, linked to `odin3_core`), `tools/blif-roundtrip/blif-roundtrip` (bash: for each `*.blif` with a matching `status=ok` `.prov` under a golden root, run `odin3-blif-rt`, then `netlist-compare`, then a name-set comparison; print a table and a summary; exit 1 on any failure), `tests/golden/blif/README.md` (fixture origin); Modify `CMakeLists.txt` (CTest `blif_roundtrip_fixtures` over `tests/golden/blif/`), `docs/PHASE1.md` (results).
Run over `~/odin3-ws/golden` (all 1846 ok BLIFs, release build, parallel `-j` bounded to the WSL memory rules); every failure is fixed in the reader/writer (TDD: reduce it to a fixture first). Record pass counts, the slowest file's time and peak RSS in `docs/PHASE1.md`.
