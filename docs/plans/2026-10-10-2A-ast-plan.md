# 2A Source manager, AST, symbol table — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The front-end data structures every HDL reader shares: a Clang-style source manager with macro and include chains, an append-only arena AST with a normative slot table and a builder-enforced depth cap, the symbol-table structures 2D fills, a Verilog printer for 2C's parse–print–parse oracle, and their C-ABI mirror. No parser.

**Architecture:** `src/ast/srcman.*` owns buffers (FILE, EXPANSION, MACRO_ARG, SCRATCH) in one 32-bit location space, line maps and per-stream segment maps; every decode is a loop over buffer records. `src/ast/ast.*` stores 24-byte node records in a pagevec with a child-index vec, payloads in an arena, an attribute u64map and a comment side table; `kinds.*` expands one `ODIN3_AST_KINDS(X)` X-macro into the slot table that `make` and `check` enforce. Walks, printing, dumping and comparison run on explicit stacks sized from the store's recorded maximum height. The design owns the source manager and the per-run ASTs (each AST owns its symbol table).

**Tech Stack:** C17, `src/util`, `src/ir` (design, strtab, prov, value), `src/backends/verilog/escape.c` (identifier escaping), Unity, cffi (Python helpers).

**Spec:** `docs/specs/2026-10-09-2A-ast-design.md` (binding; section and AST-n numbers below refer to it); PHASE2 #6–#8; test inputs from `docs/specs/2026-10-09-2C-verilog-coverage.md`; IR.md conventions (IR-5, IR-12, IR-18).

**Ordering:** 2A starts from main as it is (ABI v2). 1D (`feat/1D-abi`, ABI v3, pass registry, `src/api/*`, Python layer) is **not merged**: Tasks 1–7 need nothing from it; Task 8 needs it and runs last, rebased onto whatever ABI version main has by then (expected 3 → 2A takes 4).

## Global Constraints

- All earlier constraints: C17 `-Werror` flag set; functions ≤ 60 lines, CCN ≤ 15, ≤ 5 parameters, no adjacent convertible parameters; no recursion in `src/` (tests may recurse for reference models); no VLA, no `goto` but `cleanup:`; `abort` only in IR check; no `NOLINT`; `odin3_` snake_case; named constants; only `src/util` containers; deterministic output; single-threaded (IR-17).
- Typed IDs internally, `struct { uint32_t v; }`: `odin3_ast_id`, `odin3_loc`, `odin3_srcbuf_id`, `odin3_scope_id`, `odin3_sym_id`; 0 = none; slot 0 of every store reserved.
- **Plain-data structs are ABI-shaped from the start**: `odin3_ast_spec`, `odin3_srcfile_spec`, `odin3_expansion_spec`, `odin3_segment`, `odin3_srcpos`, `odin3_ast_comment_spec`, `odin3_scope_spec`, `odin3_symbol_spec` use raw `uint32_t` fields (typed IDs only in function parameters and returns) and end in `uint32_t reserved[2]` (zero; non-zero is `INVALID_ARG`), so Task 8 moves them into `odin3.h` unchanged.
- `_Static_assert(sizeof(odin3_ast_node) == 24)`; the field list of §4.1 is the contract; the layout stays behind accessors.
- Status use (§10): `INVALID_ARG` = builder/accessor misuse, logged; `PARSE` = input rejected, always a located message through `odin3_diag`; `NO_MEMORY` = allocation or ID exhaustion with every store, stack and handed-out ID unchanged (reserve before mutate).
- Caps, exact: `ODIN3_AST_MAX_DEPTH` 32768; `ODIN3_AST_MAX_NUMBER_BITS` = `ODIN3_READER_MAX_WIDTH` (2^20); `ODIN3_AST_MAX_DECIMAL_DIGITS` 4096; `ODIN3_AST_MAX_STRING_BYTES` 2^17; `ODIN3_AST_MAX_IDENT_BYTES` 4096; `ODIN3_AST_MAX_TEXT_BYTES` 2^20; `ODIN3_AST_MAX_CHILDREN` 2^24; `ODIN3_SRC_MAX_FILE_BYTES` 2^28; `ODIN3_SRC_MAX_BUFFERS` 2^24; node and child-table length 2^32 − 2.
- The AST is append-only and immutable after `finish`; no delete, no clone, no tombstones. Strings go to the design strtab; payload bytes and comment text to the AST arena.
- Every task: tests first (Unity, `tests/unit/test_ast_<area>.c`, registered with `odin3_add_unit_test`), an OOM sweep with `odin3_util_set_alloc_fail_after` asserting unchanged counts for every allocating entry point it adds, `ctest --preset debug` green, `/lint` before each commit, commit and push at each green checkpoint.

## Review Focus

1. A diagnostic whose chain makes the message longer than `ODIN3_LOG_BUF` (1024 bytes; e.g. 40 nested macro arguments) arrives as **one** log message whose first line is the intact `file:line:col: error: …` header (util/log cuts the tail with `...`) — test in Task 1.
2. Line/column at file edges: a token ending at end of file (`end` = one-past-the-end loc of the buffer), a file without a final newline, an empty file (len 0: still one loc, decodes 1:1) and CRLF text (lines split on `\n` only, `\r` counts as a column byte) — test in Task 1.
3. An unsized based literal wider than 32 bits (`'h1_0000_0000`, 33 bits) keeps all 33 bits with no truncation warning; `'hF` pads to 32 — test in Task 3.
4. The printer re-escapes keyword names (`\wire `) and keeps an escaped identifier whose bytes are `g[3]` (`\g[3] `) distinct from generate block `g` with index 3 (`g[3]`) — test in Task 6.
5. Absent optional slots (child ID 0) and abandoned unreachable roots: `walk`, `cursor`, `print`, `dump`, `equal` and `check` skip or report them without faulting — tests in Tasks 3, 5, 6.
