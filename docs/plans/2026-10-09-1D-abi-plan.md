# 1D Pass manager, C ABI v0, Python walk — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pass manager with built-in passes and a CLI script runner; the public C ABI for the IR; a Python plugin that walks the IR (Phase 1 exit test).

**Architecture:** `src/passes/manager.{h,c}` holds the global pass registry and `odin3_pass_run` (pass run + check around + timing); built-in passes wrap the readers/writers/check/compact/stats; `src/api/*.c` implement the ABI as thin, NULL-checking wrappers over `src/ir`; `src/cli/main.c` parses `-p` scripts; `plugins/python/odin3.py` adds a Pythonic layer over the cffi binding.

**Tech Stack:** C17, `src/ir`, `src/frontends/blif`, `src/backends/*`, `src/techlib`, cffi (Python).

**Spec:** `docs/specs/2026-10-09-1D-abi-design.md`; spec §15.3; IR.md. **Ordering:** after 1C merges (BLIF passes); writer passes are added as 1F lands, the `sim` pass as 1E lands.

## Global Constraints
- All earlier constraints; plus ABI rules from the spec (only `odin3_` exports — the `abi_exports` test enforces it; cdef block free of attributes/preprocessor; purpose/ownership/failure paragraph per function; NULL handles → INVALID_ARG at the ABI boundary).

## Review Focus
1. `odin3_pass_run` of a pass whose post-check fails returns ODIN3_ERR_CHECK and logs which rule — test in Task 1.
2. A string returned by the ABI is documented as valid until the next IR mutation, and a test mutates and re-fetches — Task 2.
3. A plugin-registered cell type built from the ABI's plain-data struct (with reserved slots zeroed) creates nodes — Task 3.
4. Python walking a golden fixture gives exactly the C `stats` counts — Task 4.
5. A CLI script with an unknown pass name fails with a located message and nonzero exit — Task 1.
