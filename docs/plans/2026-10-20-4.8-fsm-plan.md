## Deviations

Every deviation from the spec, with its reason; agent defaults are logged in PHASE4 decision 12.

1. The decision number is 12, not 11: main already held decisions 9 to 11 after the merge.
2. `fsm_opt` O-1 (unused outputs) is skipped on the first call, as in Yosys where no `unused_bits`
   exist yet; the second call uses the native unread-and-not-a-port query (Q2).
3. A `keep` wire counts as used by that query (safer than Yosys).
4. A control-output alias is a one-bit `$reduce_or` buffer, not a net merge (nets are already
   merged in the IR).
5. Odin III's `proc` makes no `$memwr..._EN` registers, so Q8 (the RAM write-enable 2-state FSMs)
   has nothing to port; the difference belongs to the 2E divergence list.
6. Seven for-loop micros are listed `native-detect`: Odin III's `proc` keeps no flop for the dead loop
   variable `i`, which Yosys marks and then rejects in extract.
7. Hand-built unit tests use `tests/unit/fsm_table.h`; the netlist-compare identity check (T-3 item
   4) is not implemented.
8. `ceval` excludes sequential drivers (Yosys ConstEval has combinational cells only).
9. The recode log line adds "was W" (the original width).
10. There is no separate `test_fsm_probe` ctest; `python_tools` runs the Python tests.
11. `fsm-diff` on the VTR designs: stereovision1 and mcml show Odin III logging an alias wire of a
    rejected register as a second rejection (nets are merged); blob_merge's baseline differs by 5
    `$dffe` in `opt` (Odin's opt_merge merges five $dffe with identical D and EN, which is legal;
    Yosys `opt -fast` merges them only after fsm; so the baseline-relative delta differs and the
    cell histograms after fsm are identical); all three are in `tests/fsm/diff_expect.txt`.
12. **D16** (hardmap-diff blob_merge): latch count equals Parmys's (575) but abc dsec says not
    equivalent. Isolated 2026-10-20 (outcome A, evidence in PHASE4 decision 12): `fsm-equiv --odin`
    on blob_merge.v proves Odin III's `fsm; opt` equivalent to its `proc` from reset (iReset held

13. **Extraction order** (X-5): Yosys `fsm_extract` rewires the logic of the first FSM before it
    looks at the next wire, so when FSM B reads FSM A's control outputs, B's evaluation sees A's
    outputs undriven. Odin III's extract never mutates the IR, so B is evaluated through A's intact
    old logic. Only `tests/fsm/two_fsm.v` covers it; the risk is low.
14. **One FSM per register** (review H1): Odin III nets are merged, so two named wires over one
    state register (`wire w = st`) are both marked. Extract skips a wire whose `$dff` an earlier
    instance already took and logs the same failure Yosys gives its second wire (`state selection
    tree is not closed`). `tests/fsm/alias_wire.v`, `test_alias_wire_extracted_once`, and three
    `fsm/alias_wire` lines in diff_expect.txt (the marking and the failure differ, the FSM does not).
15. **All-zero start of one-hot FSMs** (as Yosys and Parmys): a recoded one-hot register without an
    async reset (sync-reset FSMs: blob_merge, ch_intrinsics) powers up all-zero, an illegal state
    with no outgoing transition; the binary original started in state 0. Anything that simulates
    from the all-zero start (ABC dsec, equiv-check) sees another machine. `fsm_opt` O-0 also removes
    a no-reset state without an incoming transition (reset_state is -1), as Yosys does.
16. **`$memwr` write-enable registers** (Q8, ruling 8): Odin III's proc makes none, so the 17
