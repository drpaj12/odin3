# 4.2 to 4.7 arch-driven partial mapping (`partial_map`) Implementation Plan (v1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

v1 (2026-10-20). **Do not start code until Peter approves the spec**
(`docs/specs/2026-10-20-4.2-partial-map-design.md`, questions 1 to 9, 13 and 15 in particular).
Rule IDs (S, B, X, R, C, F, G, D, T) and question numbers are the spec's. Choices the spec leaves
open are agent defaults and are logged in PHASE4 (Task 21).

**Goal:** `partial_map` replaces `hardmap`. With no arch record, or with the k6 record, its output
equals 3C's byte for byte. With another arch record it takes the multiplier width, RAM depth
limit and the presence of `multiply`, `adder` and RAM models from the record, splits oversize
multipliers, binds generic blocks, and (declared, off by default) maps FFs.

**Architecture:** the 3C code moves to `src/passes/partial_map/` (a rename), reads one `pm_rules`
struct instead of constants, and gains rule files per item. `src/frontends/arch/` gains read-only
accessors and the `--ff-file` reader. No IR, ABI or `.o3lib` grammar change.

**Tech stack:** C17, `src/util`, `src/ir` (unchanged), `src/frontends/arch` (4.1), Unity; Python
(stdlib, `ruff`, `mypy --strict`, `unittest`) for the two new tools; shell for CLI tests.

## Global constraints

- All 3C constraints: C17 `-Werror`, functions at most 60 lines, complexity 15, 5 parameters, no
  recursion (the oversize split uses a worklist), no VLA, no `goto` but one `cleanup:`, no
  `NOLINT`, reserve-before-mutate, transactional per source cell (3C H-9), deterministic output.
- Never write under `~/odin3-ws/external`. Tests read `$VTR_ROOT` and skip (exit 77) when unset.
- **Every test that writes files makes its own temporary directory** (`mkdtemp` in C,
  `mktemp -d` under `${TMPDIR:-/tmp}` in shell, `tempfile.TemporaryDirectory` in Python) and
  removes it. No test names a fixed path. (`/tmp/claude-1000` is for an agent's own scratch only.)
- No wait loops; heavy jobs go through `tools/heavy-run`, one at a time, lanes idle, smallest
  input first.
- Merge, not rebase; no force push; commit and push after each task; `/lint` before every commit.
- **Identity gate (T-2) on every PR after the shell:** tier 1 in CI, tier 2 locally. A PR that
  breaks it does not merge, and no list absorbs a difference.
- Model and effort (PHASE0 §9): rule files Opus `xhigh` to `high` with the advisor; rename, tools
  and fixtures Sonnet or Opus `high`.

## Review focus (for the critique agent)

1. The k6 identity (spec T-2): same bytes from `hardmap`, `partial_map` with no record, and
   `partial_map` with the k6 record. Tasks 3 and 4.
2. Every constant that was 36, 15, 1, 3 in 3C comes from `pm_rules`, with no second copy. Task 3.
3. The oversize split is correct for all operand widths and keeps Parmys's multiply and adder
   counts. Task 14.
4. `memory_merge` extracts the R-8 code without a behavioural edit. Task 5.
5. A missing model is "soft, one INFO" with a record and the H-3 error without one. Task 3.
6. Transactions: on `NO_MEMORY` the source cell is intact (OOM sweep per rule). Every rule task.
7. FF mapping is off unless `--ff-file` was given. Task 18.

## Risks

1. **Identity.** A hidden second copy of a constant, or a changed iteration order, breaks byte
   identity. The grep test (Task 3) and the three tiers are the guard; tier 3 is the only one that
   sees the 19.
2. **Provenance names.** The pass name appears in DERIVED records. If a `.prov` or a `prov` style
   BLIF name embeds it, identity needs the old name for the record; Task 2 checks and, if so,
   keeps the record's pass name `hardmap` (an agent default to log).
3. **Parmys's oversize adder widths** are read from code, not measured; Task 1 decides.
4. **Goldens for k4_N4** may not exist for designs with `$mul` or memories.
5. **VPR packing of a 27-wide `multiply` into the 18x19 leaf** is not verified here; 4.13 shows it.
6. **Branch conflicts.** PRs B to E touch `partial_map.c` and `rules.c`; merge A first, then
   merge `main` into each branch (no rebase) before its PR.

## Deviations

PR B (4.7, Tasks 5 and 6), agent defaults Peter may override:

1. **R-8 code stays in `mem_merge.c`; `pm_mem_merge` is new code beside it.** The plan says the R-8
   code moves behind `pm_mem_merge(ctx, design, stats)` and `mem.c` calls it. R-8 works on a copy
   (`mem_model`) and leaves the design untouched so that a `$mem` that ends soft keeps its
   flip-flops (3C agent default d); it cannot be the pass itself. So `mem_merge()` (model level,
   no edit, also used by `lpmmap`) is unchanged and `mem.c` still calls it; `memory_merge.c` calls
   the same function and then writes the merged model into the design. Identity is untouched by
   construction (only the `MP_*` parameter-index enum moved from `mem.c` to `mem.h`).
2. **Writing the merge needs a new `$mem`.** Cell parameters have no setter, so the pass builds a
   replacement `$mem` with the three read-port bit parameters changed (`hm_kit` transaction: same
   name and attributes, one DERIVED record, node attribute `hardmap` = `$mem:merge`).
3. **Cases the pass leaves alone** (counted as asynchronous): a port whose merged `$dffe` enable is
   active low (no inverter is added; the other ports of the cell still merge); the whole `$mem`
   when a flip-flop that would go carries an `init` value. `partial_map` makes the same merge as
   before in those cases. After a data merge the old async data nets, and a wire made only of
   them, are removed.
4. **G-3 "one WARNING per design"** is implemented as one WARNING per memory and attribute found
   (the text names the memory), given by `partial_map` only: `memory_merge` maps nothing, and
   `memory_merge; partial_map` warns once because the replacement `$mem` keeps the attributes. The
   warning is also not given when the arch has no RAM model (the RAM phases are skipped); the spec
   asks for no warning then.
5. **`memory_merge; partial_map` is not structurally `partial_map` alone for memories that end
   soft** (variable-enable `$dffe` read register, falling-edge read register, OFFSET != 0): the
   pass merges regardless of the verdict, so `lower` receives a synchronous read port and builds
   the read register itself (alone, `partial_map` keeps the original flip-flops, 3C agent default d).
   The function is the same: `cli_memory_merge_soft` shows equiv-check equivalence (variable
   enable, OFFSET) and equal 1E sim vectors (falling edge). Write ports on two clocks fail in
   `lower` in both flows with the same error. For memories that map hard the BLIF is identical
   (`cli_memory_merge`).
6. **File names:** the pass registration is `register_merge.c`, the warning is `ramstyle.c`
   (declared in `hm_kit.h`); micros are `tests/micro_pm/mem_regread.v` and `mem_ramstyle.v`; the
   golden-style tests are `cli_memory_merge` and `cli_pm_ramstyle` in `tests/cli/test_cli.sh`.

PR D (4.4, Tasks 9 and 10), agent defaults Peter may override:

1. **Task 9 was mostly done by PR A.** `pm_rules_from_arch` already gave `mem_depth` and the
   `have_sp`/`have_dp` flags, and `ram.c` already read `D` from the rules (the split loop, the
   padding, the node parameters). PR D adds what was missing: a `$mem` whose plan needs a RAM kind
   the arch lacks (an SP-only arch and a memory that needs a DP block, or the reverse) is soft with
   the R-11 warning, not an error (R-6); the S-3 INFO for a missing RAM model also gives the bits
   left soft (R-8: `partial_map: 128 bits of '$mem' left soft`, a second line beside the S-3 one);
   the tests, the fixtures `ram_d11.xml` and `ram_sp_only.xml`, and the micros. The plan's
   `tests/micro_pm/ram_a9.v`, `ram_a13_sp.v` and `ram_a13_dp.v` are explicit RAM instances, so
   they are run on the COFFE-like fixture only; on an arch with no RAM model such an instance does
   not elaborate (the module `single_port_ram` is undefined), so the no-RAM case runs on an inferred
   memory (`mem_regread.v`).
2. **`--mem-width arch` pads the address to the mode's address width, not to `D`.** Spec R-5 pads
   to `D`. With `D = 11` a 256 x 32 memory padded to 11 address pins could only be placed in the
   (11, 10) mode, which defeats the option. The block's `ADDR_WIDTH` is the address width of the
   chosen mode (the one with the most data pins among the modes with at least `A'` address pins,
   the fewest address pins among equals): 9 for 256 x 32, 10 for 1024 x 20, 11 for 2048 x 10. The
   default (option off) still pads to `D`. `DATA_WIDTH` is the number of data bits of the slice
   (at most `w`), so 2048 x 32 gives slices of 10, 10, 10 and 2 bits, all with 11 address pins.
   Needs Peter's review (spec test line: "`A' 8`, `w 40`, `DATA_WIDTH 32`"; this reading has
   `ADDR_WIDTH 9`).
3. **The option is a pass argument, `partial_map --mem-width arch`** (`--mem-width 1` is accepted
   and is the default). Entry point `odin3_partial_map_run_opts(ctx, design, pm_options *, stats)`;
   `odin3_partial_map_run` is the same with no options. Without an arch record the option is a
   WARNING and changes nothing; with a record that has no RAM model it is silent (the S-3 INFO is
   given). The S-5 warning is given once per design, and only for a block that differs from the
   default one.
4. **Mode table limits:** at most 16 distinct (address, data) modes per RAM model are kept and a
   mode wider than 128 data pins is ignored (fixed capacity in `pm_rules`).
5. **Test helper:** `tests/unit/hardmap_ramsim.c` `MAX_DATA` raised from 4 to 64 so that the
   32-bit memories can be simulated.
6. **Not done here, needs the C1 goldens:** T-3 and T-6 equivalence of the sliced memories on the
   COFFE and k4_N4_90nm archs against Parmys (the unit tests use the 1E-style RAM simulator on the
   IR before and after; `cli_pm_mem_arch` counts blocks).
7. **Task 11 (read-enable emulation) follows Yosys `Mem::emulate_rden`** (read in
   `libs/EXTERNAL/yosys/kernel/mem.cc`): the enable flip-flop starts undefined here (Yosys uses 0
   when the port has no init), and the hold flip-flop takes the final output. The reference micros
   (`*_ref.v`) write the RAM block and this logic by hand; `equiv-check --match-unnamed` pairs the
   unnamed RAM blocks by simulation. The existing `memory_merge_soft` CLI test uses
   `--match-unnamed` for `mem_dffe_var`, which now maps hard. Unit tests that expected
   `MEM_SOFT_EN` now expect a mapped memory.
8. **Task 12 (50k-FF warning):** the threshold is 50,000 bits (`PM_SOFT_FF_WARN`); for an arch with
   no RAM model each `$mem` over it is warned beside the S-3 INFO.
9. **PR D review (M-1 to M-4, Lows).** Fixed: M-1 (the no-RAM INFO and the 50k warning follow
   `have_sp`/`have_dp`, tested with `read_techlib` plus a RAM-less record), M-2 (an unconnected
   `RD_EN` stays soft with a warning, `MEM_SOFT_EN` back), M-3 (sim of a variable enable, active
   high and low), M-4 (`bram.v` has `ABITS 8`, so the 8-bit reference is right; a 4-bit one is
   tested as not equivalent), L-2, L-3 (dead snprintf; negative for an unregistered enable).
   Not done: L-1 (a warning for an uninitialised ROM that Parmys deletes is Peter's call, D15 stays
   a listed difference), L-4 (the reason text for SP-only/DP-only is the generic one), L-5 (the
   located prefix of the 50k warning is checked in `cli_pm_mem_rden` only).

## Deviations (PR C, Tasks 7 and 8)

1. **Driver file.** The plan names `partial_map.c`; the driver is still `src/passes/partial_map/hardmap.c`
   (Task 2 kept the file name). Phase 0 is wired there: `odin3_partial_map_run_opts` runs
   `hm_generic_phase` after `setup_rules` and before the pre-check. `odin3_partial_map_run` is
   a wrapper with the default options.
2. **`--allow-unknown-blocks`** (spec B-6) is the first `partial_map` argument: `register.c` parses it
   into `odin3_partial_map_opts`; any other argument keeps the old error text.
3. **`write_blif --vtr` change (outside the plan's file list).** 3E refused every library cell that is
   not `hard` (E6), so a generic block registered by `read_arch` (kind `blackbox`) could not be written,
   and the Task 7 acceptance (round trip, IR-7b) failed. `odin3_techlib_is_subckt()` (`techlib/reader.h`)
   Review H1: only a library black box that the loaded arch record registered as a model is written
   (`odin3_arch_writes_subckt()` in `frontends/arch/arch.c`, used by `backends/blif/vtr.c` and `writer.c`);
   lpm cells and any black box the arch lacks keep the E6 refusal (tests in `test_pm_generic`). The
   one-line summary lists the other `.subckt` cells as `other N`, so the typed list adds up to the count.
4. **B-6 scope.** The IR does not tell an implicit black box from a `(* blackbox *)` module or a BLIF
   `.blackbox` model: all are design-local `BLACKBOX` types with no library record. With a record, every
   instance of such a type that is not a model of the arch is B-6 (review H2, M3). A type with a library
   record (lpm.o3lib, an arch model, a user `.o3lib`) is known to the tool and is never B-6. Without a
   record nothing is checked, so the default flows are unchanged.
5. **B-5 "not connected".** Elaboration ties an unconnected input to the unknown constant, so a port counts
   as not connected when every bit is on no net or on a constant-x net; a partly connected port is left.
   An explicit all-x port cannot be told from it, so the warning reads "is not connected or is x" (M1).
   A clock port is never tied (M2): the VTR writer's E3b refuses an unconnected or x clock. The warning is
   logged after the ties succeeded (L1).
6. **Task 8 archs.** COFFE has only the four templates and `k4_N4_90nm` has no model, so on the two sweep
   archs the test checks the phase is a silent no-op. The generic models come from
   `timing/k4_frac_N4_tileable_fracff_ckbuf_40nm.xml` (6) and `zeroasic/z1000/z1000.xml` (4). Each arch
   gets one design holding one instance of every generic model (not one design per model).
7. **Fixtures.** `generic_blocks.xml` has a fourth model `odd-name` (test h); two extra micros
   `generic_wide.v` (B-4, test d) and `generic_odd_name.v`. The INFO list follows the arch's model order.
8. **Goldens.** Neither task uses Parmys goldens, so no fallback was needed.
9. **Review lows left as they are.** L2 (the warning count is not in the INFO line): the warnings are
   already logged one by one. L3 (`ODIN3_ERR_INVALID_ARG` for a B-6 finding): the same status the pass's
   other design errors return.
10. **C1 goldens, PR D checks (2026-10-20).** `hardmap-diff --techlib <arch.xml>` now reads an arch XML
    with `read_arch`. COFFE: the 26 micros are 16 equivalent and 10 listed (as on k6); of the 15 VTR
    designs 2 are equivalent, the rest are listed or open in
    `tests/partial_map/diff_expect_k6_COFFE_mem20K.txt` (multipliers above 27 bits wait for PR F).
    k4_N4_90nm: 23 micros run, 13 equivalent and 10 listed (`tests/partial_map/diff_expect_k4_N4_90nm.txt`);
    new D22 (an explicit instance of a block the arch lacks is an error, Parmys builds it soft) and
    D23 (Parmys's soft memory has no read register). Open: latch deltas on k4 designs without
    memory (sha, stereovision0, stereovision1, blob_merge) and, on COFFE, boundtop, stereovision0,
    stereovision2.
