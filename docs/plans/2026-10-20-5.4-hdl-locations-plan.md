  exit test per (file, line).
- **Sweep time and memory:** labelled `sweep`, one level at a time, smallest first; memory cap of the
  lane's build-mem script applies.

5.4f-a (implementing lane):
- SHA-256 is not re-implemented: `src/util/sha256.{c,h}` (FIPS 180-4, already in the repo and tested by
  `test_sha256`) is reused, so there is no second implementation and no new dependency. T-hash-1 still
  checks the NIST vectors (empty, "abc", 448-bit, 896-bit, one million `a`) through it.
- Resolve takes the set of full names of one module and kind plus a list of reserved (non-renamed)
  names, and writes the result per input index; it keeps no state except the test-hook width.
  A repeated full name counts as one name (same result, no collision).
- An extension step is 5 characters (10, 15, 20, ... 50) and the last step clamps to 52; a collision
  left at 52 (needs a SHA-256 collision or a crafted reserved name) is a logged `INVALID_ARG`.
- `name_map` has no file I/O (the writers in 5.4f-b write the text it produces). `parse` sorts the
  entries by (module, kind, short); `odin3_name_map_check` reports entries, bad hashes and duplicate
  keys (a parsed map has no bad hashes: `parse` already ignored them with a warning, counted in
  `map->ignored`). `write` refuses two entries with one (module, kind, short).
- Limits: 2^22 names per resolve call, 2^24 entries per map, 1 MiB per map line (a longer line is
  ignored with a warning). The 2^24-entry limit has no unit test (it needs 16 million lines).
- Review fixes (5.4f-a): a module name that starts with `#` is written with that byte as `%23`
  (a line starting `#` is a comment), so H-4's escape set gains `%23`; the writer rejects an entry
  whose line is over the parser's 1 MiB limit; `find_full` uses an index (sorted pointers, built by
  `parse`) instead of a scan; sorting breaks ties by full, line, hier, file; the test hook is no
  longer global state: `odin3_hash_names_resolve_at(set, start, out)` takes the start width; CRLF
  and `# odin3-names` without a space have their own messages.
- 5.4f-b: Verilog and JSON resolve hash collisions over all kinds of a module together, not per
  kind (H-3 says per module and kind): both formats have one key namespace per module, so two kinds
  must not share a name. The result differs from a per-kind resolve only when two names collide.
  BLIF has one kind (net) and follows H-3 as written.
- 5.4f-b: `write_json --name-style provenance` is new (W-6 has no JSON name row). A cell, a non-port
  wire and a named net with an HDL location take the key `hier/<key>@file:line`, where `<key>` is the
  key they would have had (a generated `$c5`, the `$sop` suffix included); `hide_name` follows the
  first byte of that key, also under `hash`. Ports and their netnames keep their keys. `hash` runs the
  writer twice (the first to /dev/null) because JSON streams, and uses the object's place in the
  first pass to find its hash name. A map entry whose full name does not decode as `L-5` (a `$sop`
  suffix) has an empty hier and file and line 0.
- 5.4f-b: `odin3_blif_write_opts`, `odin3_verilog_opts` and the new `odin3_json_write_opts` carry
  `name_map`; NULL means `<path>.names`, and a path of `-` with no map is `INVALID_ARG`. The map is a
  private temporary opened before the netlist; both temporaries are finished first, then the map is
  renamed, then the netlist (a failed map never leaves a new netlist beside a stale one). BLIF's info line `N names
  legalised` still counts names VB-10 changed before they became hash names.
- 5.4f-b: `names` returns `ERR_CHECK` for an absent name (the status set has no NOT_FOUND; a usage
  error stays `INVALID_ARG`) and `ERR_PARSE` when `--check` finds a bad entry. The CLI flag for a
  script is `-p`, not `-c`.
- 5.4f-b (review fixes): `--name-map` equal to the output path (same directory and name, also when
  spelled differently) is `INVALID_ARG`; BLIF HASH gives a provenance-named net whose name is taken
  a hash row of the full name with the first free `$N` (H-2) instead of `$n<ID>`, so the names depend
  only on the set of full names; the BLIF info line `N names legalised` quotes the hash name for a
  hashed net; Verilog no longer warns "a generated name is used" for an object that has a
  provenance or hash name; the first JSON pass counts bytes into a sink (no `/dev/null`) and the
  second records each full name as taken so plain keys bump as in the first pass; `names --reverse`
  dedupes with a string set. Test hook: `odin3_hash_rows_test_start(width)` (T-hash-3 through a
  writer; a process-wide setting a test resets to 0). `util/file.h` gains `odin3_atomic_file_finish`
  and `_commit` (close in two steps).
