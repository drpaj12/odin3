# 1B — IR core: implementation design

Status: agent-approved under PHASE1 #9 (Peter reviews afterwards). Phase 1, sub-project 1B.
**Semantics are defined by `docs/IR.md` (v2); this document only fixes files, names and tests.**
Where they disagree, IR.md wins and this file is corrected.

## Goal

Implement IR.md in `src/ir/` on top of `src/util/` (1A): objects, IDs, cell-type registry and the
built-in cell library, provenance lineage, `check`, `compact`, and a 2M-node benchmark. No
readers or writers (1C), no pass manager or public IR ABI (1D), no simulation semantics (1E).
The only public-ABI change is `ODIN3_ERR_CHECK` (ABI 0 → 1).

Success: every IR.md rule has a unit test under ASan/UBSan; `check` catches each invariant
violation it lists (one negative test per rule); the benchmark builds and checks a 2M-node,
8M-pin synthetic module inside the 2 GB budget and records times in `docs/PHASE1.md`.

| `src/ir/design.h/.c` | design create/destroy; strtab; modules list; top |

Built-in cell types registered in 1B (ports/params/verify; `simulate` stays NULL until 1E):

- structural: `$port_in`, `$port_out`, `$port_inout`, `$_CONST0_`, `$_CONST1_`, `$_CONSTX_`,
  `$_CONSTZ_`;
- BLIF: `$sop`, `$_DFF_P_`, `$_DFF_N_`, `$_DLATCH_P_`, `$_DLATCH_N_`, `$_FF_`;
- bit gates: `$_BUF_`, `$_NOT_`, `$_AND_`, `$_OR_`, `$_XOR_`, `$_NAND_`, `$_NOR_`, `$_XNOR_`,
  `$_MUX_`;
- word set (spec §5.2): `$add $sub $mul $div $mod $and $or $xor $not $shl $shr $sshr $eq $ne $lt
  $le $gt $ge $mux $pmux $dff $dffe $adff $sdff $mem $memrd $memwr $reduce_and $reduce_or
  $reduce_xor`, with Yosys port names and parameters (`A_WIDTH`, `A_SIGNED`, `Y_WIDTH`, …);
- `$tribuf` (tristate flag), so invariant 4's tristate path is testable.

## API naming

Handles are opaque pointers (`odin3_design *`, `odin3_module *`); IR objects are IDs (IR-5).
Functions are `odin3_<object>_<verb>`: `odin3_design_create`, `odin3_module_create`,
`odin3_module_add_port`, `odin3_node_create`, `odin3_node_create_connected`, `odin3_node_delete`,
`odin3_node_replace`, `odin3_node_port`, `odin3_net_create`, `odin3_net_merge`,
`odin3_net_driver`, `odin3_net_sinks`, `odin3_net_const_value`, `odin3_pin_connect`,
`odin3_pin_disconnect`, `odin3_wire_create`, `odin3_wire_add_alias`, `odin3_prov_source`,
`odin3_prov_imported`, `odin3_pass_run_begin`, `odin3_prov_begin_op`, `odin3_prov_derive`,
`odin3_prov_parents`, `odin3_prov_sources`, `odin3_prov_index_build`, `odin3_check`,
`odin3_module_compact`. Arguments that would be adjacent same-type scalars travel in small
structs (as in 1A) to satisfy `bugprone-easily-swappable-parameters`. All fallible calls return
`odin3_status`; out-parameters return IDs.

## Error handling

Out of memory → `ODIN3_ERR_NO_MEMORY` with the IR unchanged (each operation reserves before it
mutates). Misuse detectable cheaply (dead or out-of-range ID, wrong port index, duplicate name,
adding a port to an instantiated module) → `ODIN3_ERR_INVALID_ARG` plus a log message; misuse
that would need a scan is left to `check`.

## Testing

- Unit tests per file under `tests/unit/test_ir_<area>.c` (linked against `odin3_core`).
- For every `check` rule: build a valid module, corrupt it through a test-only hook
  (`src/ir/ir_test.h`, hidden, not exported), assert `odin3_check` reports that rule.
- Provenance: decompose-then-clump scenario (one `$add` lowered into gates, two gates clumped)
  walks back to the original source location and forward from it to every live and dead object;
  100 identical-source `$add`s lowered separately produce 100 distinct operation records.
- `merge` keeps every name as alias; `compact` keeps output order and writes tombstones.
- Benchmark `tests/bench/bench_ir.c` (built, not in CTest): 2M nodes (`$_AND_`/`$_DFF_P_` mix),
  8M pins, ~2.2M nets; build, full `check`, fanout walk, compact; times and max RSS go to
  `docs/PHASE1.md`.

## Out of scope

Readers/writers, the pass manager and public IR ABI, simulation, `flatten`, memories beyond
width checks, multi-threading.
