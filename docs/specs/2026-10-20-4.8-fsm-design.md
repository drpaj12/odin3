## 1. Summary for Peter (what you are approving)

1. Odin III gets a pass `fsm` that is a faithful port of Yosys 0.55's `fsm` driver
   (`fsm_detect`, `fsm_extract`, `fsm_opt`, `fsm_recode`, `fsm_map`, `fsm_info`; `-expand`,
   `-fullexpand` and `-export` are out). It finds state registers, extracts each into a
   state/transition table, simplifies the table, recodes it, and rebuilds a register plus logic.
2. Encoding is Yosys's: attribute `fsm_encoding` wins (`none` skips, `one-hot`, `binary`, `auto`);
   `auto` is one-hot below 32 states and binary from 32 up; `fsm -encoding one-hot` forces one-hot
   for every FSM that has no attribute or has `auto`.
3. The pass runs right after `proc` in the VTR script, as Parmys runs it: `proc; fsm; opt; wreduce;
   ...`. That changes Odin III's output on every design with an FSM, on purpose (it moves Odin III
   toward Parmys). Nine of the 19 VTR designs have FSMs (§12).
4. **IR question (§3):** does a `$fsm` cell exist? No. Adding one is an IR change (and its
   tri-state "don't care" bit cannot be stored in an IR `BITS` value). Recommended: keep the FSM
   representation inside the pass; the IR gets no new cell type, and the final IR holds only
   ordinary `$dff`/`$adff`, `$eq`, `$reduce_or`, `$and`, `$pmux` cells plus attributes.
5. Provenance: every FSM is one operation; its new register and logic are `DERIVED` from the old
   register and the logic they replace. Each rebuilt state register carries `odin3_fsm_*`
   attributes (state count, encoding) for Phase 6.
6. Evidence (§12) comes from running real Yosys 0.55 on the 19 VTR designs and the micros, not
   from reading the source alone.

## 2. Scope (F-n)

**F-1 What is ported.** The `fsm` driver (`fsm.cc:80-163`) and the five sub-passes it calls by
default, plus `fsm_info` (logging). `fsm` runs them in this order (`fsm.cc:138-160`): `fsm_detect`
(unless `-nodetect`), `fsm_extract`, `fsm_opt`, `opt_clean`, `fsm_opt`, `fsm_recode` (unless
`-norecode`, passing `-encoding`), `fsm_info`, `fsm_map` (unless `-nomap`). The `-expand`,
`-fullexpand` and `-export` branches (`fsm.cc:146-150`, `156-157`) and the `-fm_set_fsm_file` and
`-encfile` outputs are not ported; an option that names one is the located error
`fsm: option '-expand' is not supported`. `fsm_expand.cc` and `fsm_export.cc` are not ported.

**F-2 Options and passes.** Registered passes: `fsm [-nodetect] [-norecode] [-nomap] [-encoding
TYPE]` and `fsm_detect [-ignore-self-reset]`. `fsm_extract`, `fsm_opt`, `fsm_recode`, `fsm_map`
and `fsm_info` are stages of `fsm`, not separate passes (consequence of the answer to question 1).
`-nomap` is supported as a dry run: stages run up to and including `fsm_info`, the IR is not
changed, the log is complete. (In Yosys `-nomap` leaves `$fsm` cells in the design; Odin III has
none, §3.) Divergence V-1.

**F-3 Scope of a run.** The whole design, every module in creation order (Odin III has no
selection; Yosys `selected_modules()` with no selection is the same set). A module with live
`$proc` nodes is skipped with an info line (Yosys never sees one: `proc` has run); the pass is
`processes = REFUSE` for that reason, so the pass manager refuses a design with processes.
Modules are independent: no state is shared between modules.

**F-4 Fidelity target.** Same as the opt spec (OP-1): on the same input, Odin III's `fsm` and
Yosys 0.55's `fsm` find the same FSMs, extract the same state sets and transition tables, pick the
same encodings, and leave the same per-module cell-type histogram after a common lowering; where
that cannot hold the difference is in the divergence table (§13) with its reason. The two
non-negotiable properties (PHASE4 4.8) are: same FSMs and state counts and encodings as Yosys 0.55;
and the output is equivalent to the input from reset (T-2).

**F-5 What `fsm` expects as input.** `fsm_detect` accepts only a `$dff` or `$adff` as the state
register (`fsm_detect.cc:146`). Yosys's own help says: run `opt -nosdff -nodffe` first
(`fsm.cc:70-71`); Parmys does (`synthesis.tcl` lines before `procs -norom`). Odin III's Phase 3
script has no such `opt` before `proc`, which does not matter here: `proc` makes only `$dff`,
`$adff`, `$aldff`, `$dffsr` and latches, never `$dffe`/`$sdff*`, and a probe (§12) shows the set
of FSMs Yosys finds on the 19 designs is the same with and without the pre-`proc`
`opt_expr; opt_clean; opt -nodffe -nosdff`. `fsm` must run before the main `opt` (that `opt`
makes `$dffe`/`$sdff`, which `fsm_detect` ignores; 2F spec §3: `stereovision3` 955 vs 1,288
`.names` if `opt` ran first).

## 3. The IR question: is there a `$fsm` cell? (decision for Peter, question 1)

Facts, from `docs/IR.md` §5 and `src/ir/cells/builtin.c`: the op registry has 75 built-in types
and **no `$fsm`**. Yosys uses `$fsm` as the interchange between its sub-passes (`fsm_extract.cc:371`
makes it, `fsm_opt`, `fsm_recode`, `fsm_info`, `fsm_map` read and rewrite it,
`fsm_map.cc:320` removes it). `$fsm` has ports `CLK`, `ARST`, `CTRL_IN`, `CTRL_OUT` and parameters
`CLK_POLARITY`, `ARST_POLARITY`, `CTRL_IN_WIDTH`, `CTRL_OUT_WIDTH`, `STATE_BITS`, `STATE_NUM`,
`STATE_NUM_LOG2`, `STATE_RST`, `STATE_TABLE`, `TRANS_NUM`, `TRANS_TABLE`, `NAME` (`fsmdata.h:34-77`).
Adding a type is an append-only registry change (index 75, `$fsm`), which is an IR change: Peter
reviews it (CLAUDE.md rule 10), and `docs/IR.md` §5, DESIGN §5.2 and `docs/PASSES.md` change.

Two facts make a registry `$fsm` more than "add one row":

- **The table needs a "don't care" bit.** `TRANS_TABLE` and `STATE_TABLE` hold the RTLIL states
  `Sa` (don't care, `-`), and `fsm_extract` uses the marker `Sm` internally. IR `BITS` values are
  4-state (0, 1, x, z; IR-10). Storing `Sa` as `x` changes behaviour: `fsm_opt` groups transitions
  in a `std::map` keyed by the pattern (`fsm_opt.cc:264-270`), so a pattern with `x` and a pattern
  with `-` are different keys in Yosys and the same key if merged; one-hot codes are `-` except
  one `1` (`fsm_recode.cc:108`). Faithful storage needs two bit-planes (pattern and mask) or a new
  value kind, which is a second IR change.
- **Liveness.** `fsm` calls `opt_clean` between its two `fsm_opt` runs (`fsm.cc:143`). The
  extracted FSM must therefore be a node that reads `CTRL_IN`, or `opt_clean` deletes the logic
  that computes the control inputs.

Options:

1. **A registry cell `$fsm`** (as Yosys). Faithful stage by stage; each stage could be a separate
   pass and be diffed against Yosys alone; a later `raise` could emit `$fsm`. Cost: an IR change
   with tri-state storage (above); `check`, `write_rtlil`, the simulator (no hook), `opt_*`
   (must skip), `lower` (must refuse), the JSON/Verilog writers must all learn a new type that
   exists for the duration of one pass; ABI surface grows (Peter's rule: protect the registry).
2. **Internal-only representation inside the pass (recommended).** `FsmData` lives in a C
   struct in `src/passes/fsm/` (the same fields as `fsmdata.h`, with its own 6-valued bit type
   `0 1 x z - m`, so no IR type is needed). The IR is read by detect and extract, and written
   once, by map, per FSM. The `opt_clean` between the two `fsm_opt` runs is replaced by one native
   question, "is this `CTRL_OUT` bit read by any node that stays alive?", which is the question
   `unused_bits` answers in Yosys (§7, O-1). No new cell type, no ABI change, no IR invariant
   touched. Cost: the sub-passes are not separately runnable (F-2); the dry run `-nomap` and the
   log stand in. The code keeps `FsmData` and the stage functions with Yosys's names and
   signatures, so promoting `FsmData` to a registry `$fsm` later (option 1) moves no algorithm.
3. **Recode directly on the state register, no table.** Detect the register and its mux tree,
   then rewrite the register as one-hot and patch the compare cells. Smallest code, but it is
   not Yosys's algorithm: `fsm_map` builds the next-state and output logic from the table
   (`implement_pattern_cache`, `fsm_map.cc:45-155`) after unreachable-state removal, input
   aliasing and don't-care merging (`fsm_opt.cc`). The logic would differ from Parmys's, and the
   "same FSMs, states and encodings" test would compare against something Odin III does not
   compute. Not recommended.

**Recommendation: option 2.** It is the only option with no IR change, and it keeps Yosys's
algorithm and its stage structure. Option 1 stays open for Phase 7 (`raise`) without redoing the
algorithm.

## 4. How Yosys's concepts map onto the IR

The mapping is the opt spec §2 table plus these rows (the common rows, such as `SigMap` and
constants, are as there).

| Yosys | Odin III |
|---|---|
| `RTLIL::Wire` with `width`, attributes, `port_id` | an IR wire (a vector of nets with attributes); `port_id != 0` is a wire whose net is on a `$port_in`/`$port_out`/`$port_inout` pin (IR-3, IR-7) |
| `SigSpec` of a wire, `assign_map(sig)` | the wire's net list; nets are already merged aliases, so two wires over the same nets are the same signal |
| `sig2driver`, `sig2user` (`SigSet` of (cell, port)) | per module, per net: the driving pin and the reading pins, built once per module per stage (an index by net ID in `util/vec`) |
| `CellTypes ct` known/unknown (`fsm_detect.cc:305-310`, `fsm_extract.cc:439`) | detect: registry types of Yosys's `internals`/`stdcells`/`mem` sets are known; every other node (instances of user modules, black boxes, hard cells) is unknown, so each of its pins counts as driver and user (`:322`, `:327`); extract: `CellTypes ct(design)` makes module instances known, with directions from the module's port nodes |
| `ConstEval` (`kernel/consteval.h`) | `src/passes/fsm/ceval.c`: the same algorithm (set, push/pop, stop signals, `busy`, `$lcu`/`$alu`/`$macc` not present in the registry) over the registry cells, evaluating each cell through 2D's `odin3_cval` operators (`src/passes/opt/fold.[ch]`); a sequential cell, `$mem*`, `$tribuf`, `$proc` or an instance is not evaluable (returns false, as `CellTypes::eval` reports an error) |
| `State::Sa`, `State::Sm` | `odin3_fsm_bit` enum `{ZERO, ONE, X, Z, DC, MARK}` in `src/passes/fsm/fsmdata.h`; never stored in the IR (§3) |
| `RTLIL::Const` ordering in `std::map<Const,int> states` (`fsm_extract.cc:300`, `rtlil.cc:316-326`) | explicit comparator: shorter first, then bit 0 upward, `0 < 1 < x < z < - < m`. This order numbers the states, so it fixes the one-hot bit of every state (§9); it must not be replaced by hash or ID order |
| `module->addWire(NEW_ID)`, `addCell(NEW_ID, ...)` | unnamed nets and nodes via `odin3_kit_new_cell` (`src/passes/opt/kit.h:156`); the state wire is named after the original (`module->uniquify(NAME)`, `fsm_map.cc:169`) |
| `module->connect(a, b)` | `odin3_kit_connect` (`kit.h:119`); a bit that must be undriven gets a fresh net |
| `wire->attributes` (`fsm_encoding`, `init`, `hdlname`, `unused_bits`) | attributes on the IR wire; `fsm_encoding` is a STRING attribute copied by the front end from `(* fsm_encoding = "one-hot" *)` (2D elaboration spec, wire declarations: the attributes of a declaration are copied to the wire); `init` is the BITS wire attribute of 2D EL-40 read through `ffinit.h` |
| `autoidx`-numbered names (`$fsm$\st$14`) | none: no `$fsm` cell exists; log lines name the FSM by module and wire (`'m.st'`) |

**Recursion.** Yosys recurses in `check_state_mux_tree` (`fsm_detect.cc:37-89`), `find_states`
(`fsm_extract.cc:41-124`), `find_transitions` (`:144-254`), and `ConstEval::eval`. The code rules
forbid recursion in IR traversals (CLAUDE.md), and a mux tree can be deep. All four use an
explicit frame stack; `find_transitions` branches on one control input per level, so its
depth is bounded by the number of control inputs, but it is still written with a stack so that the
rule has no exception. Divergence V-6.

## 6. Detect (`fsm_detect`, D-n)

Yosys: `fsm_detect.cc:121-256` (`detect_fsm`), driver `:288-346`. Run per module, per wire.

**D-1 Candidates.** Every wire of the module, in wire ID order, except as D-2 says. (Yosys:
`module->selected_wires()`, `:338`.)

**D-2 Skips, in this order** (`detect_fsm`):
1. `fsm_encoding` = `"none"` on the wire: skipped, nothing logged (`:124`, `:130-131`).
2. Width 1 or less: skipped; a `fsm_encoding` attribute is removed with the warning "Removing
   fsm_encoding attribute from 1-bit net" (`:133-139`).
3. No driver of the wire is a `$dff`/`$adff` Q port whose full Q equals the full wire
   (`:144-156`): `looks_like_state_reg` stays false and the wire is not marked. The wire must be
   exactly the Q bus (same nets, same order), not a part of it and not a concatenation. Other
   flip-flop types (`$dffe`, `$sdff*`, `$aldff`, `$dffsr`, latches) never qualify.

**D-3 `looks_like_state_reg`** (`check_state_mux_tree`, `:37-89`): true when D of the flip-flop is
a closed tree of `$mux`/`$pmux` cells (output `Y`) whose leaves are all constants or Q itself.
Exactly: a signal is acceptable when it is fully constant, or equals Q (`:42`); it is not
acceptable when it touches a module port net (`:48`); otherwise every driver of it must be a
`$mux` or `$pmux` `Y` port (`:58`), without a loop (a loop warns "logic loop in mux tree" and
fails, `:62-66`), and `A` and every `B` slice must be acceptable (`:70-82`). The visited mux
cells are collected as `muxtree_cells`. Results are cached per signal (`:39`).

**D-4 `looks_like_good_state_reg`** (`check_state_users`, `:91-119`): false when Q touches a
port net; otherwise every reader of Q is (a) a `muxtree_cells` member, or (b) a `$logic_not` on
exactly Q, or (c) a cell with only ports `A`, `B`, `Y` where Q is exactly `A` and `B` is all
constant, or Q is exactly `B` and `A` is all constant (so `$eq`, `$ne`, comparisons against
constants). Any other reader makes it false.

**D-5 Self-resetting** (`:164-204`): for each reader of Q that is `$ne`, `$reduce_or`,
`$reduce_bool` (outputs forced to 1) or `$eq`, `$logic_not`, `$reduce_and` (outputs forced to 0),
if every input bit of that reader that is a wire bit is a Q bit, set its output nets to that
constant in a `ConstEval`; then if the D input evaluates to a constant, the FSM is
"self-resetting": from a state with no matching compare the next state is constant.
`-ignore-self-reset` skips this (`:202`). (Example, verified on 0.55 with a case that has a
`default: st <= 0`: not marked, "Circuit seems to be self-resetting".)

**D-6 The decision** (`:206-255`):
- Attribute present and not `none` (user-specified): the wire stays marked; warnings are logged
  for a port, bad users, an `init` attribute ("Initialization value on FSM state register is
  ignored"), not looking like an FSM, or self-resetting; with none, an info line "already has
  fsm_encoding attribute".
- No attribute and `looks_like_state_reg && looks_like_good_state_reg && no init attribute &&
  not a module port && not self-resetting`: log "Found FSM state register m.w." and set the wire
  attribute `fsm_encoding = "auto"`.
- Otherwise, if `looks_like_state_reg`: log "Not marking m.w as FSM state register:" and one
  reason line per failed condition (port, users, init, self-reset).

**D-7 Exclusions (the answer to "ports, init, keep").** Module ports: a port net is never marked
unless the user set the attribute (then it is marked with a warning). The `init` attribute: an
initialised register is never auto-marked (a user attribute still marks it, with the warning).
`keep`: **not an exclusion in Yosys** (`fsm_detect.cc` has no `keep` test; verified on 0.55: a
`(* keep *)` state register is still detected and recoded, and the original register and its mux
tree stay alive because `keep` roots them in `opt_clean`, so the result has both). Odin III follows
Yosys (question 3). `fsm_encoding = "none"` is the user's way to exclude a register.

**D-8 Difference.** None in the rules. `-ignore-self-reset` is exposed on `fsm_detect`, not on
`fsm` (as Yosys, `fsm.cc` does not pass it).

## 7. Extract (`fsm_extract`, X-n)

Yosys: `fsm_extract.cc:256-414` (`extract_fsm`), driver `:434-483`. Runs on every wire that has
`fsm_encoding` and is not `none`, whether detect set it or the user did (`:473-475`).

**X-1 Flip-flop** (`:262-289`): `dff_out` = the wire's nets. The driver must be `$dff`/`$adff`
(the first such); take CLK, CLK_POLARITY; for `$adff` also ARST, ARST_POLARITY and `reset_state =
ARST_VALUE`. `dff_in` = D with Q bits replaced by D bits. If `dff_in` has marked (unmatched) bits:
"fsm extraction failed: incomplete input selection tree root" and the wire is left as it is.

**X-2 States and control inputs** (`find_states`, `:41-124`). Walk the mux tree from `dff_in`.
A leaf equal to Q is skipped; a fully constant leaf is a state code (logged "found state code",
only if fully defined, stored with id -1 until numbered). Each mux select bit that is not yet a
control input is appended to `ctrl_in` ("found ctrl input"). A signal with more than one or no
driver, or a driver that is not `$mux`/`$pmux` `Y`, fails with "state selection tree is not closed".
The reset state is first taken from the async reset value (`:301-304`); with a sync-reset style
FSM it is guessed from the first mux whose A-side or B-side is fully defined (`:93-105`,
"guessed from mux tree"). Fewer than two states: "fsm extraction failed: at least two states are
required". (Both failures leave the wire unchanged, including its `fsm_encoding` attribute.)

**X-3 Control outputs** (`:318-341`): start from `dff_in`; add the `Y` of every reader of Q that
has a one-bit `Y` and whose other operand is constant (`:321-334`). `ctrl_in` minus `ctrl_out`
(`:335`), both sorted and made unique (`:337-338`).

**X-4 Transition table** (`find_transitions`, `:144-254`): for each state, set Q to the state code
in a `ConstEval` with `ctrl_in` as stop signals, evaluate `ctrl_out` and `dff_in`; where evaluation
stops at a control input, branch on 0 and 1 (using `ce_nostop` when it can decide the bit,
`:214-230`), respecting `$pmux` exclusivity (`exclusive_ctrls`, `:463-469`, `:171-174`,
`:219-226`, `:242-249`); record a transition (`ctrl_in` pattern with `-` for bits that did not
matter, `ctrl_out` constants). A next state not in the state set is logged "ignored invalid
transition" and dropped (`:180-186`); an undefined next state is "ignored undef transition"
(`:196-200`); undefined bits switch to the "shortened" mode that marks remaining wire bits (`:152-158`).
The result order of `states` is the `Const` order of §4.

**X-5 The cell and the rewiring** (`:343-413`): Yosys creates a `$fsm` cell, renames the old state
wire to `$fsm$oldstate...` (dropping its `fsm_encoding`), and disconnects every old driver of a
control output onto fresh unconnected wires. **Odin III does not do these three IR steps in
extract** (question 1, option 2): extract returns an in-memory `FsmData` plus the net lists
(`ctrl_in`, `ctrl_out`), the old register node, and the set of mux-tree cells; the IR is
changed by map (M-1) in one step.

**X-6 Budget (divergence V-5).** Yosys has no bound on the work of `find_transitions`; a state
register with many control inputs can take exponential time. Odin III counts `ConstEval`
evaluations per FSM; above `ODIN3_FSM_MAX_EVALS` (default 1,000,000, a test hook lowers it) the
FSM is skipped with the warning `fsm: module 'm': state register 'w': giving up after 1000000
evaluations; not recoded`, and the wire keeps `fsm_encoding`. A corpus test asserts the cap is
never reached on the micros and the 19 designs (T-5). Question 4.

## 8. Opt (`fsm_opt`, O-n)

Yosys: `fsm_opt.cc:31-314`, driver `:325-347`. Run twice per FSM by the driver, with an
`opt_clean` between (`fsm.cc:142-144`). In order, each on the table (`:302-310`):

**O-0 Unreachable states** (`opt_unreachable_states`, `:37-78`): repeat: every state except the
reset state that is never a `state_out` of any transition is removed with its outgoing
transitions ("Removing unreachable state"), until none is left. With no reset state
(`reset_state == -1`) every state that is no transition's target is removed, as in Yosys.

**O-1 Unused outputs** (`opt_unused_outputs`, `:80-157`): a `ctrl_out` bit is removed when its
signal is unused. Yosys decides with the wire attribute `unused_bits`, which `opt_clean` writes
(`passes/opt/opt_clean.cc:476-491`: a bit of a surviving, non-port wire that no cell input reads).
**Odin III's `opt_clean` does not write `unused_bits`** (no `unused_bits` in `src/`). Two ways:
(a) make `opt_clean` write it (a change to 2F's `opt_clean`, to the `write_rtlil` text of every
module with an unused public wire, and to the `.il` goldens of `tests/opt/rules`), or (b) answer
the question natively inside `fsm`: "net is not a port net and has no reading pin on a node that
stays alive", where "stays alive" is `opt_clean`'s liveness (roots: port, `keep`, the FSM's
control inputs) computed by the same worklist (`odin3_kit_readers`, `kit.h:288`, plus the
liveness helper of `src/passes/opt/clean.c`) with the old register and mux tree treated as
removed. **Recommended: (b)**, evaluated at both `fsm_opt` calls. It matches Yosys at the second
call exactly; at the first call Yosys sees attributes left by the last `opt_clean` before `fsm`
and Odin III sees current usage, so Odin III may drop an unused output one call earlier. The
final table can differ only if the order of O-1 against O-2..O-4 matters; T-3 measures it on the
micros and the 19 designs, and a measured difference switches the plan to (a) (question 2).

**O-2 Aliased inputs** (`opt_alias_inputs`, `:159-194`): two control inputs on the same net are
merged; the transition patterns are intersected (a `-` takes the other's value; a pattern that
conflicts is dropped).

**O-3 Feedback inputs** (`opt_feedback_inputs`, `:196-227`): a control input that is also a
control output is removed; transitions whose input value disagrees with the output value are
dropped.

**O-4 Don't-care merging** (`opt_find_dont_care`, `:229-292`): transitions are grouped by
(state_in, state_out, ctrl_out); within a group two input patterns that differ in one bit merge
into one with `-` there, repeated to a fixpoint ("Merging pattern"). Transitions are rebuilt in
`std::map` order of the group key, so the table order is state_in, state_out, ctrl_out.

**O-5 Constant and unused inputs** (`opt_const_and_unused_inputs`, `:99-137`): a transition whose
pattern contradicts a constant control input is dropped; a control input that no transition
constrains is removed.

**O-6 Difference.** Only O-1 (above). 0.69's `fsm_opt` differs by 54 lines from 0.55; not
analysed, nightly drift only (T-6).

## 9. Recode (`fsm_recode`, R-n) and encoding

Yosys: `fsm_recode.cc:55-126`, driver `:155-194`. Per FSM, with the attribute taken from the
wire (carried in Yosys by the `$fsm` cell: `fsm_extract.cc:379`; in Odin III by `FsmData.encoding`
copied from the wire attribute at extract):

**R-1 Resolve the encoding** (`:57-83`). The attribute string, default `auto`. Not one of `none`,
`user`, `one-hot`, `binary`, `auto`: log "unknown encoding" and use `auto`. `none` or `user`: log
"nothing to do" and return (the FSM is still mapped, M-1). `auto`: `-encoding TYPE` if given, else
**one-hot when the state count is below 32, binary otherwise** (`:81`). The state count is the
size of the state table after `fsm_opt`, so removed unreachable states do not count.

**R-2 One-hot** (`:85-87`, `:107-109`): `state_bits` becomes the state count. The state numbered
`i` gets the code with `1` at bit `state_idx` and `-` (don't care) elsewhere, where `state_idx = 0`
for the reset state and the remaining states take 1, 2, ... in table order; without a reset
state the numbering starts at 0 (`:101-104`).

**R-3 Binary** (`:88-96`, `:110-112`): `state_bits = ceil_log2(state count)`. If that equals the
current `state_bits`, log "existing encoding is already a packed binary encoding" and return,
leaving the original codes (the FSM is still mapped). Otherwise code = `state_idx` as a binary
number, with the same numbering as R-2. Example from the evidence: mcml `LogCalc.r_indexFirstOne`,
6 bits, 32 states, becomes binary 5 bits.

**R-4 Other encodings.** Any other value is `log_error` in Yosys (unreachable after R-1). Gray,
johnson and `-encfile` are not in Yosys 0.55 and not in Odin III.

**R-5 The `-encoding one-hot` option** (Peter's decision 6) replaces the `auto` rule for every FSM
whose attribute is absent or `auto`; an explicit `binary` attribute still gives binary. `-encoding
binary` likewise. Any other value of `-encoding` is `unsupported encoding` (an error at option
parse; Yosys errors later, only when an FSM uses it).

## 10. Map (`fsm_map`, M-n)

Yosys: `fsm_map.cc:157-321`, helper `implement_pattern_cache` `:45-155`. Per FSM:

**M-1 State register** (`:167-188`): a new wire of `state_bits` bits named after the original
wire (the old one is renamed out of the way: in Odin III its wire name becomes `$fsm$oldstate<name>`
as in `fsm_extract.cc:393`, then the new wire takes the original name), and a new `$dff`, or a
`$adff` when the FSM has a non-constant async reset (ARST, ARST_POLARITY copied). The async reset
value is the reset state's code with every bit that is not `1` set to `0` (`:177-181`), which for
one-hot is `1` in bit 0 and zeros elsewhere. A FSM with no async reset gets a plain `$dff`:
**no reset value and no `init`**. (Consequence for equivalence, §15: a sync-reset one-hot register
powers up all-zero, an illegal code, until the first reset.)

**M-2 State decoder** (`:190-228`): per state, the "state is `i`" signal. For one-hot (code with
exactly one `1`) it is the state bit itself (a wire alias); otherwise an `$eq` of the code bits
that are `0`/`1` against the constant. If every state is a pure one-hot code the new wire gets
the attribute `onehot` (bool, `:227-228`).

**M-3 Next state** (`:230-296`): a single state: constant. Otherwise per target state `i`, the
signal "next state is `i`" built by `implement_pattern_cache`: for each input pattern, an `$eq` of
the constrained control inputs, ANDed with an OR of the source states that need it (omitted if
all states are covered), all OR-ed with `$reduce_or`. For one-hot the per-state signals connect
straight to the state bits (`:258-272`). For other encodings a `$pmux` selects the code of each
non-reset state, defaulting to the reset code (`:273-295`; x if there is no reset state).

**M-4 Control outputs** (`:298-316`): per `ctrl_out` bit, the same builder over the transitions
whose output is `1`. The old drivers of these nets have been detached first (X-5, done here), so
the new logic is their only driver.

**M-5 Cleanup.** The old `$dff`, its mux tree and the old compare cells are now unread; the next
`opt` in the script removes them (Yosys: the `opt_clean` inside `fsm`, `fsm.cc:143`, and later
`opt`). `fsm` does not call `opt_clean` itself in Odin III, to keep `fsm` free of `opt` state;
the script's following `opt` does it (divergence V-3). A `keep` old register survives (D-7).

**M-6 Structure of the new cells.** The cell types Yosys makes are `$dff`/`$adff`, `$eq`,
`$reduce_or`, `$and`, `$pmux`; all exist in the registry (`docs/IR.md`), with Yosys's parameters
(`A_SIGNED = B_SIGNED = 0`, widths from the signals). Unsigned throughout.

## 15. Equivalence of the result (T-2)

The recoded design is equivalent to the RTL **from reset**, not from the all-zero power-up state:
a sync-reset FSM gets a plain `$dff` with no reset value (M-1) and the one-hot register powers up
all-zero. This is the same in Yosys and Parmys (PHASE3 #43: `equiv-check` said NOT equivalent only
from the all-zero one-hot init, and equivalent after setting the reset-state bit). The equivalence
tool for the micros therefore proves a bounded miter after reset (`tools/fsm-check/fsm-equiv`, verified
on 0.55): `miter -equiv -flatten -make_assert gold gate m; async2sync; sat -verify -seq N
-set-init-zero -set-at 1 <rst> <v> -set-at 2 <rst> <v> -prove-asserts m`, with `<rst>` the reset
input(s) of each micro from its `tests/fsm/micros.txt` row. For the 19 designs the equivalence
rule of PHASE3 stands (big VTR designs are not equivalence-tested; they route and pass `fcheck`).

## 17. Provenance and FSM attributes (P-n)

**P-1 One operation per FSM** (`odin3_prov_begin_op` on the pass run, as the opt spec §15). The
objects it creates share one `DERIVED` record: the new state register node and its nets, the
decoder `$eq` cells, the next-state and output logic, and the new state wire.

**P-2 Parents**, in this order: the old state register node; then the mux-tree cells consumed
(ascending ID); then the nodes that drove the control outputs (ascending ID). A name derived from
the record leads with the first parent's source, so the new register is reported at the original
`reg` declaration. Nets that were control outputs keep their records (only their driver changed, IR-15).
Forward navigation from the source line of the `case` statement finds the dead old cells (slot or
tombstone) and the new logic.

**P-3 Attributes** (for Phase 6 items 6.2 and 6.3; names are agent defaults, question 7), set on
the new state wire and on the new state register node:

| Key | Kind | Value |
|---|---|---|
| `odin3_fsm_states` | INT | number of states after `fsm_opt` |
| `odin3_fsm_encoding` | STRING | the encoding in force after recode: `one-hot`, `binary`, `none` or `user` |
| `odin3_fsm_orig_bits` | INT | width of the original state register |
| `odin3_fsm_orig_name` | STRING | name of the original state wire |

Yosys's `onehot` bool attribute (M-2) is set on the wire as well. A register that `fsm_extract`
rejected carries none of these (its `fsm_encoding` attribute stays, as Yosys). The keys are
internal until Phase 6 exports them as versioned Odin III keys.

## 20. Open questions for Peter (each with a recommendation)

1. **The IR question: is there a `$fsm` cell?** No cell exists. Options: (1) add `$fsm` to the
   registry (an IR change, and the table's don't-care bit does not fit an IR `BITS` value);
   (2) keep the FSM representation inside the pass, no IR change; (3) recode the register
   directly with no table (not Yosys's algorithm). *Recommended: 2.* Option 1 stays available
   later without redoing the algorithm.
2. **How `fsm_opt` knows an output is unused** (Yosys reads `unused_bits` written by
   `opt_clean`). Options: (a) make `opt_clean` write the attribute; (b) a native "unread and not
   a port" test inside `fsm`. *Recommended: (b)*; switch to (a) only if T-3 measures a table
   difference.
3. **`keep` on a state register.** Yosys detects and recodes it and keeps the old register too.
   Options: follow Yosys, or treat `keep` as an exclusion. *Recommended: follow Yosys* (matches
   Parmys); `fsm_encoding = "none"` is the way to exclude.
4. **Evaluation cap** (X-6): 1,000,000 evaluations per FSM, then skip with a warning. *Recommended:
   yes*; Yosys has none, but a 2,000,000-node IR must not hang.
5. **Pre-`proc` `opt_expr; opt_clean; opt -nodffe -nosdff`**, which Parmys runs and Odin III's
   Phase 3 script does not. *Recommended: do not add them for 4.8.* The probe shows the same FSMs on
   the 12 designs probed; adding the lines changes every design, which is a separate decision.
6. **Who gets `fsm`.** *Recommended:* only scripts that name it; the VTR scripts (the Phase 3
   script and the `vtr-qor` legs) do. Not gated on `--vtr-compat`, and no new default flow.
7. **Names of the FSM attributes** (P-3: `odin3_fsm_states`, `odin3_fsm_encoding`,
   `odin3_fsm_orig_bits`, `odin3_fsm_orig_name`). *Recommended: as written*; Phase 6 may rename
   them when it versions the export keys.
8. **RAM write-enable registers that Yosys treats as 2-state FSMs** (§12). Port faithfully
   (recode them, as Parmys does) or exclude them. *Recommended: faithful*, because the goal is
   Parmys parity and the detection diff decides the rest; if Odin III's `proc` does not make
   these registers there is nothing to port, and the difference goes to the divergence list of
   2E, not to this pass.
9. **Equivalence method for the micros** (§15): a bounded Yosys miter after reset
   (`fsm-equiv`) instead of `equiv-check`, which starts one-hot registers all-zero.
   *Recommended: yes*, with the reset ports listed per micro; `equiv-check` stays the tool for
   the Phase 3 comparisons.
10. **stereovision3's unexplained flop** (PHASE3 #43). *Recommended:* not a blocker; the sweep
    after 4.8 either closes it or leaves a smaller `counts:` line, and the investigation is a
    follow-up task, not part of 4.8.

## 21. Review focus and risks

1. **Fidelity of the state order** (§4): the one-hot bit of each state follows Yosys's `Const`
   order; a different order is a correct but different encoding and fails T-3 (2).
2. **O-1** (question 2) is the only place the port computes a fact differently from Yosys.
3. **The iteration over control inputs** (X-4) is the hardest code to make iterative faithfully;
   the T-5 cases replay Yosys's logged tables (ch_intrinsics `cur_state` extracts with about 20 control inputs and ends with 5 inputs and 16 outputs).
4. **Detection depends on `proc`'s output shape**: one register per assigned variable chunk (2E
   spec §9, "what `fsm_detect` needs"), `$pmux` for `case`, the guessed reset state. A difference
   in 2E shows here first; T-3 isolates it from the port.
5. **`fsm` is REFUSE for processes**, so `proc` must have run; the Phase 2 script (no `fsm`) is
   unaffected.
