- **seen** with its `file:line`, or
- **to verify against the Intel LPM docs** (V-list in §11), where there is no local source or the

No name in this spec is invented. A rule that depends on an unverified name says so, and plan
Task 1 closes the V-list before any code. The test files `tests/micro/verilog/micro/bm_lpm_*.v` and

`bm_add_lpm.v` likewise. `ethmac.v:809` instantiates `altera_dpram_16x32`, a Quartus-generated
wrapper, not `altsyncram` (it is under an `ifdef` that is off).

**Gaps in the infrastructure** (each handled by a task, not by a rule change):
1. `.o3lib` parameters are `int` only (`reader_cell.c:352`: "only 'int' parameters are
   supported"). `intended_device_family`, `operation_mode` and `LPM_REPRESENTATION` are strings.
   Task 2 adds `param NAME string "text"` (L-3, question 2).
2. A `hard` cell must have a function for every output; only `blackbox` may have none (1G
   Syntax). LPM semantics are deferred, so the four cells are `blackbox` (L-2, question 1).
3. The BLIF writer refuses a `.subckt` whose parameters the reader would not derive
   (`blif/writer.h:116`), and `netlist-compare` reads BLIF only. A string parameter is not
   derivable. The round-trip comparison therefore cannot be plain BLIF (T-3, question 3).
4. The Verilog writer emits an empty `(* blackbox *)` stub for each hard or black-box type it
   writes (`writer.h`, "one `(* blackbox *)` empty module stub per black-box or hard cell type").
   Right for lint and read-back; wrong for Quartus, where the stub would shadow the real LPM
   module (W-4, question 5).

## 1. Purpose and scope (H-1)

`lpmmap` binds word cells to Altera LPM megafunctions by fixed rules, so that the Verilog writer
produces structural Verilog that instantiates `lpm_add_sub`, `lpm_mult`, `lpm_compare` and
`altsyncram` with parameters, and the rest as plain soft logic. It is the Altera counterpart of
3C `hardmap` and, like it, a fixed subset of DESIGN §7 (no matcher, D5/D10).

| In 5.1 | Not in 5.1 |
|---|---|
| `$add`, `$sub` to `lpm_add_sub` (A) | `lpm_ff`, `lpm_counter`, `lpm_mux`, `lpm_shiftreg`, `altdpram`, `altmult_add`, `altshift_taps` (decision 1: flip-flops are plain DFFs, the rest soft) |
| `$mul` to `lpm_mult` (M) | multiplier splitting, DSP-block parameters, pipelined multipliers (`LPM_PIPELINE` fixed at its default) |
| `$lt $le $gt $ge $eq $ne` to `lpm_compare` (C) | constant-operand compare specialisation |
| inferred `$mem` (one write, one read, one clock) to `altsyncram` SINGLE_PORT or simple DUAL_PORT (R) | true dual port, several reads or writes, two clocks, byte enables, memory initialisation files, ECC |
| `intended_device_family` set by a `--family` option | LPM simulation models and an equivalence check (decision 1); a Quartus compile |
| write, read back, lint tests (T) | Stratix verification (reachable by the option, untested: Quartus Lite has no Stratix) |

## 2. Where the pass sits (P-1 … P-4)

- **P-1 A new pass `lpmmap`, not a rule set inside `hardmap`. Recommended** (question 4).
  Reasons, all from the code:
  - `hardmap` is bound to the VTR arch in its data structures: `hm_kit.h` fixes its four types in
    `enum hm_hard { HM_ADDER, HM_MULTIPLY, HM_SP_RAM, HM_DP_RAM }`, and `mem.h`/`ram.h` carry the
    arch's 15-address-bit, 1-bit-slice shapes.
  - Its rules reproduce Parmys decision by decision (M-2 thresholds, 1-bit `adder` chains of
    `n + 2` cells, slicing). An LPM is a word-level block (`LPM_WIDTH` bits in one cell): nothing
    in A-1..A-9 or R-1..R-7 carries over, and none of 5.1's rules apply to the VTR flow.
  - `hardmap` is the pass of the Phase 3 exit test and Peter's Parmys-parity gate; a second rule
    set behind a flag would put the exit test's code under change for an optional target.
  - A separate pass has its own `docs/PASSES.md` row and its own tests (CLAUDE.md rule 1).
  `lpmmap` gets a small kit of its own (`lm_kit`, the transaction pattern of `hm_kit`: build on
  fresh nets, one provenance operation, delete the source, merge) instead of editing `hm_kit`.
  Folding the two kits into one is a follow-up, not part of 5.1.
- **P-2 Library.** `read_techlib lib/lpm.o3lib` registers the four types (L-1). `lpmmap` finds
  them by name and never creates a type: a missing or wrong-kind type is the located error
  `lpmmap: cell type 'lpm_add_sub' is not registered; read_techlib lib/lpm.o3lib first` (as 3C H-3).
  A type is looked up only when a rule fires, so a design with no `$add` does not need
  `lpm_add_sub`.
- **P-3 Script position and views.** `lpmmap` runs on the RTLIL view (word cells, IR-9) after `opt`
  and `wreduce`, before any `lower`, and does not need `flatten` (it maps per module and keeps
  the hierarchy; the Verilog writer writes every module). Recommended script:
  ```
  read_techlib lib/lpm.o3lib; read_verilog D.v; proc; opt; wreduce; opt_clean; opt -full;
  lpmmap [--family "Cyclone V"]; opt -full; write_verilog out.v
  ```
  There is no `lower` in this script: the soft remainder is written as word-level `assign`s
  (what Quartus wants as input, and readable for reverse engineering). A user who wants gates adds
  `lower` after `lpmmap`; `lower` never opens hard or black-box cells (3B O2).
- **P-4 Order and options.** Cells are mapped in node-ID order within each module, kind order
  `$add`/`$sub`, `$mul`, comparisons, `$mem` (determinism, H-8). Options: `--family NAME` only
  (§8). `processes = REFUSE`.

## 3. The library `lib/lpm.o3lib` (L-1 … L-4)

- **L-1 Four cells**, in `lib/lpm.o3lib`, `library lpm`. No other type, no `lpm_ff`.
- **L-2 Kind `blackbox`** (question 1). A black box has declared ports and parameters and no
  function (IR-7b). `read_verilog` resolves an instance of a `hard` or `blackbox` type to that
  type (EL-6 item 5), and the writer emits both as instances with a stub, so "LPM instances are
  hard cells" (PHASE5) holds in the IR-7b sense that matters: a registered type that `opt`,
  `lower` and the checkers leave alone. Simulation semantics (`fn`, `memory`) would need verified
  LPM behaviour and are deferred with the equivalence step (decision 1).
- **L-3 Parameter kinds.** `.o3lib` gains `param NAME string "text"` (a quoted default, no
  escapes). Integer parameters stay `param NAME int N`. Port widths are integer expressions over
  integer parameters (1G decision 3), so `dataa LPM_WIDTH` works as `adder`'s and `multiply`'s do.
  (Question 2: the alternative is no string parameters and a Verilog-side workaround, which
  fails the writer round trip.)
- **L-4 Contents.** Tables 3.1 to 3.4. Column "Source" is the evidence for the name.

Name case (V-8, verified): the Altera Verilog prototypes of `lpm_add_sub`, `lpm_mult` and
`lpm_compare` use lower-case port and parameter names (`lpm_width`, `lpm_widtha`, `dataa`;
UG-01063 p. 5-2, 4-2, 6-2), and so does `altsyncram` (Quartus wizard output, §3.4). String values
are upper case (`"SIGNED"`, `"UNUSED"`, `"SINGLE_PORT"`). The library uses these cases. The VHDL
declarations use upper case, which does not matter for Verilog.

**Verification of the `altsyncram` names and values (Task 1, 2026-10-19).**
- Ports, generics and their defaults match Quartus 16.0 help, "VHDL Component Declaration"
  (altsyncram; `ALTERA_MF_COMPONENTS.vhd`), https://resources.altera.com/quartushelp/16.0/mapIdTopics/jka1465580266892.htm.
  It confirms every port of the table above, lower-case names, and these input defaults: `rden_a`
  and `rden_b` '1', `wren_a` and `wren_b` '0', `clock0`, `clock1`, `clocken0..3` '1', `aclr0`,
  `aclr1`, `addressstall_a`, `addressstall_b` '0', `byteena_a` all '1' (width `width_byteena_a`,
  which settles the `[(width_a/8)-1:0]` quirk of V-10: byte enables are left out and default to
  all ones). It also gives `read_during_write_mode_port_a` and `_port_b` default
  `"NEW_DATA_NO_NBE_READ"`, `read_during_write_mode_mixed_ports` default `"DONT_CARE"`,
  `operation_mode` default `"BIDIR_DUAL_PORT"`, `intended_device_family` default `"unused"`.
- `operation_mode` values: `"SINGLE_PORT"`, `"DUAL_PORT"`, `"BIDIR_DUAL_PORT"`, `"ROM"`
  (Quartus 15.1 help, https://resources.altera.com/quartushelp/15.1/hdl/mega/mega_file_altsynch_ram_d1289e822.htm).
  **Simple dual-port is `"DUAL_PORT"`** (the lower-case `"dual_port"` in `megafunction_bb.v:489`
  is the same value in another case).
- `read_during_write_mode_mixed_ports` values: `"OLD_DATA"`, `"NEW_DATA"`, `"DONT_CARE"`;
  `read_during_write_mode_port_a` values: `"NEW_DATA_NO_NBE_READ"`, `"NEW_DATA_WITH_NBE_READ"`,
  `"OLD_DATA"` (same 15.1 page). `"NEW_DATA"` and `"OLD_DATA"` on mixed ports are supported only
  if the read address and output data use the write clock in MLAB mode (same page): so a
  transparent read across two ports (R-5) is not mapped.
- A Quartus (MegaWizard) generated Cyclone III simple dual-port instance

## 4. Common rules (H-2 … H-8)

- **H-2 Operand extension (`ext`).** As 3C A-2. `s = odin3_opt_both_signed(cell)` (PHASE2 #25: a
  mixed-sign cell is unsigned). For an operand `X` of width `w` resized to `n` bits: bits
  `i < min(w, n)` are `X[i]`; for `i >= w`, `X[w-1]` when `s`, else gnd. Truncation drops the high
  bits. This is exact for `$add`, `$sub` and `$mul` modulo `2^n`, and for comparisons when `n >=
  max(A_WIDTH, B_WIDTH)` (C-2).
- **H-3 Constants.** gnd and vcc are the canonical `$_CONST0_`/`$_CONST1_` nets. LPM operands that
  are constants stay constant nets; no folding (that is `opt`'s job and it ran). There is no `x`
  pad in 5.1: where a port is unused it is tied to a constant by the rule that names it.
- **H-4 Unused ports.** Ports the rule does not use are left unconnected, except the `altsyncram`
  ties of R-3, which follow `brams_map_m9k.v:71-90`. An unconnected output is written `.P()`
  (writer contract). An unconnected input of an LPM block reads as its Intel default (verified:
  `clken` 1, `add_sub` ADD, `cin` 0 for add and 1 for subtract, UG-01063 p. 5-3; `altsyncram`
  input defaults in §3.4). R-3 and R-4 still tie the `altsyncram` constants explicitly, as the
  Quartus wizard does.
- **H-5 Parameters.** Each new node carries its parameters as node parameters, in the type's
  parameter order. Integer parameters are INT, strings are STRING. The writer prints them as
  `#(.P(value))` (writer contract; STRING quoted byte-exact).
- **H-6 Provenance** (IR-12/13, D9). As 3C H-7: each source cell is one operation; every node it
  creates shares one DERIVED record whose parent is the source cell's record; the source is
  killed and its output nets survive as aliases where reused. The writer then ends each instance
  with `// file:line` of the first leaf of the DERIVED walk (writer contract). Each created node
  gets the string attribute `lpmmap` = `<type>:<role>` (for example `lpm_add_sub:add`), as 3C
  agent default (b); the writer prints it as an instance attribute `(* lpmmap = "..." *)`.
- **H-7 Names.** The new node takes the source cell's name (made unique by the IR's `_N` rule when
  a cell makes more than one node; 5.1 makes one node per cell).
- **H-8 Determinism, memory, diagnostics.**
  - Node-ID order within a module, new nodes appended; two runs give byte-identical Verilog.
  - Each mapping builds all nodes and nets before it kills the source, so `NO_MEMORY` leaves the
    IR valid and the source cell intact (3C H-9). Budget checked with `odin3_budget_check` per
    cell kind.
  - INFO `lpmmap: N lpm_add_sub, M lpm_mult, K lpm_compare, R altsyncram; S cells left soft`.
    One WARN per cell left soft by an S rule. DEBUG one line per mapped cell. ERROR for P-2.

## 5. `$add` / `$sub` to `lpm_add_sub` (A-1 … A-5)

- **A-1 Candidates.** Every live `$add` and `$sub` with `Y_WIDTH >= 1`. A cell with
  `Y_WIDTH = 0`, or an operand of width 0, is left alone silently. `$neg` is soft (S-1).
- **A-2 Width.** `LPM_WIDTH = Y_WIDTH`. Both operands are resized to `Y_WIDTH` by H-2. Since add
  and subtract are modular, the low `Y_WIDTH` bits are right whatever the operand widths, so no
  carry-out is needed and `cout` and `overflow` stay open. `wreduce` has already capped
  `Y_WIDTH` at `max + 1` where that holds, so the block is never wider than the result.
- **A-3 Ports.** `dataa = ext(A)`, `datab = ext(B)`, `result = Y`. `cin`, `add_sub`, `clken`,
  `clock`, `aclr`, `cout`, `overflow`: unconnected (H-4).
- **A-4 Parameters.**
  - `lpm_width = Y_WIDTH`.
  - `lpm_direction`: `"ADD"` for `$add`, `"SUB"` for `$sub` (values per §3.1; `add_sub` is then
    left open, as UG-01063 p. 5-3 requires).
  - `lpm_representation`: `"SIGNED"` when `s`, else `"UNSIGNED"` (both verified, §3.1). It records the source's signedness for the reader
    of the Verilog; the value of the result does not depend on it (A-2).
- **A-5 Subtract and carry-in.** For `$sub` the rule relies on `lpm_direction = "SUB"` computing
  `dataa - datab` with `cin` unconnected: UG-01063 p. 5-3 gives the default of an omitted `cin`
  as 1 for subtraction, which is the carry-in of `a + ~b + 1`. Verified (V-1).

Example: `$sub A[7:0] B[7:0] -> Y[7:0]`, unsigned, becomes
structural text (port order as in the library):
```
lpm_add_sub #(.lpm_width(8), .lpm_direction("SUB"), .lpm_representation("UNSIGNED")) u0 (
  .dataa(a), .datab(b), .cin(), .add_sub(), .result(y), .cout(), .overflow(),
  .clken(), .clock(), .aclr());
```

## 6. `$mul` to `lpm_mult` (M-1 … M-5)

- **M-1 Candidates.** Every live `$mul` with `A_WIDTH`, `B_WIDTH`, `Y_WIDTH` all at least 1. A
  constant operand is not special-cased. There is no width threshold (no arch): a 2x2 multiply is
  an `lpm_mult` too (question 7).
- **M-2 Widths.** `A` and `B` keep their widths (no extension: the block takes any widths).
  `LPM_WIDTHP = A_WIDTH + B_WIDTH` and `result` is that wide; `Y[i]` is `result[i]` for
  `i < min(Y_WIDTH, A_WIDTH + B_WIDTH)`. The extra `result` bits dangle (writer: `$p<ID>`
  wires). Using the full product width is required: when `lpm_widthp` is smaller than the full
  product only the `lpm_widthp` most significant bits are present (UG-01063 p. 4-3, verified,
  V-3), so a narrower `lpm_widthp` would return the wrong bits.
- **M-3 Signedness.** `s` as H-2.
  - Both signed: `lpm_representation = "SIGNED"`.
  - Otherwise unsigned: `"UNSIGNED"` (a mixed cell is unsigned, PHASE2 #25).
- **M-4 Y wider than the product.** `Y_WIDTH > A_WIDTH + B_WIDTH` stays soft with the WARN
  `lpmmap: '$mul' '<c>' has Y wider than A + B; left soft (run wreduce first)` (as 3C M-3: the
  extra bits would need a merge after the delete). It cannot occur after `wreduce`.
- **M-5 Ports and parameters.** `dataa = A`, `datab = B`, `result` as M-2; `sum`, `clock`, `clken`,
  `aclr` unconnected. Parameters: `lpm_widtha = A_WIDTH`, `lpm_widthb = B_WIDTH`, `lpm_widthp = A_WIDTH +
  B_WIDTH`, `lpm_widths` left at its default 1, `lpm_representation` as M-3, `lpm_pipeline = 0`
  (combinational, p. 4-4), `lpm_type`, `lpm_hint` left at the library defaults (names verified,
  §3.2). Pipelined multipliers are out of scope.

## 7. Comparisons to `lpm_compare` (C-1 … C-4)

Names verified (V-4, §3.3: UG-01063 chapter 6). Output meanings are from the Intel online guide
(§3.3).

- **C-1 Candidates and outputs.** Every live `$lt $le $gt $ge $eq $ne` whose `A_WIDTH` and
  `B_WIDTH` are at least 1. The result drives `Y[0]` from the matching output:

  | Cell | Output (expected) |
  |---|---|
  | `$lt` | `alb` |
  | `$le` | `aleb` |
  | `$gt` | `agb` |
  | `$ge` | `ageb` |
  | `$eq` | `aeb` |
  | `$ne` | `aneb` |

  The other five outputs are unconnected. `Y[1..]` (a `Y_WIDTH` above 1) are gnd, merged with
  `odin3_net_merge` (as 3C agent default (c)).
- **C-2 Widths and signedness.** `LPM_WIDTH = max(A_WIDTH, B_WIDTH)` (the Verilog comparison
  width). Both operands are extended to it by H-2 (sign-extended only when both signed, so a
  mixed-sign compare is unsigned, matching PHASE2 #25 and `lower`'s `$lt` rule). The
  representation parameter is `"SIGNED"` when both signed, else `"UNSIGNED"`.
- **C-3 Every width goes hard.** No threshold: a 1-bit `$eq` is an `lpm_compare` (question 8). It
  is wasteful and correct, and it keeps the rule table fixed.
- **C-4 Ports.** `dataa`, `datab` as C-2; every other port open.

## 8. Memories to `altsyncram` (R-1 … R-9)

Candidates are inferred `$mem` cells (the form of 3C §6.2, EL-27/EL-39). `$mem` parameters used:
`SIZE`, `OFFSET`, `ABITS`, `WIDTH`, `RD_PORTS`, `WR_PORTS`, `RD_CLK_ENABLE`, `RD_CLK_POLARITY`,
`RD_TRANSPARENT`, `WR_CLK_ENABLE`, `WR_CLK_POLARITY`, `INIT` (`src/ir/cells/mem.c`).

- **R-1 FF merge first.** An altsyncram read is synchronous. As 3C R-8, each `$mem` read port
  with an asynchronous read (`RD_CLK_ENABLE` 0) whose `RD_DATA` bits each feed one `$dff` (or a
  `$dffe` whose enable becomes the port's `RD_EN`) on one clock and polarity becomes synchronous
  and the flip-flops go (data merge); else if `RD_ADDR` is the `Q` of `$dff`s on one clock the
  address merge applies, only when no write port is on that clock (3C D12). Without this step
  almost no `$mem` is mapped, because `proc`/`opt` leave the read register separate. Plan Task 7
  first measures how far `mem_merge.c` is coupled to the VTR RAM model: if it splits cleanly the
  merge is reused through a new header with no change of behaviour; if not, `lpmmap` implements
  the data merge only and an address-merge candidate stays soft (question 9). A `$mem` that ends
  soft keeps its original flip-flops (3C agent default (d)).
- **R-2 Patterns mapped.** After R-1, with `r` read ports and `w` write ports:

  | r, w | Mapping | `operation_mode` |
  |---|---|---|
  | 1, 1, read and write address nets identical | one RAM port | single-port |
  | 1, 1, addresses not identical | write on port a, read on port b | simple dual-port |
  | any other | soft (S-3) | |

  Every other pattern (read only, write only, `r > 1`, `w > 1`) stays soft with the WARN
  `lpmmap: memory '<m>' (<r> read, <w> write ports) has no 5.1 mapping; left soft`. The
  `operation_mode` strings are `"SINGLE_PORT"` and `"DUAL_PORT"` (simple dual-port), both
  verified (§3.4).
- **R-3 Single-port instance** (copied from `brams_map_m9k.v:45-90`, the one complete local
  instance):

  | Port or param | Value | Line |
  |---|---|---|
  | `data_a`, `address_a`, `wren_a`, `rden_a`, `q_a` | `WR_DATA`, `WR_ADDR`, `WR_EN` bit, `RD_EN`, `RD_DATA` | `:71-75` |
  | `clock0` | the clock | `:81` |
  | `data_b`, `address_b`, `wren_b`, `rden_b`, `q_b` | gnd, gnd, gnd, gnd, open (the techmap ties `data_b` to the write data and `address_b` to 0; 5.1 ties `data_b` to gnd instead, a deliberate, harmless difference) | `:76-80` |
  | `clock1`, `clocken0..3` | vcc | `:82-86` |
  | `aclr0`, `aclr1`, `addressstall_a`, `addressstall_b` | gnd | `:87-90` |
  | `width_a`, `width_b` | `WIDTH` | `:67,69` |
  | `widthad_a`, `widthad_b` | `ABITS` (1 when `ABITS = 0`) | `:66,68` |
  | `numwords_a`, `numwords_b` | `SIZE` (the techmap uses a mode table, `:64-65`, which is its own M9K limit) | |
  | `operation_mode` | `"SINGLE_PORT"` | `:54` |
  | `intended_device_family` | the `--family` value (§9) | `:55` |
  | `read_during_write_mode_port_a` | R-5 | `:62` |
  | the string defaults of §3.4 | library defaults | |

  A `RD_EN` that is constant 1 is tied to vcc. A `RD_EN` that is not constant leaves the `$mem`
  soft with the WARN `lpmmap: memory '<m>' has a read enable that is not constant 1; left soft`,
  because the behaviour of `rden` low (the output holding its value) is not verified (V-7, open);
  this is the 3C D9 rule and it can be lifted when V-7 is closed.
- **R-4 Simple dual-port instance.** Write on port a (`data_a`, `address_a`, `wren_a`), read on
  port b (`address_b`, `rden_b`, `q_b`), `clock0` the clock for both, `width_b` and `widthad_b`
  the read side's (equal to `width_a` and `widthad_a` here), `q_a` open, `data_b` gnd, the
  other ports tied as in R-3. Shown by the wizard instance of §3.4: one clock on `clock0`, `address_reg_b = "CLOCK0"`,
  `outdata_reg_b = "UNREGISTERED"`. These two parameters are therefore **in the library and set
  by this rule** (`address_reg_b = "CLOCK0"`, `outdata_reg_b = "UNREGISTERED"`; declared in the
  Quartus 16.0 component, §3.4). A read on a second clock stays out of 5.1 (R-6).
- **R-5 Read-during-write.**
  - Single-port: `RD_TRANSPARENT` 1 (the read sees the new data) is
    `read_during_write_mode_port_a = "NEW_DATA_NO_NBE_READ"`; `RD_TRANSPARENT` 0 (old data) is
    `"OLD_DATA"` (both values verified, §3.4).
  - Simple dual-port: `read_during_write_mode_mixed_ports` (default `"DONT_CARE"`).
    `RD_TRANSPARENT` 0 maps to `"OLD_DATA"` (as the wizard instance of §3.4 does);
    `RD_TRANSPARENT` 1 stays soft with the WARN `lpmmap: memory '<m>' has a transparent read
    across two ports; left soft` (`"NEW_DATA"` across ports is supported only in MLAB mode with
    the write clock, §3.4).
- **R-6 Not mapped (soft, with the S-3 WARN):** a falling-edge read or write clock; a read and a
  write on different clocks; `OFFSET != 0`; a `WR_EN` whose bits are not one net (a byte-enable
  pattern); a `$mem` with a defined `INIT` (no initialisation file in 5.1; dropping it would
  change behaviour silently, so unlike 3C R-12 the cell stays soft); an asynchronous read port
  left after R-1.
- **R-7 Widths.** Any `WIDTH` and `ABITS` map as one `altsyncram` (Quartus fits the blocks; no
  slicing or depth split, unlike 3C R-1..R-4). A port wider than the reader's cap (`2^20` bits,
  `ODIN3_READER_MAX_WIDTH`) is the located error the writer and reader already give.
- **R-8 Names and provenance.** H-6 and H-7; the role is `sp` or `sdp`.
- **R-9 Flip-flops are not touched** (decision 1). The read register absorbed by R-1 is the only
  flip-flop `lpmmap` removes.

## 9. The family option (P-4, F-1 … F-2)

- **F-1 `lpmmap --family NAME`.** `NAME` is any non-empty string, stored unchanged as the
  `intended_device_family` STRING parameter of every `altsyncram` node. Default `"Cyclone V"`.
  Not validated and not mapped to anything else: Stratix is reachable (`--family "Stratix IV"`)
  and untested (Quartus Lite has no Stratix; D10). The 5.1 library does not carry
  `intended_device_family` on the three `lpm_*` cells: the Altera Verilog prototypes do not
  declare it (UG-01063 p. 5-2, 4-2, 6-2; only the LPM_COMPARE parameters table lists it, p. 6-4,
  as computed by the parameter editor), so question 6's recommendation stands (V-2).
- **F-2 Spelling.** The default is the spelling D10 and PHASE5 use. Local files show
  `"MAX 10 FPGA"`, `"auto"` and `"CYCLONE IVE"`, a Quartus wizard instance `"Cyclone III"` and an
  Intel community post `"Cyclone V"` (§3.4); `"Cyclone V"` is consistent with the family names
  Quartus writes, but is not confirmed by a primary document. It stays the default and is the one
  open spelling (V-5).

## 10. Writing, reading back, and the CLI (W-1 … W-5)

- **W-1 Writer.** No change in 5.1. `write_verilog` writes each `lpm_*`/`altsyncram` node as a
  module instance with `#(.P(value))` and named ports in the library's port order
  (`writer.h`: "Any other cell (module, hard, black-box, ...) is a module instance"), the soft
  remainder as `assign`s and `always` blocks, and one `(* blackbox *)` stub per type written.
- **W-2 Stubs and lint.** The stubs make the file self-contained for Icarus and Verilator. A port
  whose width is a parameter is `[P-1:0]` in the stub, so a width mismatch between an instance
  and its parameter is a lint finding (this is the check on A-2, M-2, C-2 and R-7).
- **W-3 Read back.** `read_techlib lib/lpm.o3lib; read_verilog out.v` resolves each
  `lpm_*`/`altsyncram` instance to the registered type (EL-6 item 5), with its parameters
  converted to the type's parameter kinds (2D spec, INSTANTIATION). The `(* blackbox *)` stubs in
  the same file are definitions of registered type names, so 2D's rule applies: the file's
  definition is ignored for a registered cell type and its widths are taken from the registered
  type (IR-7b, EL-11). If that is wrong in practice the test (T-2) fails and the fix is a 2D
  rule, which would go to Peter; no change is planned.
- **W-4 Quartus.** A Verilog file with stubs must not go to Quartus: the empty stub would
  shadow the real `lpm_*` module. 5.1 does not change this (Quartus compile is deferred, decision
  1); the one-line workaround is to delete the stub block. A `write_verilog --no-stubs` option is
  the follow-up (question 5).
- **W-5 CLI and script surface.**
  - `lpmmap [--family NAME]`; no other option; unknown options are `lpmmap: unknown option`.
  - Registered in `src/passes/builtin.c` with a `docs/PASSES.md` row and
    `processes = ODIN3_PASS_PROCESSES_REFUSE`.
  - `read_techlib lib/lpm.o3lib` (existing pass).
  - The CLI form: `odin3 -p "read_techlib lib/lpm.o3lib; read_verilog D.v; proc; opt; wreduce;
    opt_clean; opt -full; lpmmap; opt -full; write_verilog out.v"`.
  - The VTR flow's script is not changed.

## 12. Tests (T-1 … T-4) and what is not tested

- **T-1 One micro per LPM cell** (`tests/lpm/`): `lpm_add_sub.v` (an `$add` and a `$sub`,
  signed and unsigned), `lpm_mult.v`, `lpm_compare.v` (the six comparisons), `altsyncram_sp.v`,

  checks the instance count and parameter values.
- **T-2 Write, read back, same netlist.** `write_verilog` of the mapped design, then a fresh run

  same netlist, with the LPM instances typed as the registered hard (black-box) cells.
- **T-3 How "same" is decided** (question 3). The BLIF writer cannot carry string parameters
  (`blif/writer.h:116`), so `netlist-compare` on BLIF is not the primary comparison. Primary:
  the two `write_verilog` texts are byte-identical (the writer is deterministic and keeps names;
  this is a fixpoint test) and `odin3_check_design` FULL passes on the read-back design.
  Secondary, as far as BLIF can express it: `write_blif` of the design with the LPM cells
  replaced by black boxes through `ODIN3_BLIF_ATTR_EXTRAS` (plan Task 8 step 1 checks this
  route first), compared with `netlist-compare`. If the secondary route needs a tool change, it
  is dropped and logged, and `write_json` text equality takes its place.
- **T-4 Verilog lint with stub modules.** Both tools are installed here: `/usr/bin/iverilog` and
  `/usr/bin/verilator`. Required gate: `iverilog -g2005 -Wall -o /dev/null out.v` with no

## 14. Questions for Peter (each with a recommendation)

   functions? **Recommend `blackbox`.** Functions need verified LPM behaviour (V-1 to V-4) and

   the same.

   reader and width-rule-free change, plan Task 2)? **Recommend yes.** The LPM parameters are
   strings (`intended_device_family`, `operation_mode`, `lpm_representation`), and without them
   the write and read-back round trip cannot carry the family.
3. **How the round trip is compared.** `netlist-compare` reads BLIF and BLIF cannot carry string
   parameters. Accept the Verilog fixpoint (write, read, write: identical text, plus `check`
   FULL) as the 5.1 "same netlist", with the BLIF route as a bonus if it works?
   **Recommend yes.** Extending `netlist-compare` to read Yosys JSON is 5.3's reader plus a
   tool change and does not belong in a light item.
4. **Pass placement.** A new pass `lpmmap` with its own small kit (P-1), or an `--lpm` rule set

## 16. Changes found by the implementation (v1.2, 2026-10-19)

None of them changes a mapping rule of §5 to §8.

1. **T-3, the round trip.** Reading turns an open instance pin into `1'bx` (inputs) or a fresh net
   `$n<ID>` (outputs), so `write_verilog` of the read-back design differs from the first text in
   exactly those connections. The primary check is therefore a fixpoint of generation 2 to 3
   (`// file:line` comments dropped), plus an instance-by-instance comparison of generation 1 with
   generation 2 (type, name, parameters, connected pins; open, x and fresh-net pins equal). The read
   runs with `--check`. The BLIF leg is dropped: `write_blif` refuses LPM cells (`parameters
   neither declared nor implied by the connected formals have no BLIF form`).
2. **T-4, the lint.** `iverilog -g2005 -Wall` notes every open instance input as a floating port;
   those notes are the Altera defaults of H-4 and are filtered, and any other finding (a width
   mismatch against the stub, a syntax error) fails. Verilator runs `--lint-only -Wall` with
   `-Wno-DECLFILENAME -Wno-UNUSED -Wno-UNDRIVEN -Wno-PINCONNECTEMPTY -Wno-PINMISSING`.
3. **The `.o3lib` reader** (L-3) also lets a port be called `clock` (spec 1G amendment of
   2026-10-19); `lpm_add_sub`, `lpm_mult`, `lpm_compare` have a port `clock`.
4. **R-1 reuse.** `mem_load` and `mem_model_free` are exported from `src/passes/hardmap/mem.c`
   (declared in `mem.h`) so `lpmmap` runs hardmap's R-8 merge on its own copy of the `$mem`.
5. **Soft-memory warnings** (§13 additions; each is `lpmmap: memory '<m>' ...; left soft`): `has
   OFFSET <n>`, `has initial contents`, `has an asynchronous read port`, `has a port on the falling
   clock edge`, `has read and write ports on different clocks`, `has a write enable that is not one
   net`, `has a read enable that is not constant 1`, `has a transparent read across two ports`, and
   `(<r> read, <w> write ports) has no 5.1 mapping`.
6. **Debug `check`** logs rule 11 warnings for the open LPM input pins; they are warnings.
7. **Open items.** V-7 (the behaviour of `rden` low; R-3 maps only a constant 1) and a primary
   document for the `"Cyclone V"` spelling (V-5) remain open (§11).
