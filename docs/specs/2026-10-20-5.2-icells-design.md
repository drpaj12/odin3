# 5.2: Verilog read-back at every level (`read_verilog -icells`): design

Status: v1.1 (2026-10-20). **Agent defaults taken** for the questions of §12 (PHASE5 decision 9);
Peter may override. v1.1 records what the implementation changed (§13); it supersedes the text it
names. This item is not a mapping algorithm and changes neither the IR, the ABI,
an ADR nor how Verilog without `-icells` elaborates, so the controller approves the plan and the
lane implements (task statement 2026-10-20). Rules have IDs (**I-n** resolution, **N-n** names and
stubs, **V-n** validation, **X-n** exceptions, **T-n** tests) so they can be changed line by line.

Phase 5, item 5.2 (PHASE5.md, D11): a `read_verilog -icells` mode, as Yosys's, that reads an
instance of one of Odin III's own cell types (`$mem`, `$shiftx`, `$pow`, `$dffsr`, `$dlatch`, the
word flip-flops, ...) as that cell and not as an unknown module. Test: for the micros, write
Verilog after `opt` (word), after `lower` (gate), after `abc` (LUT) and after 5.1 (LPM), read each
back, and show the read-back netlist equivalent to the netlist that was written.
HDL locations on read-back are 5.4, not this item (provenance stays as it is, §8).

## 0. What the repo already gives, and what it does not

**Already there.**
1. Stage 2 (`elab2_inst.c`) already builds a node of any registered cell type from an
   `INSTANTIATION`: parameters from `#(...)` (`odin3_elab2_param_value`: INT, BITS and STRING),
   ports by name, widths from the registry (`odin3_celltype_port_width_checked`), parameters
   inferred from connection widths (`odin3_celltype_infer_params`) when not given. Stage 1 checks
   a cell type's parameter names (`cell type 'T' has no parameter 'P'`), its port names and
   connection count. This is the path of `hard` and `black box` types (tech library cells, 5.1's
   LPM cells), reached by EL-6 item 5.
2. EL-6 refuses it for built-in types by name only: `resolve_outside` accepts only granularity
   `hard` or `blackbox`, and §3.1a says names beginning with `$` never resolve to built-in
   types. Without `-icells` an instance `\$mem u (...)` is therefore `unresolved_module`.
3. The writer (`writer.h`) writes a built-in cell as a module instance, with every parameter as
   `#(.P(value))` and every port by name, whenever the cell is not one of `BUILTINS` (the table
   of cells written as `assign`s and always blocks) and not a module. It writes
   `(* blackbox *)` stubs only for `hard` and `black box` types (`stub_kind`).

**Not there.**
1. An option to let `$` names resolve (`-icells`).
2. A strict check of widths: stage 2 resizes a connection to its port with a warning (I4). That
   is right for user Verilog and wrong for a netlist read back (V-3).
3. A way to read an empty BITS parameter: the writer spells a zero-length BITS value `""`, which
   `odin3_elab2_param_value` rejects for a BITS parameter (`is not an integer`) (V-5).
4. A round-trip tool and tests at the four levels (§9).

## 1. The option (I-1, I-2)

**I-1.** `read_verilog` gains `-icells`, and `--icells` as a second spelling (the pass's own
options are `--` options; `-icells` is Yosys's spelling and the one the task and PHASE5 use). Both set
`odin3_elab_opts.icells` (an internal struct in `src/frontends/elab/elab.h`, not the C ABI).
Without the option nothing changes: not one byte of the resolution, the diagnostics or the IR
differs (T-1 proves it on the existing corpus).

**I-2.** `-icells` is refused with `--lib` and with `--parse-only`:
`read_verilog: -icells cannot be combined with --lib` (a `--lib` read keeps units for later reads,
which would elaborate under the later read's options) and likewise `--parse-only` (nothing is
elaborated). Same style as `check_lib_args` for `--auto-blackbox`.

## 2. Resolution (I-3 to I-7)

**I-3.** A new first step of EL-6, **item 0**, before the module chain, only when `icells` is set
and the instantiated name begins with `$`: look the name up among the design's registered cell
types (`odin3_celltype_find`). Found and instantiable (I-4): the instance is that cell
(`ODIN3_RES_CELLTYPE`, the existing kind, so stage 1 and stage 2 treat it exactly as a library
cell). Items 1 to 7 are not consulted, so no module, library unit or `(* blackbox *)` stub
named `$...` can shadow a registered type (N-1).

**I-4.** Instantiable: every registered type whose granularity is not `module` and that is not a
port (`ODIN3_GRAN_PORT`: `$port_in`, `$port_out`, `$port_inout`) or a process (`ODIN3_CT_PROCESS`:
`$proc`). That is the whole registry otherwise: word cells, bit cells, gates, constants, `$sop`,
`$lut`, memories, flip-flops, plugin types, `hard` and `blackbox` types with a `$` name. It is not
limited to the cells the writer emits as instances, so a hand-written netlist may instantiate
`\$add` or `\$_AND_` too (Yosys does the same). Refused types: located error
`cell type '$proc' cannot be instantiated from Verilog (a process; run proc first)` and
`cell type '$port_in' cannot be instantiated from Verilog (a module port)`.

**I-5.** A `$`-prefixed name that is not a registered type, under `-icells`: located error at the
instantiation `unresolved_module: cell type '$foo' is not registered (read_verilog -icells)`.
`--auto-blackbox` does not turn it into an implicit black box (a typo of a cell name must not
vanish).

**I-6.** A non-`$` name resolves exactly as without `-icells` (so a design may mix library cells,
user modules and `$` cells, which is what the LPM level needs).

**I-7.** Instance forms: named ports and named `#(.P(v))` parameters as the writer prints them;
positional ports and ordered parameters are accepted as for any registered type (stage 1 already
does). The instance array form `\$and u [3:0] (...)` is accepted as for any registered type.

## 3. Names, stubs and shadowing (N-1 to N-3)

**N-1 (how the stubs do not shadow).** The writer never writes a stub for a built-in type: it
writes `(* blackbox *)` stubs only for granularity `hard` and `blackbox` (`stub_kind`), and the
built-in types are word, bit and port granularity. A `$`-named `hard` or `blackbox` type (a
plugin) does get a stub. Under `-icells` item 0 (I-3) resolves the instance to the registered type
before the chain is looked at, so the stub, which is a module definition of the same name, is
never reached by that instance, never specialized, and so never triggers the "has the name of cell
type" error of EL-6 (`report_taken` runs only for a definition that is reached). An info line says
once per name `module '$x' is a stub of a registered cell type; ignored (read_verilog -icells)`.
Without `-icells` behaviour is as before (the stub resolves as a module; the unchanged rule).

**N-2.** `-icells` does not register anything. A type is read only if it is registered in the
design: a built-in, a plugin type, or a type from `read_techlib`/`read_blif` earlier in the
script. The LPM level (T-2, level 4) therefore reads `lib/lpm.o3lib` before the Verilog, as the
5.1 round trip does; the `lpm_*` and `altsyncram` instances resolve by EL-6 item 5 and their
stubs are the library units 5.1 already handles.

**N-3.** Instance names: an instance keeps its name (`$c12`, `\u1 `) as it does for any cell;
the writer's generated names `$c<ID>`, `$n<ID>`, `$w<ID>`, `$p<ID>` read back as ordinary
identifiers.

## 4. Validation against the registry (V-1 to V-6)

All errors are located at the offending connection or parameter (file:line:col from the AST) and
count against the elaboration error cap like any `ODIN3_ERR_PARSE`.

**V-1 (parameters, existing).** An unknown parameter name: `cell type 'T' has no parameter 'P'`
(stage 1, exists). A value that is not an integer for an INT parameter: exists.

**V-2 (parameter kinds, new wording under `-icells`).** A value that does not fit the kind of its
parameter is `value of parameter 'P' of cell type 'T' is not an integer` (INT given a string),
`... is not a string` (STRING given a number) or `... is not a bit vector` (BITS given anything
but a number or a string).

**V-3 (port widths, new, strict).** For an instance resolved by item 0, a connection whose width
differs from the port's width (the width the registry gives for the instance's parameters) is the
error `port 'A' of '$add' instance 'u' is 8 bits; the connection is 4 bits` (the existing resize
warning of I4 stays for every other instance). A wholly unconnected port (`.P()`) is not an
error: an input becomes the constant x, an output a fresh net, the same as 5.1's `lpm-check`
documents. An input connected to an unsized constant is a width error too (the writer always
sizes its literals).

**V-4 (unknown port).** `.X(...)` naming no port: `cell type 'T' has no port 'X'` (stage 1, exists;
the test pins the text).

**V-5 (empty BITS).** The writer spells a zero-length BITS parameter `""` (no Verilog literal
exists). Under `-icells`, a string literal given to a BITS parameter is read as the bits of its
bytes (Verilog's rule, a string is a vector), and the empty string as the zero-length BITS value:
this is the inverse of the writer, so the value round-trips exactly. Without `-icells` the error
stays.

**V-6 (parameter rules of the type).** The type's own `verify` hook (`odin3_celltype_def.verify`,
for example `$mem` geometry, `$sop` cover shape, `$lut` INIT width) is run on the instance's
parameter set; a failure is a located error on the instance
`instance 'u' of '$mem': <reason>` and not an IR check failure later. (If node creation already
reports it with the cell, V-6 only adds the location; Task 3 finds out.)

## 5. What round-trips and what does not (X-1 to X-8)

The writer writes three kinds of cell: instances (read by `-icells`, this item), `assign`s (read as
ordinary Verilog expressions: they come back as other word cells, same function) and always
blocks (read as `$proc`, then `proc`). So the claim at each level is **equivalent**, not
identical (T-2). The exceptions:

| ID | Case | What happens |
|---|---|---|
| X-1 | `$proc`, `$port_*` instance | located error (I-4); the writer never writes them, and a design with a live `$proc` is not a netlist (write after `proc`) |
| X-2 | zero-length BITS parameter | exact through V-5 |
| X-3 | an open instance pin | reads as x (input) or a fresh net (output); generation 2 differs from generation 1 in exactly those pins (5.1 decision 7); the fixpoint is generation 2 to 3 |
| X-4 | a name the writer cannot write (blank, backtick, control or non-ASCII byte) | the writer already refuses (`INVALID_ARG`); the round trip does not start |
| X-5 | `$_FF_` (global clock) and INIT 2/3 start values | **to confirm by Task 5**; if the reader cannot take `(* gclk *) $gclk`, it is a documented exception listed in the tool's expect file, never silent |
| X-6 | `$pmux` with several select bits set | the writer ORs the slices; the read-back is the same expression, so the same function (Yosys simlib says x); the equivalence is a refinement, gold x is don't care |
| X-7 | provenance | not read back: every read-back object is IMPORTED from the Verilog line (spec 2C), as for any Verilog; 5.4 adds `src` attributes |
| X-8 | a netlist with a hierarchy of user modules | read as modules (item 6 of EL-6 order is unchanged); only cells are special |

Every item of this table that is not "exact" is either an error with a location, an INFO or a
line of `tests/icells/expect.txt` that the tool prints; none is silent (T-5).

## 7. The round trip (T-2)

One tool, `tools/icells-check/icells-check`, one design and one level per run:

```
icells-check --level word|gate|lut|lpm [--odin3 P] [--yosys Y] [--keep DIR] DESIGN.v
```

Per level the tool runs Odin III twice.

*Written side* (script A; the level's script, §8, ends `write_rtlil G.il; write_verilog W.v`).
`G.il` is the gold: the netlist as it was written. *Read-back side* (script B):
`[read_techlib lib/lpm.o3lib;] read_verilog -icells W.v; proc; opt_clean; write_rtlil R.il;
write_verilog W2.v`, then script C reads `W2.v` the same way and writes `W3.v`.

Legs, in order, first failure printed, exit 1:

1. **read**: script B exits 0 with no `error` line.
2. **check**: B runs with `--check` (the IR invariants hold on the read-back).
3. **equivalent**: `G.il` and `R.il` through `opt_equiv.Checker.judge` (the 2F/3B refinement:
   Yosys 0.55 `equiv_make; equiv_simple -undef -seq 4; equiv_induct -undef`, clock-aware
   lowering, hard blocks cut by name and width, base case from the initial state). See Q7.
4. **fixpoint**: `W3.v` equals `W2.v` once `// file:line` comments are dropped (generation 2 to 3,
   as 5.1; the reading is deterministic).
5. **instances**: every `$`-type instance of `W.v` is, in `W2.v`, an instance of the same type,
   name and parameters, with connected pins equal up to the open-pin rule of X-3
   (`lpm-check`'s comparison, reused). This is what proves the cells came back as cells and not as
   expression logic.

Exit codes follow the opt tools: 0 ok, 1 a leg failed, 2 usage or tool error, 3 crash, 4
unproven (a size limit), 77 skipped (no Yosys).

## 8. The four levels (scripts)

The scripts are the single source in `tests/icells/<level>.script` (`@DESIGN@`, `@OUT@`, `@IL@`
substituted), not re-spelled in the tool.

| Level | Script before the writes | What is written |
|---|---|---|
| word | `read_verilog --nolatches @DESIGN@; proc; opt; opt_clean` | word cells: `$mem`, `$shiftx`, `$pow`, word flip-flops are instances |
| gate | the word script, then `flatten; opt -full; lower; opt -fast` | bit cells; bit storage cells such as `$_DFFE_PP_` are instances |
| LUT | the gate script, then `abc --lut 6` | `$lut`/`$sop`-style cells and flip-flops |
| LPM | `tests/lpm/lpm.script` (5.1) | `lpm_*`, `altsyncram`, soft remainder, and `$mem` that stays soft |

(`proc`, `lower`, `abc`, `lpmmap` exist; the exact pass lists are fixed by Task 4 against what
each micro needs, with a design that a level cannot process listed in the expect file with its
reason.) A design that gives no instance of a `$` type at a level still runs the legs (the
`assign` and always block path is read back and proved), but the unit tests (§9) cover each
instance type directly, so coverage of `-icells` does not depend on a micro happening to use it.

## 9. Tests (T-1 to T-5)

**T-1 (unchanged without the option).** The existing CTest set passes unchanged, and a unit test
shows that `\$mem u (...)` without `-icells` is still `unresolved_module`, byte for byte.

**T-2 (resolution unit tests, `tests/unit/test_icells.c`).** One test per rule I-1 to I-7, N-1,
V-1 to V-6 on hand-written Verilog through the `et_read` harness: a `$add`, a `$mem` with INIT, a
`$shiftx`, a `$pow`, a `$dffsr`, a `$dlatch`, a bit flip-flop, a `$lut`, a `$sop`; each
asserts the node's type, parameters and connected nets. Error tests assert the exact located
text (width, parameter, port, `$proc`, unknown `$` name, `--lib` refusal). A `(* blackbox *)` stub
named `$add` beside an instance does not change the result.

**T-3 (round trip per cell type).** A write-then-read unit test builds one cell of every
registered type that the writer writes as an instance (the list is derived from the registry
minus `BUILTINS`, minus ports and process, so a newly added type is covered or fails the
test), writes it, reads it with `-icells`, and asserts type, name, parameters and pins. This
is the "every cell type the writer emits as an instance" acceptance, and it fails if a type
gains a parameter the reader cannot read.

**T-4 (the four-level round trip on micros).** `icells-check` per level over a curated micro list
(`tests/icells/micros.txt`: `tests/micro/verilog/micro/*.v` chosen to cover memory, shifts,
`pow`, flip-flops with set and reset, latches, arithmetic and wide muxes, plus the per-cell
designs `tests/icells/*.v`), one CTest per level. The whole `tests/micro/verilog/micro` set
(68 files) is the `sweep` form of the same tool (`--all`); it is not in the default CTest set
(Q9) and is not run through `tools/heavy-run` by this lane.

**T-5 (no silent exception).** A design the tool cannot take at a level must be listed in
`tests/icells/expect.txt` as `<level> <design> <reason>`; a listed design that now passes fails
as stale, one that fails unlisted fails. The tool's last line states `compared N of M`.

## 10. Risks

- Strict widths (V-3) could reject something the writer writes. The writer sizes every port from
  the registry, so it should not; T-3 and T-4 would show it, and the fix would be in the writer's
  width, not a relaxed reader.
- Equivalence of a memory netlist needs the Checker's `memory` lowering; opt-equiv already
  handles `$mem`. If the Checker is `unproven` (size) for a micro, the micro goes in the expect file
  as "unproven" and the structural leg 5 stays; this is stated, not hidden.
- The LPM level has no simulation model for the LPM cells (PHASE5 decision 1): the Checker cuts
  them as hard blocks (outputs shared, inputs compared). So level 4 proves the soft remainder and
  the connections of the LPM cells, not their function, which is what decision 1 allows.

## 11. Out of scope

HDL locations on read-back (5.4); the JSON reader (5.3); `write_verilog` changes (none planned; if
Task 4 finds a width or parameter the writer prints that the registry rejects, that is a writer
fix and is reported); SystemVerilog; any pass; BLIF.

## 12. Open questions (agent defaults taken; Peter may override)

1. **Spelling of the option.** (a) `-icells` and `--icells` both; (b) only `--icells` to match
   the pass's other options; (c) only `-icells`. **Recommend (a).** The task, PHASE5 and Yosys
   say `-icells`; the pass's options are `--`.
2. **Which types may be instantiated.** (a) every registered type that is not a module, port or
   process; (b) only the types the writer emits as instances. **Recommend (a)**: it is Yosys's
   behaviour, it needs no list to keep in step with the writer, and hand-written netlists work.
3. **Widths.** (a) strict error for a `$` instance; (b) the existing resize with a warning.
   **Recommend (a)**: read-back must not silently reshape a netlist.
4. **An unknown `$` name under `--auto-blackbox`.** (a) error; (b) implicit black box.
   **Recommend (a)** (I-5).
5. **Shadowing by stubs.** (a) item 0 wins and the stub is ignored with an info line; (b) refuse
   the stub as a duplicate. **Recommend (a)** (N-1): it needs no writer change and matches the
   writer, which writes no stub for built-in types anyway.
6. **Empty BITS.** (a) read `""` as zero-length BITS under `-icells`; (b) leave the writer's
   spelling unreadable and list it as an exception. **Recommend (a)** (V-5): exact round trip.
7. **Equivalence tool.** (a) `opt_equiv.Checker` on `write_rtlil` of both sides; (b)
   `tools/equiv-check` on `write_blif` of both sides; (c) the `lower-equiv` flow. **Recommend
   (a).** `equiv-check` reads BLIF, and a word-level netlist (`$mem`, `$shiftx`, `$pow`, word
   flip-flops) is not BLIF at the word and LPM levels (`write_blif` refuses or cannot carry
   them), so it could judge only the gate and LUT levels, with a second method for the other two.
   The Checker takes RTLIL at any level, treats gold x as don't care (right for `$shiftx` and
   `$pmux`), is clock aware, runs the memory lowering and cuts hard blocks by name and width (the
   LPM cells). One method at four levels is easier to defend. (`lower-equiv` is `lower`-specific.)
8. **Fixpoint.** (a) generation 2 to 3 text identical plus the instance comparison (5.1's
   rule); (b) generation 1 to 2 identical. **Recommend (a)**: assigns re-elaborate to other word
   cells, so generation 1 and 2 differ in more than open pins.
9. **Size of the CTest set.** (a) curated micro list plus per-cell designs in CTest, all 68 micros
   as an opt-in `sweep`; (b) all micros in CTest. **Recommend (a)**: four Yosys proofs per
   design are minutes per micro on the larger ones; Peter runs the sweep through heavy-run at PR
   time (his rule); this lane does not.
10. **`-icells` with `--lib`.** (a) refuse (I-2); (b) carry an `ICELLS` unit flag so the library
   unit elaborates with it. **Recommend (a)**: (b) adds an AST unit flag for no use today.
11. **Provenance.** Keep as is (task statement): a read-back cell is IMPORTED at the Verilog
    instance line. **Recommend** no change; 5.4 owns locations.
