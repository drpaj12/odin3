# Odin III 1.1.0 release notes

## What it is

Odin III is an MIT-licensed HDL elaboration and front-end synthesis framework for FPGA CAD
research, the successor to Odin (FPL 2005) and Odin II (FCCM 2010). It reads Verilog-2005 and now
SystemVerilog (plus BLIF, Yosys JSON, structural gate-level Verilog and VPR architecture files)
into one hierarchical, provenance-tracked IR, does architecture-driven partial mapping, links ABC
for soft logic, and writes BLIF for VPR, LPM Verilog for an Altera-style flow, structural Verilog
of library gate cells, and dot and JSON for analysis. Every object in the output can be traced to
the HDL text it came from. The manual is `docs/user/` (published at
<https://drpaj12.github.io/odin3/>); the design is `docs/DESIGN.md`. The 1.0 notes are
`docs/RELEASE-NOTES-1.0.md`.

v1.1.0 rolls up everything since v1.0.0. The patch versions v1.0.1 to v1.0.5 were never released on
their own; all of them ship here, so the Yggdrasil III tools (Wyrd III, Loki III, Midgard III,
Bifrost III) build on one core.

## What is new since 1.0.0

- **SystemVerilog** through slang v12.0, vendored in `third_party/slang` (offline build). The C++20
  adapter `adapters/slang` elaborates packages, enums, structs, interfaces and modports,
  `always_ff/comb/latch` and generate, and emits the Odin III elaborated form with source
  locations into the `.sv` text. `read_verilog` routes `.sv`/`.svh` files and a project's
  SYSTEMVERILOG entries to it. The core stays C17; `-DODIN3_WITH_SLANG=OFF` builds without it.
- **Structural Verilog netlists**: `abc --gates L; dfflibmap L; write_verilog` writes the mapped
  design as instances of library gate cells, and `read_verilog` reads it back.
- **Gate mapping** (v1.0.2): `abc --gates L` maps soft logic onto an `.o3lib` gate library,
  `dfflibmap L` maps flip-flops and latches, `write_blif --gates-as-names` makes the result
  checkable with `tools/equiv-check`. `lib/cmos6.o3lib` and `lib/abc/gates.abc` ship with it.
- **Simulation API** (v1.0.3, ABI 5): `odin3_simulation_*` in the C ABI and a `Simulation` class in
  the Python binding step a design one clock at a time; `sim --vectors-in` replays an input
  vector file and `sim --vcd` writes IEEE 1364 VCD waveforms.
- **`unmap`** (v1.0.4): the inverse of `partial_map`; VTR hard cells `adder`, `multiply`,
  `single_port_ram` and `dual_port_ram` come back as `$add`/`$sub`, `$mul` and `$mem` with
  provenance, including regrouped carry chains, split multipliers and sliced or depth-split RAMs.
- **Core options for Loki III** (v1.0.5): `submod -bus BUSKEY` makes vector ports from
  `NAME[BIT]` attributes; `cone_check` and `raise` take `-const PORT=V`.
- **Route retry** (v1.0.1): `odin3-flow` retries the VPR route at fixed wider channel widths on
  tiny devices; `summary.json` gets `route_retry`.
- **Fixes**: `read_verilog --vtr-compat` falls back to `lib/soft_primitives/<name>.v` for an
  instance whose parameters do not fit the registered hard cell (#262); the SystemVerilog adapter
  lowers compound assignments to bit-selects (#264).
- **ABI 6** (was 4 in 1.0.0): ABI 5 adds the ABC engine's `load_genlib`/`get_cells` and the
  simulation calls; ABI 6 adds `odin3_sv_reader_register`/`odin3_sv_read_fn`.

The full list is `CHANGELOG.md`; the per-feature logs are `docs/V1.0.2.md`, `docs/V1.0.4.md`,
`docs/V1.0.5.md` and the build log below.

## Install

From source (Ubuntu 24.04; CMake 3.28 or later for the default SystemVerilog build, or 3.25 with
`-DODIN3_WITH_SLANG=OFF`; Ninja, a C and C++ compiler, `bison`, `flex`, `libreadline-dev`):

```bash
git clone --recursive https://github.com/drpaj12/odin3.git && cd odin3
cmake --preset release && cmake --build --preset release
cmake --install build/release --prefix "$HOME/odin3-1.1.0"
```

The install holds `bin/odin3`, `lib/libodin3.so`, the SystemVerilog adapter library,
`include/odin3/odin3.h` and `share/odin3/` (technology libraries, the flow script and the QoR
tools).

Release assets (GitHub release `v1.1.0`):

- `odin3-1.1.0.tar.gz`: the source with the ABC and Unity submodules, which GitHub's own archives
  leave out (`tools/release/make-tarball`). slang is committed in the tree.
- `odin3-1.1.0-py3-none-linux_x86_64.whl`: the Python wheel (scikit-build-core), bundling
  `libodin3`, the in-process ABC, the `odin3` CLI and the `odin3-flow` command. The tag is
  `linux_x86_64`, not `manylinux`, as for 1.0 (`docs/PHASE7.md` decision 8). Install with
  `pip install odin3-1.1.0-py3-none-linux_x86_64.whl`.
- `SHA256SUMS`: check with `sha256sum -c SHA256SUMS`.

## How it was tested

- The unit, tools and golden CTest suites (Debug, ASan and UBSan) and the CI lint gate pass.
- `tools/release/clean-check` (CTest `release_clean`) on a fresh clone with a minimal environment:
  Release build, `cmake --install`, wheel build and install in a new venv, the installed CLI and
  flow, and every shell block of `docs/user/getting-started.md`.
- SystemVerilog: `test_read_slang`, `cli_slang_flow` (equivalence to the RTL and to Yosys 0.55) and
  the VerilogEval corpus test: all 156 references are pinned, 146 elaborate and map through the
  cmos6 gate flow, 10 are refused with a located, pinned reason (8 latches, 2 explicit casts); a 20-design sample is equivalent
  to Yosys's techmapped output.
- Gate mapping: 439 (generic gates) and 437 (cmos6) of the 539 micros are equivalent to the RTL
  with a re-map leg; none is not equivalent (`docs/V1.0.2.md`).
- `unmap` over the 19 VTR designs of the hard-block sweep: all finish, no group declined
  (`docs/V1.0.4.md`).

## Stability

There is no API or ABI stability promise (`docs/PHASE7.md` decision 4). The C ABI (version 6), the
Python binding, the `.o3lib` format and the JSON keys may change in later releases.

## Known limits

- SystemVerilog covers the synthesizable subset above. Functions and tasks, `foreach`, `break`/
  `continue`/`return`, `case inside`, `unique`/`priority`, intra-assignment timing, delays and
  strengths, `real`/`string`, assertions, `ref` ports, explicit casts and union member access are
  refused with a located `ODIN3_ERR_PARSE`. A mixed Verilog/SystemVerilog read, `--lib`,
  `--parse-only`, `-icells`, `-netlist` and `--vtr-compat` are refused on the SystemVerilog path.
- Inferred latches have no cell in `cmos6`; eight VerilogEval references are refused for that.
- The wheel is tagged `linux_x86_64` (no `manylinux`).
- Gate mapping sweep: 82 micros are not checkable because `proc`, `opt` or `lower` refuse them;
  a few are unproven within the equivalence time limit (`docs/V1.0.2.md`).
- A depth-split RAM with two read ports comes back from `unmap` as one `$mem` per read port
  (`docs/V1.0.4.md`, decision 19).
- The 1.0 known gaps still apply: the `k4_N4_90nm` ABC time limit on `mkDelayWorker32B`, the
  dead-adder warning on some EArch designs, `fcheck` not simulating latch designs, and the ABI gaps
  of `docs/RE-ARCHITECTURE.md` section 5.
- Not in 1.1.0: VHDL (ADR D11), SystemVerilog `--lib` and mixed-language elaboration, function and
  task emission, interface-port pass-through, assertions and classes.

## Build log


Status: built on branch `feat/sv-adapter` (2026-10-23), from ADR D13 and DESIGN §4.2/§12.1. This
is the release log: what was built, the tests that prove it, and the agent defaults or deviations
taken along the way (Peter may overrule any of them).

## What was built

- **Vendored slang**: `third_party/slang` is slang v12.0 (`545f88b2`, the commit sv-elab
  `8911a6ca` pins) with fmt 12.2.0, boost.regex boost-1.91.0 and tomlplusplus v3.4.0, committed
  as source (`VENDORING.md`). `BUILDING.md` records the exact build: slang's three FetchContent
  dependencies are replaced by `FETCHCONTENT_SOURCE_DIR_*` local copies, mimalloc/tools/tests are
  off, so configure and build need no network. Odin III's `ODIN3_WITH_SLANG` (default ON) adds
  it and builds the static `slang_slang`; none of its flags reach Odin III targets.
- **Adapter** `adapters/slang`: C++20, links slang, walks the elaborated AST and emits the
  Odin III elaborated form (EL-4) through `odin3_ast_*`, then drives `odin3_ast_elaborate`.
  It exports exactly one C function, `odin3_read_slang`, in `libodin3_slang.so`; the core stays
  C17. Packages, imports, enum values, `$bits` and constant expressions fold to `NUMBER`/
  `STRING` leaves; packed and unpacked structs become one packed vector with member accesses as
  selects; interface instances flatten to `<instance>.<signal>` nets and interface ports to
  `<port>.<signal>` module ports (modport order and directions); `always_ff/comb/latch` become
  ALWAYS with those subs; `always @(...)`/`@*` become ALWAYS over `TIMING_STMT[EVENT_CONTROL,S]`;
  generate is already expanded by slang and its scope names flatten into net names; block and
  loop variables are hoisted. Source locations are copied verbatim into the design's source
  manager (per-file line tables), so IR `SOURCE` records point at the `.sv` text.
- **Wiring**: ABI v6 adds `odin3_sv_reader_register`/`odin3_sv_read_fn`; the CLI registers the
  adapter at start-up; `read_verilog` routes a project's SYSTEMVERILOG design files, or direct
  `.sv`/`.svh` paths, to it. A mixed Verilog/SystemVerilog read, `--lib` and `--parse-only` are
  refused for SystemVerilog in v1.1.0, as are `-icells`, `-netlist` and `--vtr-compat`; a
  project's include directories and defines reach slang's preprocessor
  (`odin3_sv_options`). The build is unchanged for hosts with
  `-DODIN3_WITH_SLANG=OFF` (the core and its tests stay C17, `read_verilog` reports no reader).
- **Structural Verilog netlists**: the existing writer already writes library cell instances by
  type and pin name, so `proc; opt; lower; abc --gates L; dfflibmap L; write_verilog` writes the
  mapped netlist as `BUF`/`INV`/`NAND2`/`NOR2`/`DFF` cell instances with netlist-visible names.
  The one reader-side change needed for the roundtrip: a registered **bit-granularity** cell
  type now binds to a Verilog instance of its name (`src/frontends/verilog/elab1_lookup.c`,
  `resolve_outside`), where only hard and black-box types bound before.

## Tests and evidence

- `test_read_slang` (unit; links `libodin3` and `libodin3_slang.so`): sv_package (package,
  wildcard import, always_ff/case), sv_types.sv (enum, packed struct, memory, always_comb/ff/
  latch) and sv_iface.sv (interface instance and modport port): counts, ALWAYS subs, flattened
  names, no GEN_BLOCK, and AST-2's source-range and provenance invariants over every node.
- `cli_slang_flow` (end-to-end): five NVIDIA verilog-eval references (committed under
  `tests/unit/data/slang/verilog-eval`, MIT), the two fixtures and the sv_package golden project
  through `read_verilog; proc; opt; lower; abc --gates cmos6; dfflibmap cmos6; write_verilog` and
  `write_blif --gates-as-names`; the structural Verilog is read back and `tools/equiv-check`
  proves both BLIFs equivalent. With Yosys on PATH, each reference's RTL BLIF is also proven
  equivalent to Yosys 0.55's `read_verilog -sv; proc; opt; techmap; opt; write_blif`.
  `tests/golden/slang/alwaysblock2.blif` is the gate golden.
- `test_read_verilog` gains the bit-cell-type binding case.

## Agent defaults and deviations (Peter may overrule)

1. **Source of the vendored bytes**: the brief named sv-elab `8911a6ca`; that commit's
   `third_party/slang` submodule is slang v12.0 `545f88b2`, and the populated Yosys submodule on
   disk is that same commit, so the tree is slang v12.0 from `external/yosys/libs/slang`. The
   sv-elab checkout's own submodule was empty.
2. **Dependencies vendored**: fmt/boost.regex/tomlplusplus are committed and slang's fetch
   replaced by source dirs, so the build is offline (the brief asked to report network needs).
   mimalloc is off; it is an optional allocator.
3. **Specialization names**: the top keeps its definition name; other distinct instance bodies
   take the definition name with `$2`, `$3`, … when taken (not EL-9's `base$P=v` value-keyed
   names, which are stage 1's; the adapter only needs unique deterministic names). Bodies of one
   definition with equal types share a MODULE.
4. **Parameter value widths**: a parameter's NUMBER carries the final value's width, not EL-4's
   0-for-still-unsized, because slang's `SVInt` does not keep `is_unsized`. Values are exact;
   only extension in a wider context could differ.
5. **Unpacked structs** are flattened to a packed vector like packed ones (all member accesses
   go through the adapter's offsets, so the model is self-consistent). A union is declared as one
   packed vector as well, but a union member access is refused (a union has no bit layout to
   select from).
6. **Refused for now** (a located `ODIN3_ERR_PARSE`, never a silent drop): functions/tasks and
   their calls, `foreach`/`do while`/`forever`, `break`/`continue`/`return`, `case inside`,
   `unique`/`priority` checks, intra-assignment timing, delays/strength, real/realtime/string
   variables, assertions/processes/final, `ref` ports, interface-port pass-through, `--auto-blackbox`,
   `--lib`, `--parse-only` and mixed-language reads. `-icells`/`-netlist` do not apply on the SV
   path.
7. **Reader-side change**: accepting bit-granularity cell types in `resolve_outside`. Without it
   `write_verilog`'s gate-cell netlists would not read back; the roundtrip is v1.1.0's stated
   goal. Existing designs are unaffected unless a `read_techlib` registered a gate of that name.
8. The `read_verilog` row in `docs/PASSES.md` now describes the SV routing; no new pass name was
   added (the adapter is a reader seam, not a pass). The writer row records the gate-cell
   structural Verilog path.

## Not in v1.1.0

VHDL (still deferred), `--lib`/`--parse-only` SystemVerilog reads, mixed-language elaboration,
function/task emission, interface-port pass-through, assertions and classes. The slang adapter
answers the synthesizable subset above; each refusal is a located error.
