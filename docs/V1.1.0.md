# v1.1.0 — SystemVerilog via the vendored slang adapter, structural Verilog netlists

Status: built on branch `feat/sv-adapter` (2026-10-23), from ADR D12 and DESIGN §4.2/§12.1. This
is the release log: what was built, the tests that prove it, and the agent defaults or deviations
taken along the way (Peter may overrule any of them).

## What was built

- **Vendored slang**: `third_party/slang` is slang v12.0 (`545f88b2`, the commit sv-elab
  `8911a6ca` pins) with fmt 12.2.0, boost.regex boost-1.91.0 and tomlplusplus v3.4.0, committed
  as source (`VENDORING.md`). `BUILDING.md` records the exact build: slang's three FetchContent
  dependencies are replaced by `FETCHCONTENT_SOURCE_DIR_*` local copies, mimalloc/tools/tests are
  off, so configure and build need no network. Odin III's `ODIN3_WITH_SLANG` (default ON) adds
  it and builds the static `slang_slang`; none of its flags reach Odin III targets.
- **Adapter** `adapters/slang`: C++20, links slang, walks the elaborated AST and emits the
  Odin III elaborated form (EL-4) through `odin3_ast_*`, then drives `odin3_ast_elaborate`.
  It exports exactly one C function, `odin3_read_slang`, in `libodin3_slang.so`; the core stays
  C17. Packages, imports, enum values, `$bits` and constant expressions fold to `NUMBER`/
  `STRING` leaves; packed and unpacked structs become one packed vector with member accesses as
  selects; interface instances flatten to `<instance>.<signal>` nets and interface ports to
  `<port>.<signal>` module ports (modport order and directions); `always_ff/comb/latch` become
  ALWAYS with those subs; `always @(...)`/`@*` become ALWAYS over `TIMING_STMT[EVENT_CONTROL,S]`;
  generate is already expanded by slang and its scope names flatten into net names; block and
  loop variables are hoisted. Source locations are copied verbatim into the design's source
  manager (per-file line tables), so IR `SOURCE` records point at the `.sv` text.
- **Wiring**: ABI v6 adds `odin3_sv_reader_register`/`odin3_sv_read_fn`; the CLI registers the
  adapter at start-up; `read_verilog` routes a project's SYSTEMVERILOG design files, or direct
  `.sv`/`.svh` paths, to it. A mixed Verilog/SystemVerilog read, `--lib` and `--parse-only` are
  refused for SystemVerilog in v1.1.0, as are `-icells`, `-netlist` and `--vtr-compat`; a
  project's include directories and defines reach slang's preprocessor
  (`odin3_sv_options`). The build is unchanged for hosts with
  `-DODIN3_WITH_SLANG=OFF` (the core and its tests stay C17, `read_verilog` reports no reader).
- **Structural Verilog netlists**: the existing writer already writes library cell instances by
  type and pin name, so `proc; opt; lower; abc --gates L; dfflibmap L; write_verilog` writes the
  mapped netlist as `BUF`/`INV`/`NAND2`/`NOR2`/`DFF` cell instances with netlist-visible names.
  The one reader-side change needed for the roundtrip: a registered **bit-granularity** cell
  type now binds to a Verilog instance of its name (`src/frontends/verilog/elab1_lookup.c`,
  `resolve_outside`), where only hard and black-box types bound before.

## Tests and evidence

- `test_read_slang` (unit; links `libodin3` and `libodin3_slang.so`): sv_package (package,
  wildcard import, always_ff/case), sv_types.sv (enum, packed struct, memory, always_comb/ff/
  latch) and sv_iface.sv (interface instance and modport port): counts, ALWAYS subs, flattened
  names, no GEN_BLOCK, and AST-2's source-range and provenance invariants over every node.
- `cli_slang_flow` (end-to-end): five NVIDIA verilog-eval references (committed under
  `tests/unit/data/slang/verilog-eval`, MIT), the two fixtures and the sv_package golden project
  through `read_verilog; proc; opt; lower; abc --gates cmos6; dfflibmap cmos6; write_verilog` and
  `write_blif --gates-as-names`; the structural Verilog is read back and `tools/equiv-check`
  proves both BLIFs equivalent. With Yosys on PATH, each reference's RTL BLIF is also proven
  equivalent to Yosys 0.55's `read_verilog -sv; proc; opt; techmap; opt; write_blif`.
  `tests/golden/slang/alwaysblock2.blif` is the gate golden.
- `test_read_verilog` gains the bit-cell-type binding case.

## Agent defaults and deviations (Peter may overrule)

1. **Source of the vendored bytes**: the brief named sv-elab `8911a6ca`; that commit's
   `third_party/slang` submodule is slang v12.0 `545f88b2`, and the populated Yosys submodule on
   disk is that same commit, so the tree is slang v12.0 from `external/yosys/libs/slang`. The
   sv-elab checkout's own submodule was empty.
2. **Dependencies vendored**: fmt/boost.regex/tomlplusplus are committed and slang's fetch
   replaced by source dirs, so the build is offline (the brief asked to report network needs).
   mimalloc is off; it is an optional allocator.
3. **Specialization names**: the top keeps its definition name; other distinct instance bodies
   take the definition name with `$2`, `$3`, … when taken (not EL-9's `base$P=v` value-keyed
   names, which are stage 1's; the adapter only needs unique deterministic names). Bodies of one
   definition with equal types share a MODULE.
4. **Parameter value widths**: a parameter's NUMBER carries the final value's width, not EL-4's
   0-for-still-unsized, because slang's `SVInt` does not keep `is_unsized`. Values are exact;
   only extension in a wider context could differ.
5. **Unpacked structs/unions** are flattened to a packed vector like packed ones (all member
   accesses go through the adapter's offsets, so the model is self-consistent).
6. **Refused for now** (a located `ODIN3_ERR_PARSE`, never a silent drop): functions/tasks and
   their calls, `foreach`/`do while`/`forever`, `break`/`continue`/`return`, `case inside`,
   `unique`/`priority` checks, intra-assignment timing, delays/strength, real/realtime/string
   variables, assertions/processes/final, `ref` ports, interface-port pass-through, `--auto-blackbox`,
   `--lib`, `--parse-only` and mixed-language reads. `-icells`/`-netlist` do not apply on the SV
   path.
7. **Reader-side change**: accepting bit-granularity cell types in `resolve_outside`. Without it
   `write_verilog`'s gate-cell netlists would not read back; the roundtrip is v1.1.0's stated
   goal. Existing designs are unaffected unless a `read_techlib` registered a gate of that name.
8. The `read_verilog` row in `docs/PASSES.md` now describes the SV routing; no new pass name was
   added (the adapter is a reader seam, not a pass). The writer row records the gate-cell
   structural Verilog path.

## Not in v1.1.0

VHDL (still deferred), `--lib`/`--parse-only` SystemVerilog reads, mixed-language elaboration,
function/task emission, interface-port pass-through, assertions and classes. The slang adapter
answers the synthesizable subset above; each refusal is a located error.
