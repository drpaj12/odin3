## The activity pass

Method in one paragraph: each net is the pair of its values in two consecutive cycles, stationary, with joint
distribution set by its static probability `P1` and transition density `D`. A node takes its inputs as independent and
gets `P1` and `D` exactly from its function table (up to 16 inputs, `O(k 2^k)`), simultaneous switching included.
Flip-flops outside feedback copy the statistics of their data input; inside a feedback component `P1` is iterated to a
fixpoint (Aitken extrapolation, damping) and `D` is `P(next != state)` with the state held at 0 and 1. No vectors, no
random numbers.

Options (`docs/user/activity.md`): `--pi-prob`, `--pi-density`, `--pi-file`, `--vcd` (inputs measured from a
waveform), `--clock`, `--ff-start`, `--tol`, `--max-iter`, `--exact`, `--opaque-prob/-density/-type`, `--out F.act`
(VPR activity file under the `write_blif --vtr` names), `--name-style`, `--json F` (schema `odin3-activity` 1),
`--no-attrs`. Python `Design.activity`.

Comparison (51 designs of `wyrd power run`, `tools/activity/act_check.py`):

| Measure | Result |
|---|---|
| vs ACE 2.0, same netlist and inputs, ACE configuration (`--opaque-type adder --ff-start 0`) | P1 MAE 0.025 (median 0.011); density MAE 0.054 (median 0.038) |
| vs Monte Carlo of the same model, density MAE (34 designs) | 0.008 vs 0.096 for ACE 2.0 on 21 combinational; 0.024 vs 0.055 on 13 sequential |
| VPR total power, `activity` file over ACE 2.0 file | geomean 1.14 over 44 designs (range 1.02 to 1.42) |
| Run time and memory, 7 designs of 7000 to 108000 nets | `activity` 12 to 520 ms, 18 to 93 MB; ACE 2.0 2.7 to 40 s, 55 to 288 MB |

Against simulation (testbench through the netlist; mixed result, see the reconvergence caveat):

| Design | VPR power, simulation (mW) | `activity`, inputs measured | `activity`, default inputs | ACE 2.0 |
|---|---|---|---|---|
| mmuart | 2.07 | 2.36 | 2.60 | 3.06 |
| wb_lcd | 5.21 | 6.44 | 8.34 | 7.89 |
| verilog_cordic_core | 28.97 | 42.28 | 34.59 | 19.36 |

Caveat: inputs of a node are treated as independent, so reconvergent fanout is the main source of error; reachable
states a testbench never leaves (170 of 414 nets of mmuart never change) are invisible to the analytic model.

## `odin3-prov-steps --activity`

`odin3-prov-steps FLOW_DIR --activity F.act` (`F.act` from `odin3 activity --name-style hash --out F.act` on the same
BLIF) adds `attrs.act_p1`, `attrs.act_density`, `attrs.act_source` (`odin3-vectorless` or `--activity-source LABEL`) to
the `luts` objects. No schema change; Python `prov_steps.fpga_steps(..., activity=...)`.

## `sim_tb` hard-cell fix and the wb_lcd case

A tech-library hard cell with an unknown input bit made every output x in 4-state mode; the generic wrapper now tries
every 0/1 completion of up to 6 unknown input bits and keeps an output bit known when all completions agree. Fixes
mmuart, verilog_cordic_core and `adder` carry chains on a `hardmap`'d netlist. Known case: wb_lcd on an `abc`-mapped
netlist still fails in the default 4-state mode, because `abc` drops the RTL `if (x)` select (`lower --keep-sel`) and the
LUT cover propagates x; run it with `sim_tb --2state` (307 checks pass).

## Known gaps
- Spatial correlation, reachable states, glitches, multi-clock domains (`docs/user/activity.md`, "What it does not know").
- Analytic engine only; a `sim:N` engine behind the same options is left open.
- Feedback components of wb_lcd, sdr_ctrl and vga_lcd do not reach the tolerance in `--max-iter` sweeps (WARNING, `converged` false).
- On simulation-referenced designs the power ratios are 1.1 to 1.5 (see table); the density bias is positive.

## Upgrade notes
- Version macros 1.6.0; ABI 7 unchanged. A new module attribute family `odin3:activity_*` is written by the `activity`
  pass only (`--no-attrs` to omit); other flows are unchanged.
- `sim_tb` 4-state results change for netlists with hard cells: outputs that were x are now known where the completions agree.
