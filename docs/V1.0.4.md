# Odin III v1.0.4: unmap

Spec: `docs/specs/2026-10-21-unmap-design.md`. Plan: `docs/plans/2026-10-21-unmap-plan.md`. Purpose:
Loki III starts from VTR netlists whose arithmetic and memories are hard cells; `unmap` is the
inverse of `partial_map` and gives it word-level cells with provenance (exactly or not at all).
Core features after v1.0 are patch releases (v1.0.1 route retry, v1.0.2 gate mapping, v1.0.3 S1
simulation API, v1.0.4 `unmap`); tags only on Peter's go.

## Decisions log

Peter, 2026-10-21: all good (spec section 10); the recommendations below are the decisions.

1. (Peter) `unmap` is Phase 7 item 7.7 "unmap, for Loki"; it needs no core change.
2. (Peter) A chain with a real carry-in (a user `adder` whose first `cin` is a signal) is declined in
   v1 (`adder:cin_signal`).
3. (Peter) The read-enable hold logic of `partial_map` R-10 stays as `$mux` and `$dff` cells next to
   the recovered `$mem`.
4. (Peter) Signed `$add`/`$sub` recovery rests on repeated top nets; a mixed case comes back unsigned
   with the repeated bits written out.
5. (Peter) A split that `partial_map` reduced to `m00` comes back as a `W x W` `$mul` (M-7).
6. (Peter) `--no-regroup` is the only option.
7. (Peter) Depth merge (R-8) is in v1, as the last tasks (15, 16), isolated in `ram_depth.c`.

Agent defaults taken during the implementation (Peter may override):

8. A subtraction chain whose last `cout` is observed is declined `adder:cout_sub` (the carry-out of
   `a - b` is the inverse of the borrow bit, not `Y[n]`); an observed last `cout` also keeps every
   stage (no trailing stage is dropped, so no observed net loses its driver) and the chain is
   recovered unsigned with the carry as the top result bit.
9. `cin_carry` is also the reason when a stage's carry-in is the top result bit of a chain `unmap` has
   recovered already (a node with the `unmap` attribute), so a second run gives the same note
   (S-7).
10. A write enable that is constant 0 through an `$and` chain (the dead second write port of a depth
    split, `we2` on gnd) is no write port; an open or pad write enable is no write port either
    (R-2 says "not gnd").
11. `unmap_origin` is also set on a recovered cell made of one hard cell (its own record).
12. A candidate set (R-6, R-7) marks every cell of the set with `unmap_cand`; the R-7 set (equal
    write nets, no common origin) says `write` in its INFO line. Cells of a R-6 candidate set do not
    take part in R-7.
13. R-8 handles leaves with one write port and a read side of `$mux`/`$dff` glue; a read-only depth
    split (a ROM) and leaves whose enable is not an `$and` (after `lower`) are left as they are with
    no note. A mismatch in the glue gives the note `ram:depth` and one warning.
14. The P-4 line counts `multiply` as the cells seen, `$mul` as the cells left after regroup and
    `regrouped` as the multiplies absorbed by merges (4 multiplies into one `$mul`: `1 $mul (3
    regrouped)`); no line when no hard cell was seen.
15. The command-line tests are `tests/unmap/run.sh` (cases `rtl`, `blif`, `golden`), not cases of
    `tests/cli/test_cli.sh`: parallel lanes edit that shared file.
16. Test scripts note `hardmap; opt_clean; unmap` for the low-product-only multiplier (the dead pieces
    of the split read their inputs, so `unmap` alone keeps them), and `--no-regroup` for the RAM
    micros that are cut into one-bit slices. For the 40x40 family the regroup quality depends on
    `opt_clean` running before `unmap`: a split cut down by dead upper bits is only
    recognised once the dead pieces are gone.
17. R-8 does not check that the glue cells carry the provenance record of `unmap_origin` (spec R-8
    asks for it). The structure check (write-enable chain, select registers, mux trees, one reader
    per net inside the structure) is exact, so a same-structure network from another origin is the
    same memory in function; the leaves already share the origin.
18. R-8 refuses (`ram:depth`) when the write enables of the data bits of a leaf differ, and when a
    select register is not a 1-bit rising-edge `$dff` driving the mux select from Q bit 0. The width
    slices of R-6 are ordered by the `b<n>` role of `hardmap` when every slice has one, else by
    node ID.
19. Known limit: a depth split with two read ports (`tests/unmap/ram_deep_2r.v`) comes back as one
    `$mem` per read port, each depth-merged; the replicas have their own write-enable trees, so R-7
    cannot pair the leaves, and R-7 does not run again on the R-8 results. The netlist is
    equivalent (equiv-check on the micro); `tests/unmap/expect.txt` lists the count difference.
