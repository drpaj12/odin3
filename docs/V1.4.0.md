# Odin III 1.4.0 release notes

Status: on branch `feat/v1.4-silicon`, not merged, not tagged. The tag and release are the controller's.

## What it is

v1.4.0 is a minor release on v1.3.0. The C ABI stays 7. It adds three things that belong together:
the silicon flow, a way to describe flows in the project file, and provenance step files that let a tool
read provenance at every stage of a run. Spec: `docs/specs/2026-11-03-v1.4-silicon-provenance.md`.

## What is new

1. **Silicon flow** (`tools/silicon`, `odin3-flow --target silicon`; manual `docs/user/silicon-flow.md`).
   Odin III maps a design onto SKY130 `sky130_fd_sc_hd` cells with `abc --gates` and `dfflibmap`;
   OpenROAD (driven by `tools/silicon/openroad_flow.tcl`), KLayout, Magic and Netgen take it to a routed GDS,
   a transistor netlist and an LVS verdict; a name-free join takes the extracted cells back to the placed
   cells and the HDL. There is no Yosys in the path. The library `lib/sky130hd.o3lib` is data generated
   from Liberty outside the core (gatemap G-1). The tools are optional, user-space installs; Odin III builds and
   its tests pass without them, and the silicon tests skip.
2. **Flows in the project file** (`docs/user/project-flows.md`). `schema 2`, `tool`, `flowdef`, `step`,
   `provlink`, `flow-var`. The core parses, validates and dumps; it never runs a step. Schema 1 files are
   unchanged. New error kind `unsupported_schema`.
3. **Provenance step files** (`docs/user/provenance-files.md`, `docs/schemas/`). A header and a JSON Lines
   objects file per step, an index with sha256 values, link kinds and confidence, for the silicon flow and
   for `odin3-flow --prov`. `tools/silicon/schema_check.py` validates a run. Loki reads them (Loki
   `prov_steps.py`).

## Compatibility

| File | Reader | Result |
|---|---|---|
| schema 1 project (no `schema`) | 1.4 | loads, dump byte-identical to 1.3 |
| schema 2 project | 1.4 | loads, dump adds `schema`, `tools`, `flows` |
| schema 2 project | 1.3 | `unknown_key` at line 1 |
| `schema 3` | 1.4 | `unsupported_schema` |

## Limits

Two small designs only. OpenROAD is pinned to the March 2022 conda build; upgrading it is a later change.
Device-level (transistor) objects are not modelled: the `extracted` stage holds cells. No `restructure`, no
setup repair, power grid met1 rails and met4 straps only. See the manual for the full list.
