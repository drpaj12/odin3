# Odin III v1.0.2: gate mapping

Spec: `docs/specs/2026-10-21-gatemap-design.md` (decisions G-1 to G-9). Plan:
`docs/plans/2026-10-21-gatemap-plan.md`. Post-v1.0 core feature, released as a patch version
(CLAUDE.md, "Where things are going"). Peter reviews the mapping algorithms (`abc --gates`,
`dfflibmap`) before they merge (G-9).

**Goal.** `abc --gates L` maps soft logic onto the gate cells of an `.o3lib` library `L`,
`dfflibmap L` maps the bit flip-flops and latches onto its state cells, the result stays in the
provenance IR and writes as structural Verilog, and `write_blif --gates-as-names` plus
`tools/equiv-check` prove it equivalent to the RTL.

## Decisions log

All entries are agent defaults (autonomy rule, CLAUDE.md 11) that Peter may override. Numbers
GM-1 to GM-14 are those of the plan's "Spec gaps and agent defaults" table; GM-15 and later were
decided in review rounds.

1. (Agent default, gatemap, GM-1) `Mio_LibraryRead(NULL, ...)` (spec 4.2) crashes: with a buffer it
   appends `.genlib` to the NULL file name. Review round: it also dereferences a library it failed
   to read (mioRead.c:96). The adapter reads the text with `Mio_LibraryReadBuffer`, names the
   library `odin3.genlib` with `Mio_LibrarySetName` and installs it with `Mio_UpdateGenlib`, the
   pattern ABC uses itself, on a writable copy of the text.
2. (Agent default, gatemap, GM-2) With `PIN *` Mio numbers pins by first appearance in the formula
   and drops an unused input, so the genlib has one `PIN <port>` line per input in port order, and
   a cell whose function ignores an input is skipped with a note. Spec section 3 is corrected
   accordingly.
3. (Agent default, gatemap, GM-3) The core derives the genlib text (`src/passes/abc/genlib.c`,
   ISOP from `odin3_blif_isop_set`), so it can be hashed and golden-tested; `load_genlib` takes the
   finished text.
4. (Agent default, gatemap, GM-4) `--gates` always uses the linked engine and the in-memory
   exchange; `ODIN3_ABC_EXCHANGE` is ignored and `--via-blif` with `--gates` is refused. A user
   `--script` with `--gates` runs in-process, without subprocess isolation.
5. (Agent default, gatemap, GM-5) The genlib always ends with `GATE $odin3_const0 0 Y=CONST0;` and
   `GATE $odin3_const1 0 Y=CONST1;`, so ABC can map constant nodes; library TIE cells never enter
   the genlib and the splice uses them.
6. (Agent default, gatemap, GM-6) Under `--gates` an in-domain flip-flop with INIT 1 is a cut point
   (the init-1 restore flips LUT tables, which a library gate cannot do).
7. (Agent default, gatemap, GM-7) `.o3lib` `seq` has no asynchronous set or reset, so cmos6's
   DFFSR is a `blackbox` cell with a comment giving its function; `dfflibmap` never chooses it.
8. (Agent default, gatemap, GM-8) A library state cell with init x keeps no INIT 0 or 1;
   `dfflibmap` warns with the count, and the sweeps list the micros whose register then differs
   under equiv-check with the reason `init-lost`.
9. (Agent default, gatemap, GM-9) cmos6 has no latch, so `dfflibmap cmos6` refuses `$_DLATCH_*`;
   the sweeps front with `read_verilog --nolatches`.
10. (Agent default, gatemap, GM-10) The RTL reference of the equivalence check is
    `write_blif --gates-as-names` right after `lower`; the option writes every gate-like cell,
    built-in or library, as `.names`, and library state cells as `.latch`.
11. (Agent default, gatemap, GM-11) With `--gates` only `--script` overrides the default script
    `builtin:lib/abc/gates.abc`; a project or `--abc-script` LUT script is not used and an INFO
    line says so.
12. (Agent default, gatemap, GM-12) The log has no NOTE level: spec "NOTE" lines are INFO lines
    whose text starts `abc: note:`.
13. (Agent default, gatemap, GM-13) cmos6 areas follow Yosys's `cmos_cells.lib` (BUF 6, INV 3,
    NAND2 4, NOR2 4, DFF 18, DFFSR 18), so `map -a` matches Gate-Breaker's flow; DFFSR is
    active-high set and reset, S wins.
14. (Agent default, gatemap, GM-14) `dfflibmap` keeps the state cell's attributes (every attribute
    is copied, as `flatten` does) for the provenance-to-HDL and graph goals; a shared clock inverter
    takes a DERIVED record whose parents are the records of every flip-flop that uses it.
15. (Agent default, gatemap, review) Strict genlib text check in the adapter: only the canonical
    subset the core writes is accepted (GATE with area and `Y=formula;`, one PIN line per formula
    name with phase and six numbers, at most 6 pins, names and numbers bounded, no comments, no
    LATCH, no duplicate gate, no pin the formula does not name). ABC's own parser asserts or
    crashes on other input. The failure text is `ABC cannot read the gate library (line N:
    reason)`.
16. (Agent default, gatemap, review) `load_genlib` is refused once any command has reached the
    engine's guard (`load the gate library before the mapping script`), so a library cannot change
    under a network that was already mapped.
17. (Agent default, gatemap, review) A TIE cell is a constant kind of its own in the region
    (`ODIN3_ABC_TK_TIE`, value from the cell's function) with a literal fallback, not a
    `const_value` hook on the library cell type, which would change every pass's view of TIE
    cells.
18. (Agent default, gatemap, review) `abc: final: depth` and the run info count library gate cells
    (those eligible by `odin3_gate_truth_eligible`) as levels, as well as `$lut`; built-in bit
    gates are not levels.
19. (Agent default, gatemap, review) The splice's `$_CONST0_` and `$_CONST1_` cells and nets carry
    the run's coarse provenance record (also in LUT mode), so no gate or constant lacks a SRC.
20. (Agent default, gatemap, review) New skip reason `ODIN3_LIBCELL_CELL_NAME` ("its name is not a
    genlib name"): a gate cell whose name is not `[A-Za-z_][A-Za-z0-9_]*` or is `CONST0` or
    `CONST1` is skipped with a note. The run's flag is `gates_mode` (`run->gates` is the cell-type
    table). The adapter reads numbers as `digits[.digits]` only.
21. (Agent default, gatemap, review) Script checker: `map` and `&nf` options get per-letter value
    ranges and crash refusals (map `-A`/`-B`, `&nf -k` without XOR and MUX, `&nf -R/-E/-Q` and
    `map -M/-F` in 0..1000), and after a gate mapping only commands that keep the gate network are
    accepted (`&put` after `&nf`, the LUT network commands `mfs`, `mfs2`, `lutpack` and `&mfs` are
    refused with the after-mapping message).
22. (Agent default, gatemap, review) `$dff` and the other word flip-flops and latches (flags 0) are
    refused by name in `dfflibmap`, besides the flag rule that covers `$_FF_` and the `$_DFFE_*` and
    `$_SDFF_*` families.
23. (Agent default, gatemap, Task 14) The re-map leg reads the gate netlist as BLIF (`write_blif`
    without `--gates-as-names`, library cells as `.subckt`) and not as written Verilog:
    `read_verilog -netlist` of `gates.v` stops with `unresolved_module: module 'NAND2' is not
    defined`, because outside a module only hard and black-box cell types resolve. The plan and
    spec 9 name `read_verilog`; a core change to resolve library gate cells in Verilog is left to
    Peter (open issue below).
24. (Agent default, gatemap, Task 14) `gatemap-run` maps an equiv-check error (exit 2, e.g. a
    flip-flop clocked by an internal net) to the outcome `error` with exit 1 (listable), not to the
    odin3-failure exit 3, so the cmos6 falling-edge case can be an expected failure; exit 3 is for
    odin3 itself failing.
25. (Agent default, gatemap, Task 14) The smoke tests are `gatemap_smoke_generic` and
    `gatemap_smoke_cmos6` (one elab-sweep each over the four micros with `--remap`), because
    `gatemap-run` takes one design.
26. (Agent default, gatemap, Task 15) The micro sweeps are registered inside the Yosys-gated block
    of `CMakeLists.txt` so they reuse the lower sweeps' expect-fail lists; they do not use Yosys.
27. (Agent default, gatemap, Task 14) The sweep flow is the plan's script with three additions found
    by the first sweeps: `lower --neg-edge keep` (so generic_gates maps falling-edge registers to
    DFFN and the reference BLIF has no clock inverter), `lib/vtr.o3lib` read first (designs that
    instantiate `single_port_ram`, `dual_port_ram` or `multiply` need the hard-block types; they stay
    cut points in `abc` and `dfflibmap`), and equiv-check run with `--blackbox
    adder,multiply,single_port_ram,dual_port_ram` after `gatemap-run` writes each hard block as
    `.gate` (the plain BLIF writes hard blocks as `.subckt` with no `.model`, which equiv-check
    refuses).
28. (Agent default, gatemap, Task 14) When equiv-check refuses an undriven net that reaches an
    output of the RTL itself, `gatemap-run` repeats the check with `--allow-undriven` (both netlists
    then read the net as 0; the gate netlist keeps the net undriven). The re-map leg runs equiv-check
    with `--timeout 1200` (a near-limit design passed or timed out depending on machine load).
29. (Agent default, gatemap, Task 14) Reasons in the expect-fail lists beyond the plan's set
    (`front`, `init-lost`, `no-latch-cell`, `unproven`, `multiclock`): `negedge-inverter` (named in
    the brief) and `level-latch` (equiv-check rejects a level-sensitive latch of a RAM model). No micro
    needed `init-lost`. `front` is the micros that proc, opt or lower refuse; the sweeps read those
    lists (`tests/proc`, `tests/opt`, `tests/lower` incl. `run_micro_expect_fail.txt`).
30. (Agent default, gatemap, Task 14) An equiv-check killed by the 2G child cap (LU64PEEng,
    arm_core) is `unproven`, listed with the needle `killed by the memory cap`; uncapped, LU64PEEng
    times out after 600 s.

## Exit evidence

(`tools/heavy-run`, label `sweep`, smallest micro first), 2026-10-22, 539 micros in `tests/micro`
per library. Each micro: `read_techlib vtr; read_techlib L; read_verilog --nolatches; hierarchy;
proc; opt; lower --neg-edge keep; write_blif --gates-as-names rtl.blif; abc --gates L; dfflibmap
L; write_blif --gates-as-names gates.blif`, `equiv-check rtl.blif gates.blif`, only library cells,
constants, ports and hard blocks in the result, every library cell with a SRC, then the re-map leg
(gate netlist read back as BLIF, mapped again, equivalent to the first gate netlist).

Floors (`--min-compared-total`, measured less 5 percent): 417 and 415.

What the table does not prove (the "big benchmarks untested" policy: equivalence is for the micros
and small designs, big ones only need to get through the flow):
- The two 2G-cap entries (LU64PEEng, arm_core) are cap-bound: equiv-check was killed at the child
  cap, so there is no verdict. They are not proven.
- About 20 big designs per library have no equivalence proof (generic_gates: 11 unproven, 6
  multiclock, 1 level-latch; cmos6: 10, 6, 1), and the 3 cmos6 `negedge-inverter` designs have none
  either. For these the evidence is only that the gate flow completes and the cell, SRC and re-map
  checks of the other rows hold where they run.

Timing note: the `unproven` entries of `tests/gatemap/expect_fail_<lib>.txt` that sit near the 600 s
limit (bgm, stereovision1, raygentop and the dsec timeouts) flip between `timed out after 600
seconds` and `UNDECIDED` under load, so they share the needle `gatemap-run: unproven`. A faster
machine can prove one of them: the sweep then reports XPASS, and the fix is to delete that line
from the list, not to change the tool.
