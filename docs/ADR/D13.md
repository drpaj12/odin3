# D13: v1.1.0 scope — vendored slang SystemVerilog adapter and structural Verilog netlists

Status: Accepted
Date: 2026-10-22

## Context
D2 makes SystemVerilog a front end reached through an adapter, and v1.0 (D10) deferred it. Peter's
reverse-engineering goal and the VTR flow both need SV designs read inside Odin III without an
external tool: the Yosys plugin path (sv-elab) exists outside this repository and would add a
subprocess and a second IR. The gate flow's `write_verilog` already writes library cell instances
by type and pin name, so a mapped netlist made by Odin III can in principle be read back by Odin
III's own Verilog front end.

## Decision
Peter, 2026-10-22: v1.1.0 is the vendored SV slang adapter plus the structural Verilog netlist
writer. In detail:

- `third_party/slang` is slang v12.0 (the commit sv-elab `8911a6ca` pins) with fmt, boost.regex
  and tomlplusplus vendored as source, so configure and build need no network
  (`third_party/slang/VENDORING.md`, `BUILDING.md`).
- `adapters/slang/` is the C++20 shim: it links slang, walks the elaborated AST and emits the
  Odin III elaborated AST through the `odin3_ast_*` builders, then drives stage 2
  (`odin3_ast_elaborate`). It exports exactly one C function, `odin3_read_slang`, in its own
  shared library; the core stays C17 (D8′).
- ABI v6 adds the reader seam `odin3_sv_reader_register`/`odin3_sv_read_fn`; the CLI registers
  the adapter at start-up and `read_verilog` routes `.sv`/`.svh` files and a project's
  SYSTEMVERILOG entries to it. A mixed Verilog/SystemVerilog read, `--lib`, `--parse-only`,
  `-icells`, `-netlist` and `--vtr-compat` are refused on that path.
- The structural Verilog roundtrip: `proc; opt; lower; abc --gates L; dfflibmap L;
  write_verilog` writes the mapped netlist as library gate cell instances, and the owned Verilog
  reader binds an instance of a registered bit-granularity cell type to that type.
- The build stays unchanged for hosts that configure `-DODIN3_WITH_SLANG=OFF` (CMake 3.28 is
  required only when it is on, and it defaults on).

Spec: `docs/DESIGN.md` §4.2 and §12.1. Release log, tests and agent defaults:
`docs/V1.1.0.md`.

## Consequences
Positive:
- SV designs elaborate and synthesize to structural Verilog netlists inside Odin III alone.
- The IR, the gate flow and the writers stay one implementation; the core stays MIT/C17.
Negative:
- A large vendored tree (slang and three dependencies) and the only C++ outside `third_party/`.
- The adapter's limits are real v1.1.0 limits: functions and tasks, `foreach`, `unique`/
  `priority`, intra-assignment timing, strengths, `ref` ports and interface-port pass-through are
  located errors, not silent drops (`docs/V1.1.0.md` item 6).
