# D1: One IR, two granularities

Status: Accepted
Date: 2026-10-08

## Context
Odin III has forward synthesis, reverse engineering (RE), and verification, and each needs to
read, write, check, or rewrite the same design (spec §1). Separate data structures per
granularity would mean duplicating every reader, writer, checker, simulator, and the matcher.

## Decision
There is one IR with two granularities: a word-level "RTLIL view" and a bit-level "netlist
view". Passes `lower` (word to bit) and `raise` (bit to word) move between them. `to_rtlil` and
`to_netlist` are views/checks over the one IR, not separate data structures (spec §2, D1).

## Consequences
Positive:
- Every writer, reader, checker, simulator, and the matcher exist once (spec §2 rationale).
- RE is `lower` run backwards (spec §8).
Negative:
- Mixed granularity must be tolerated during `lower`/`raise` (spec §5.4: legal there only), so
  `check` must understand the granularity tag on every node. (Amended 2026-10-08, `docs/IR.md`
  IR-9: two structural tags, `module` and `port`, join the four; both views allow them.)
Forces on later phases:
- Phase 1: core IR, op registry (cell types carry a `granularity` tag: `word`, `bit`, `hard`,
  `blackbox`; spec §5.2), `check`, and the views (spec §5.4).
- Phase 3: `lower`. Phase 6: `raise` (spec §12).
- Both views assert their node sets: rtlil view = `word`/`hard`/`blackbox`; netlist view =
  `bit`/`hard`/`blackbox` (spec §5.4).
