# D3: MIT license; external tools are subprocesses except ABC (linked)

Status: Accepted
Date: 2026-10-08

## Context
The project is open source under MIT (spec §1). It uses several external tools. The core must
stay MIT; ABC's permissive license allows linking (spec §2 rationale).

## Decision
- License: MIT.
- External tools run as subprocesses: GHDL, Yosys (as oracle), Quartus, VPR.
- ABC is the exception: it is linked as `libabc`.

## Consequences
Positive:
- Core stays MIT; no copyleft code is linked in.
- libabc is C, which fits the C17 core (D8' rationale).
Negative:
- Subprocess tools cost process spawn and file round-trips, and need robust invocation.
- A linked ABC ties the build to a libabc build (Phase 3).
Forces on later phases:
- Phase 3: libabc linked; `abc` pass on the soft-logic cone, with black boxes preserved and
  results read back and re-stitched (spec §6 step 10).
- Spec §13 #2 fallback (linking libghdl) would be a separately-licensed optional module, i.e.
  an exception to this rule that must stay outside the MIT core.
- Phase 0: oracle runs (Yosys, Parmys, VPR) are subprocess-based.

## Related
- D2 (GHDL subprocess), D4 (ABC `cec`/`dsec`), D8' (libabc is C).
- Spec §1, §6 step 10, §10, §13 #2.

Revisit if: ABC's license changes or linking it proves unworkable, or a subprocess tool must
be linked for performance or fidelity.
