# D10: v1.0 scope (2026-10-19)

Status: Accepted
Date: 2026-10-19

## Context
Peter re-scoped v1.0 on 2026-10-19: "since our goal is to make Odin III ... I just want the
tool to work". On reverse engineering: "go with all the recommendations (we will be looking
reverse engineering from a different perspective of the goal of going from altera all the way
up) I would like to target Altera devices with LPM and structured verilog, but I'm not
interested in their low-level formats."

The original plan (spec §12) ended Phase 4 on QoR parity, built a subgraph matcher (D5) and
Altera primitive atoms with `bind`/`unbind` (D6), and spent Phases 5 and 6 on SystemVerilog,
VHDL, `raise`, VQM/EDIF and Titan. Verilog-2005 is close to good enough, and the Altera work
that matters is LPM structural Verilog, not device atoms or vendor netlist formats.

## Decision
v1.0 is: the tool works on VTR architectures and on Altera via LPM.

- **Phase 4** is "the tool works on VTR architectures and on Altera via LPM". QoR parity is no
  longer an exit criterion. Kept: VPR-XML import (4.1), generic hard blocks by exact port
  signature (4.2), multiplier splitting from the arch (4.3), memory depth/width splitting
  (4.4), carry chains from the arch model (4.5), FF feature matching (4.6), memory port merge
  (4.7), the arch-sweep exit test (4.13), and new 4.14, the Altera target: an LPM tech library
  (`.o3lib`), mapping word-level cells to LPM megafunctions (partial map), a structural Verilog
  writer that instantiates LPM modules with parameters, and reading LPM-structured Verilog back
  with LPM instances as hard cells. Dropped: FSM detect/recode (4.8; this moves PHASE3 decision
  #43's placement of `fsm` out of v1.0), mux collapsing (4.9; already done by `opt`:
  `opt_muxtree`, `opt_reduce`), matcher v1 (4.10), project mapping rules (4.11), per-bit
  `opt_dff` parity (4.12).
- **Phase 5** (SystemVerilog via slang, VHDL via GHDL) is delayed. Nothing is built. The method
  is recorded in DESIGN §12.1.
- **Phase 6** is removed from v1.0 (`raise`, RE scorecard, VQM/EDIF, Altera `bind`, primitive
  library v0, Titan). It is recorded in DESIGN §12.1. Reverse engineering is now approached
  "from Altera (LPM structural Verilog) up", which 4.14 starts.
- **Phase 7** is kept except the EDIF writer (7.5, dropped): CIRCT writer, Yosys JSON reader,
  visual tooling polish, docs (including the extension-API review), release.

Amends D5: the subgraph matcher is not in v1.0. Hard blocks are matched by exact port
signature and fixed rules (the 3C hardmap rules, the arch-derived rules of 4.2 to 4.6).
Amends D6: Altera is supported through LPM structural Verilog. There are no device atoms
(`stratixiv_*`/`cycloneiv_*`), no `bind`/`unbind`, no VQM/EDIF, no Titan.
Touches D2: SystemVerilog and VHDL adapters are deferred; D2 itself stands.

Peter's follow-up, 2026-10-19: "Cyclone V is fine, go ahead just a basic set of memory and
simple items is fine - it's just a basic path". The device family is Cyclone V (Quartus Lite).
The LPM set is exactly `lpm_add_sub`, `lpm_mult`, `lpm_compare` and `altsyncram` (single- and
simple-dual-port); flip-flops are plain DFFs in soft logic (agent default); everything else is
soft logic as generic structural Verilog gates or assigns. This answers DESIGN §13 question 5
for v1.0.

## Consequences
Positive:
- A short path to a tool that works on VTR archs and emits Altera-usable LPM Verilog.
- No matcher, no pattern DSL work, no Titan-scale runtime risk in v1.0.
- `.o3lib` hard cells and the Verilog front end are reused for the Altera direction.
Negative:
- No generic inference of arbitrary DSP/MAC structures; unknown blocks need exact port
  signatures.
- The RE thread (spec §1 thread 2) and the paper-2 results (RE round trip, Titan) are not in
  v1.0.
- QoR parity with Parmys is measured (Phase 3 table) but not a gate after Phase 3.
Forces on later phases:
- Phase 4: PHASE4.md is the plan.
- Phase 3 is unchanged; the 3C hardmap rules remain the base that 4.2 to 4.6 generalise.
- IR provenance, IDs, hierarchy and the C ABI stay intact so a matcher, `raise` and other
  plugins can be added later without core changes.
