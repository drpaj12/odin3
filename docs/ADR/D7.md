# D7: Not built on MLIR/CIRCT

Status: Accepted
Date: 2026-10-08

## Context
CIRCT/MLIR is an obvious foundation for a hardware IR. The spec's reason against it: the LLVM
dependency and SSA semantics "fight the node/pin/net model needed for RE and in-place
rewiring" (spec §2).

## Decision
Odin III is not built on MLIR/CIRCT. It borrows ideas: op registry, pass manager, verifiers,
first-class attributes. It provides `write_circt` (hw/comb/seq) and, later, `read_circt`.

## Consequences
Positive:
- No LLVM dependency; the node/pin/net model stays intact for RE and in-place rewiring
  (spec §5.1).
Negative:
- The op registry, pass manager, and verifiers must be built in-house.
Forces on later phases:
- Phase 1: op registry (spec §5.2, "CIRCT-inspired"), pass manager, `check`.
- Phase 7: CIRCT writer (hw/comb/seq); `read_circt` and JSON reader (spec §9, §12).

## Related
- D1, D8' (C core; no LLVM), D9.
- Spec §5.1, §5.2, §9, §14.

Revisit if: the node/pin/net model is shown not to be required for RE and in-place rewiring,
or interop demand makes `write_circt`/`read_circt` insufficient.
