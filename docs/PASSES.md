Stage 2 (2D Task 17; EL-2, EL-23, EL-24, EL-45, EL-46) binds the elaborated store, makes one IR module per `MODULE` with its ports (declared range and sign, `scalar` without a range, a SOURCE record at the `PORT_DECL`) before any body, then one wire per net or variable declarator named by its scope path (`g[0].t`, `blk.count`, `$unnamed_block$1.tmp`) with a SOURCE record at the declarator (`hier` = `<module>/<scope path>`) and the declaration's attributes (none: INT 1, `NUMBER`: BITS, `STRING`: STRING); a function's locals are inlined, a memory is `elab2_mem.c`'s. Stage 2 also generates expressions (2D Task 18; EL-28, EL-30, EL-31, EL-32 reads): `assign` and net declaration assignments (`wire w = e;`, a port's too) drive the lhs nets by construction (the rhs's outermost cell has the lhs nets as its `Y`) or merge the two nets (`odin3_net_merge`, the rhs net kept; the same net twice is a no-op); the lhs is a net or variable, a constant bit or part select of one (`+:`/`-:` included) or a concatenation (`continuous assignment to 'y' with a non-constant index is not supported`; bits outside the net are dropped with `assignment to bits outside 'y' [7:0] is ignored`). Every operator becomes one registered word cell with genrtlil's parameters (`$add $sub $mul $div $mod $pow $and $or $xor $xnor $not $neg $shl $shr $sshr $eq $ne $lt $le $gt $ge $reduce_* $logic_not $logic_and $logic_or $mux`; `~&`/`~|` a 1-bit reduction and a `$logic_not`; `2 ** b` a `$shl`; `+a`, concatenation, replication, `$signed` and `$unsigned` no cell), all-constant operators fold through `odin3_cval_op`, `===`/`!==` are exact on constants and a wildcard `$eq`/`$ne` otherwise, and a select is wiring when its index is constant (`range select [9:6] of 'w' is out of bounds; bits outside [7:0] are x`, `part-select [0:3] of 'w' is reversed relative to its declaration [7:0]`) and a `$shiftx` (with the `$sub` offsets of EL-32) when it is not. A cell over `ODIN3_ELAB_MAX_CELL_PINS` is `cell of N pins exceeds the limit of M pins` (fatal). Stage 2 also lowers drivers, instances and gates (2D Task 19; EL-10, EL-11, EL-26, EL-28, EL-29): every driver of a net bit is claimed before it attaches (A4 `'y[3]' has two drivers (also driven at f.v:L:C)`, `'u' is a uwire and has a second driver (first at …)`, a `supply0`/`supply1` net is the shared constant, `{n4[0], n4[0]}` is A4), `wand`/`wor`/`triand`/`trior` collect their drivers and chain them in `$and`/`$or` at the end of the module (declarator provenance), `c ? d : 'bz` and `bufif*`/`notif*` are a `$tribuf` on a top-level output or inout port (`tri-state driver on 't' is supported only on a top-level output or inout port (D3)` elsewhere; an `inout` pin with logic on one net is the F22 error), an `INSTANTIATION` is a node of the module's, black box's or registered cell type with its connections resized to the ports (I4: `port 'a' of instance 'u' (module 'sub') is 8 bits; the connection of 4 bits is extended`/`… is truncated`, an unconnected input the x constant, an output wider than its port driven by the port's top bit when the child declares it `signed`, else 0; cell-type parameters inferred from the connection widths; `parameter:<NAME>` attributes), a `(* blackbox *)` definition is one cell type under its base name (`black box 'x' does not match the registered cell type: <why>`), gates are `$and`/`$or`/`$xor` folds (`$not` after for nand/nor/xnor, buf/not per output, `$tribuf` for bufif/notif), a wire with sinks and no driver warns once (`'w' is never driven`) and `'r' is a variable assigned by a continuous assignment; treated as a net`. Stage 2 also decides and emits memories (2D Task 20; EL-27, EL-39 reads): each array (a declarator with unpacked dimensions) is one `$mem` or one register per word by Yosys's `mem2reg_as_needed` rules (a net array or `(* mem2reg *)`; written in an `always` without exactly one edge event; read after a blocking write of the same block; inside an lvalue's index or a concatenation lvalue; written only at constant indices (a `for` with constant bounds counts: Yosys unrolls it first); `(* nomem2reg *)` exempts it from the last four, `--nomem2reg` from all and errors on an array it leaves that `assign` or a combinational block writes: `array 'w' cannot be a memory (it is written in a combinational block) and --nomem2reg is set`), with `replacing memory 'm' with list of registers; see t.v:12` at the declarator; the words of registers are wires `m[k]` (a constant index reads or assigns the word, out of range is x with a warning, a variable index into registers is a case over the words, Task 23), and a memory is one `$mem` per array with an asynchronous read port per `m[i]` (the raw index on `RD_ADDR`, `OFFSET` the lowest declared index, a multi-dimensional array's row-major address as `$sub`/`$mul`/`$add` cells), `memory 'm' of N bits exceeds the limit of M bits` (fatal) above the memory-bits cap. Stage 2 also builds processes (2D Task 21; EL-33 to EL-35, EL-41 T9/T10): each `always` block is one `$proc` node (or none when it has no output), made whole by the process generator (`pg.h`) following Yosys's `ProcessGenerator`: the sorted lvalue bits are the outputs, each with a `$0` temporary net and, per chunk (a run of consecutive bits of one variable), a root hold action `t0 = c` and a sync action `c <- t0`; blocking assignments update `rv` so later reads see the value, non-blocking ones do not (`q <= q + 1` and `r2 <= r1` read the register); an assignment removes the earlier actions of its bits and appends one action per run of consecutive temporary bits, the leftmost part of a concatenation first; `O` pins are the nets some action assigns and `I` pins every other net read, constants on their shared nets, both in net-ID order, so the node's `BODY` is IR-19's canonical layout (cases, switches and actions numbered breadth first). An event list is one sync per `posedge`/`negedge` (`posedge on 'x', which is N bits; a 1-bit signal is needed`) or one `ALWAYS` for `@*` and level lists (`incomplete sensitivity list: 'b' is read but not listed; the block is built as @*`); `--nolatches` drops the hold actions of a block with no edge and reads x until an output is assigned. `'w' is a net assigned in an always block; treated as a variable`; every output is claimed through the driver table (`'r[2]' is assigned in two always blocks (also at f.v:L:C)` T10 and A4 against continuous drivers; `'r' is assigned with both '=' and '<=' (also at f.v:L:C)` T9), and the conflicting chunk is dropped from the body. The attributes of the `always` are the node's, and each action, case and switch has the SOURCE record of its statement. Stage 2 also builds `if`, `case`, `casez` and `casex` (2D Task 22; EL-36): a switch on `$reduce_bool(c)` (an `if`) or on the selector with the item expressions as compares at the widest width (a `case`; `casez`/`casex` wildcards are `ANY`, the default item is the last case wherever written, an item may be an expression), the bits the branches assign by `=` get case temporaries (one group per chunk, entry `t1 = rv(bits)`, exit `lv(bits) = t1`, an added default holding them or x under `full_case`), `full_case`/`parallel_case` attributes and metacomments are the switch flags with D1's two warnings (`'full_case' is honoured: case values no item lists assign x`, `'parallel_case' is honoured: case items are not prioritised`), and a condition or selector and items that are literals and parameters fold to the branch they take; a bit or part select (`y[s]`, `y[b +: w]`) with a non-constant index as a target is the case method (a position temporary, a case per position the index can hold, no default for `<=`; inside a concatenation `non-constant index into 'y' is not supported in a concatenation target`). Stage 2 also unrolls loops and inlines calls (2D Task 23; EL-37, EL-38): `for` (a constant condition on the variable the generator holds as a constant; `for-loop condition is not constant (it reads 'n')`, `for-loop initialisation and step must assign the same variable`, `loop variable 'i' is assigned in the loop body`, `loop exceeds N iterations`, the run's total counting on from the generate loops: `unrolled loops exceed N iterations in this design`) and `repeat` are unrolled, the variable an output only when the module reads it outside its loops; a user function or task call is tried by the interpreter first and else inlined through a frame of unnamed wires (`function 'f' has N inputs; M arguments given`, `recursive call of 'f' cannot be inlined (its arguments are not constant)`, `function call nesting deeper than N at 'f'`, `function 'f' can be called only with constant arguments (it uses 'while')`, `output argument N of task 't' must be a variable`); a call in a continuous context is a `$proc` of its own; the word of a register array with a variable index is a case over the words (a read inline in a process or a `$proc` of its own, a write one word per case); mem2reg rules 2 to 5 scan called bodies. Stage 2 also writes memories and initial values (2D Task 24; EL-39, EL-40): `m[i] <= d` in a block with exactly one edge event is one write port of the memory's `$mem` (in source order; `WR_CLK` the edge's net, `WR_CLK_POLARITY` its edge), whose address, data and enable are three process-local variables per statement (`addr`, `data`, `en`: assigned `x`, `x`, `0` at the start of the block and `i`, `d`, all ones by the statement, so every path assigns them and `proc` builds no feedback; a constant index or full-word constant value needs no variable; no sync action; they join every `if`/`case` switch the statement is in, so a loop or a call makes one set per execution); a partial write (`m[i][3:0]`) sets the enable on those bits, a concatenation target with a word is split per part as Yosys does, a non-constant bit select of a word and a word in a nested concatenation are located errors, and a write in a block without exactly one edge to a `(* nomem2reg *)` array is `array 'm' cannot be a memory (it is written in a block without exactly one edge) and (* nomem2reg *) is set`. Every `initial` block and variable initialiser (`reg r = 4'd5;`) runs statement by statement through the interpreter after the instances and assignments (a statement that reads an input or a net driven by logic is `initial statement is not constant and is ignored`): a value an `always` block assigns is the wire's `init` attribute (or a `$mem`'s `INIT`), a variable nothing else drives is merged onto the constant net, and a value on a net driven by a continuous assignment, an instance, a gate or an input port is `initial value of 'w' is ignored: 'w' is driven by a continuous assignment` (`an instance`, `a gate`, `an input port`); `initial values need more than N bits` is the cap. `$readmemh`/`$readmemb` as a statement of an `initial` reads the file as Yosys does (`//` and block comments, `@hex`, `_`, `x`, `z`; the path beside the source file, never the working directory) into the memory's `INIT` (`cannot open 'f' for $readmemh`, `bad address '@zz' in 'f' line N`, `bad word 'g' in 'f' line N`, `'f' is larger than N bytes (the $readmem limit)`). No construct is left pending: the point (l) tables are empty. On success it sets the design's top and logs `read_verilog: elaborated top 'T': M modules (S specializations), P processes, C cells, N nets, t1 + t2 ms`; after any stage-2 error the top stays unset and the design holds valid, incomplete modules (fit only for destruction). A construct whose elaboration has not landed is the located `elaboration is not available yet (2D): '<KIND>'` (`PARSE`), once per kind, the rest of the module is still emitted. Caps: `elaboration needs more than 67108864 net bits` (at the declarator) and the byte budget `elaboration needs more than N bytes (the budget is 60% of physical memory)`, both fatal. Keep levels: the elaborated store and its symbol table are handed to the design under `--keep-ast` (ELABORATED or ALL) and otherwise destroyed at the end of the read (also after a failure), the parsed store under `--keep-ast=all` only. CLI: `odin3 --elab-only a.v b.v` is `-p "read_verilog a.v b.v; stats"` (with `--project`/`-f` the record's files; with `-p` or a `.o3` script it exits 2: `--elab-only cannot be combined with a script; use read_verilog in the script`); `odin3 --parse-only a.v b.v` is `-p "read_verilog --parse-only a.v b.v"`; with `--project`/`-f` the read_project runs first and `read_verilog --parse-only` follows; `--parse-only` with `-p` or a `.o3` script file exits 2 ("use the pass option"). |

**Processes** (2D EL-33, as amended in 2D spec v4.2, "mode P"). Each pass declares whether it may
run on a design that still has processes (`$proc` nodes, `docs/IR.md` IR-19): the
`odin3_pass_def.processes` flag (`ODIN3_PASS_PROCESSES_OK` or `_REFUSE`), and for a plugin pass
the `odin3_plugin_pass.processes` slot (NULL is `REFUSE`). Before a `REFUSE` pass runs, the pass
manager fails it when some module has a process, naming the first such module in creation order:
`pass '<name>': module '<m>' has processes; run proc first` (`ODIN3_ERR_INVALID_ARG`; nothing
runs, no pass run is opened). The `OK` passes are `read_blif`, `read_techlib`, `read_project`,
`dump_project`, `preprocess`, `check`, `stats`, `compact`, `hierarchy`, `write_verilog_ast`,
`write_rtlil` (2D) and `proc` (2E, which lowers them); `read_verilog` (2C/2D) and the eight opt
passes of 2F (`opt`, `opt_expr`, `opt_merge`, `opt_muxtree`, `opt_reduce`, `opt_share`, `opt_dff`,
`opt_clean`) are `OK` (registered by 2F Task 4; all eight are real). Every other pass is `REFUSE`: here `write_blif`, `write_json`,
`write_verilog`, `write_dot` and `sim`; later `flatten`, `lower` and `abc`. An `OK` pass treats a
`$proc` node as opaque (no constant propagation or CSE through it; its `O` pins drive unknown
values, its `I` pins read); `opt_muxtree` and `opt_clean` skip a module that still has processes.
The writers `odin3_blif_write`, `odin3_json_write`, `odin3_verilog_write` and `odin3_dot_write`
also refuse such a design themselves, for callers that bypass the pass manager: `module '<m>' has
processes; run proc first`, before the path is opened.
