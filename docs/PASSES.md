# Passes

One entry per pass, added by the `/new-pass` skill and kept in pipeline order (spec §6).

| Pass | Phase | Input view → output view | Source | Golden test | Notes |
|---|---|---|---|---|---|
| `read_project [--format o3proj\|f\|qsf\|odin2] [--revision <r>] <entry>` | 2 (2B) | — → same (project record) | `src/frontends/project/*.c`, `src/passes/project_pass.c` | `test_project_pass`, `cli_project_dump`, `cli_project_top`, `cli_project_revision` | PRJ-16: fills the design's project record (`odin3_project_read`); format from the entry's suffix unless `--format`; `--revision` (else the CLI's) selects a Quartus revision; the CLI's `--top` replaces the project's top (info line when they differ). Runs no front end; a `flow` is stored, not run. A second read is `INVALID_ARG`; a failed read drops the record. CLI: `--project FILE`, `-f LIST` prepend it. |
| `dump_project [<file>]` | 2 (2B) | — → — | `src/frontends/project/dump.c`, `src/passes/project_pass.c` | `test_project_pass`, `cli_project_dump` | PRJ-17: the record as the corpus's JSON (README keys and order, resolved paths) on stdout, or written atomically; `INVALID_ARG` when no project was read. CLI: `--dump-project` appends it. |
| `preprocess [--out <dir>] [--segments]` | 2 (2B) | — → — (debug) | `src/frontends/verilog/*.c`, `src/passes/project_pass.c` | `test_project_pass`, `cli_project_preprocess` | PRJ-17: the record's Verilog design files in listing order through one preprocessor (project defines and include directories; the includer's directory first, never the working directory). Each stream to stdout, or `<dir>/<n>.v` (`n` from 0), with `--segments` `<n>.segments.json` (`[{out_offset, file, line, col, buffer_kind, macro, spell_file, spell_line, spell_col}]`: `file:line:col` is the file location, `spell_*` where the segment's bytes are spelled, chased to their `FILE` buffer, for the §10.5 fuzzers (agent default, 2B Task 13); files named per `--diag-paths`, `null` fields for a loc-0 segment), and `<dir>/files-read.txt` (resolved, first-read order). `<dir>` is created when missing. |
| `read_blif <file>` | 1 (1C, 1D) | — → netlist (BLIF cells, black boxes) | `src/frontends/blif/reader.c`, `src/passes/builtin.c` | `blif_roundtrip_fixtures`, `cli_*_roundtrip` | Empty design only; the first model is the top (`odin3_design_set_top`), the CLI `--top` then wins. |
| `read_techlib <file>` | 1 (1G, 1D) | — → same (cell types added) | `src/techlib/reader.c`, `src/passes/builtin.c` | `test_pass_manager` (read_techlib), `cli_techlib`, `blif_roundtrip_techlib` | Each cell of a `.o3lib` becomes a local cell type with its library data; read it before the netlist that instantiates the cells. |
| `hierarchy [--top <name>] [-auto]` | 1 (1D) | any → same (top recorded) | `src/passes/builtin.c` | `test_pass_manager` (hierarchy) | `--top`, else CLI `--top`, else a set top is kept unless `-auto`, else the single uninstantiated module; 0 or ≥2 candidates is an error listing them (DESIGN §4.0, PHASE1 #18). |
| `check [--fast]` | 1 (1B, 1D) | any → same | `src/ir/check.c`, `src/passes/builtin.c` | `test_ir_check`, `test_pass_manager` | IR.md §9; FAST = rules 1–5, 11. Also run FULL by the pass manager before/after every pass in Debug (`--check` in Release). |
| `compact` | 1 (1B, 1D) | any → same (IDs renumbered) | `src/ir/compact.c`, `src/passes/builtin.c` | `test_ir_compact`, `test_pass_manager` | IR-6; tombstones for dead objects. Atomic per module only: an out-of-memory failure leaves earlier modules compacted. Not yet wired: `odin3_symtab_remap` after each compacted module of a design that keeps its symtab (spec 2A §8; 2D wires it, PHASE2 #8). |
| `stats` | 1 (1D) | any → same | `src/passes/builtin.c` | `test_pass_manager` (stats format) | Logs `stats: design: modules N, top T`, then per module ports/nodes/nets/wires (live) and a name-sorted cell-type histogram; the Python walk (1D T4) matches it. |
| `write_blif <file>` | 1 (1C, 1D) | netlist → — | `src/backends/blif/writer.c`, `src/passes/builtin.c` | `blif_roundtrip_fixtures`, `cli_*_roundtrip`, `cli_top_written_first` | The top module first (BLIF's first model is the top), then the rest in creation order. |
| `write_json <file>` | 1 (1F, 1D) | netlist → — | `src/backends/json/writer.c`, `src/passes/write_formats.c` | `writer_check_fixtures`, `test_pass_outputs`, `cli_writers` | Yosys-schema JSON (every module, then declared black-box stubs); written atomically. |
| `write_verilog <file> [--name-style short\|provenance]` | 1 (1F, 1D) | netlist → — | `src/backends/verilog/writer.c`, `src/passes/write_formats.c` | `writer_check_fixtures`, `test_pass_outputs`, `cli_writers` | Structural Verilog-2005 with `// file:line` provenance comments; `short` names by default, `provenance` gives `hier/name@file:line` names (IR §6). The path may come before or after the option. |
| `write_dot <file> [--focus F] [--max-nodes N]` | 1 (1F, 1D) | netlist → — | `src/backends/dot/writer.c`, `src/passes/write_formats.c` | `writer_check_fixtures`, `test_pass_outputs`, `cli_writers` | Graphviz dot. `F` is `cone(<net>)` or `cone(<module>:<net>)` (fan-in cone), `<file>:<line>` (digits after the last `:`; the provenance forward index), else a hierarchical path `module/inst/…`; a focus lifts the budget. Without one, more than `N` nodes (default 2000) is refused with the count. |
| `sim <cycles> <seed> [<file>\|-]` | 1 (1E, 1D) | netlist → same | `src/sim/*.c`, `src/sim/vectors.c`, `src/passes/sim_pass.c` | `test_pass_outputs`, `cli_sim`, `sim_check_fixtures` (driver) | Simulates the design's top for `cycles` cycles, inputs from the seeded PRNG. With a file (`-`: stdout) it writes the vectors in the `odin3-sim-vectors` format (`src/sim/vectors.h`, shared code) titled `# odin3 sim <top> seed S cycles N`; without one it logs `sim: <top>: N cycles, seed S; last cycle: <vector>`. Tech libraries come from an earlier `read_techlib`. The design is not changed. |
| `write_verilog_ast <file>` | 2 (2A) | AST → — | `src/ast/print.c`, `src/passes/builtin.c` | `test_pass_manager` (write_verilog_ast), `cli_keep_ast` | Prints every AST store the design holds for the latest read run (parsed, then elaborated), each after a `// odin3 write_verilog_ast: run N, <form> AST` line and each UNIT after `// unit <name> at <resolved file:line:col>`; written atomically. Wants the AST (`wants_ast`): a script naming it raises the keep level to elaborated before anything runs (`--keep-ast=all` also keeps parsed stores). No AST held is an error. |
