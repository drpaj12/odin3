# What hardmap-diff may report for a design other than identical or equivalent (3C spec 9.3, 10).
# Syntax: `<path> <id> <reason>`; <path> is relative to tests/micro/verilog (a micro) or
# benchmarks/verilog (a VTR design). <id> is one of
#   D<n>           the design differs from Parmys by the divergence of spec 10 (equiv-check: not
#                  equivalent), with the same hard-block counts;
#   counts:<+N|-N> <unit>   the unit's count differs from Parmys by exactly N (the netlists are
#                  then not compared); the reason names the divergence;
#   unproven       equiv-check cannot decide the design (tests/exit/vtr_unproven.txt).
# A reason is required on every line. An entry that no longer occurs is stale and fails: the list
# shrinks. A `run wreduce first` warning is never listable.

# D15 (new, 2026-10-17): Parmys's Yosys (opt_mem) deletes a memory that has no write port and no
# INIT; its read data is x and the golden netlist has no RAM and undriven outputs. Odin III's opt
# has no opt_mem, so hardmap maps the read-only memory to RAM slices with we on gnd (R-10 p_1_0).
# Not a hardmap rule: the fix is an opt_mem rule in 3G. By reading the BLIFs (not a recorded run):
# the golden BLIFs have no subckt and Odin III's slices carry data and we on gnd. The `counts:`
# lines skip the comparison, so nothing here proves that no defined value differs.
common/1r.v counts:+8 single_port_ram D15: read-only memory without INIT, Parmys deletes it (opt_mem), Odin III maps 8 slices
common/2r.v counts:+8 dual_port_ram D15: read-only memory without INIT, Parmys deletes it (opt_mem), Odin III maps 8 slices

# D6 evidence (2026-10-17, owed since 3C-1): with every `adder` subckt of both BLIFs expanded to
# sumout = a^b^cin, cout = maj(a,b,cin), equiv-check says micro/multiply_hard_block.v is equivalent
# (abc cec) and twobits_arithmetic_multiply.v is equivalent (abc dsec): only the adder count differs.
common/bram.v counts:-8 dual_port_ram D9: Parmys drops RD_EN and maps 8 slices, Odin III leaves the `$mem` soft (R-10)
micro/multiply_hard_block.v counts:-8 adder D6: Parmys builds each 2x2 multiplier from AND gates and 4 hard adders, Odin III leaves the `$mul` soft (M-2)
operators/twobits_arithmetic_multiply.v counts:-4 adder D6: Parmys builds the 2x2 multiplier from AND gates and 4 hard adders, Odin III leaves the `$mul` soft (M-2)

# D2b (3C spec 10): the top stage of an unsigned `$sub` whose result is wider than the operands. The
# 2026-10-17 run of the full `lower` shows it on this micro: Parmys wires the top adder's a and b to
# `unconn`, so out[2] is the carry (the borrow is lost); Odin III uses a=gnd, b=vcc and is RTL-correct.
# hardmap's choice (A-8), not lower's.
operators/twobits_arithmetic_minus.v D2b top adder of the unsigned `$sub` pads with vcc (RTL-correct); Parmys uses unconn and loses the borrow

# D15 on the full `lower` (2026-10-17): with a constant-free read enable hardmap leaves the read-only
# `$mem` soft (R-10), `lower` turns its read data `$dffe` into latches (3 x 8 in nr) and Parmys, whose
# opt_mem deleted the memory, has none. Not a hardmap or lower rule: opt_mem is 3G.
common/rom.v counts:+8 latch D15: read-only memory without INIT, Parmys deletes it and its read register (opt_mem), Odin III keeps the 8 read-data flops
common/nr.v counts:+24 latch D15: three read-only memories without INIT, Parmys deletes them and their read registers (opt_mem), Odin III keeps 3 x 8 read-data flops

common/bram.v counts:+136 latch D9: the soft `$mem` is lowered to 16 x 8 bit latches plus 8 read-data latches
