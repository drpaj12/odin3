# Parmys golden because Parmys ITSELF rejected the design. It counts as passing, so every entry needs
# a needle. One line per micro: `<path relative to tests/micro/verilog> [needle] <one-line reason>`,
# the same syntax and matching as elab-sweep's lists. `exit-check` classifies a golden whose recorded
# status is `failed` as a `reject` (a failure unless listed here), and the needle must appear in its
# log: `[Parmys rejected the design]` is exit-check's own message. The reason is the first error line
# of the oracle's log (golden/<arch>/regression/verilog/<group>/<leaf>/<leaf>.parmys.log), which
# `golden/` keeps. Rejections that are oracle-HARNESS gaps (a missing include or -D) are not here:
# they are `no-golden` (tests/exit/micro_nogolden.txt, 4 micros), which never counts as a pass.
# A micro whose golden run was CAPPED (large/LargeRam.v) is NOT listed: a cap kill is no verdict on
# the design, so it stays an unexpected `error` until its golden is regenerated with a larger
# ODIN3_ORACLE_MEM_MB. A `differs`, an `error` and a `hard` failure are never listable.
#
