# 5.2 icells-check: the designs a level cannot take, and why (spec section 5, T-5). Format:
#   <level> <design file name> <outcome> <reason>
# An entry for a design that passes is stale and fails the run. Nothing is skipped silently.
#
# X-11: the micro multiply_hard_block.v instantiates the VTR hard block `multiply` (tech library
# lib/vtr.o3lib, tests/icells/techlib.txt). The word and LPM levels read it back (the library
# instances are compared). `write_blif --vtr` cannot write a `multiply` instance: its WIDTH
# parameter is not derivable from the BLIF formals, so the gold of the gate and LUT levels does not
# exist. (The other two hard-block micros, adder_hard_block and hard_adder_cin_propagation, pass
# at all four levels with the soft n-bit adder tests/hardmap/adder_lib.v.)
gate multiply_hard_block.v fail:read write_blif --vtr cannot recover the WIDTH parameter of a multiply instance from the BLIF formals
lut multiply_hard_block.v fail:read write_blif --vtr cannot recover the WIDTH parameter of a multiply instance from the BLIF formals
#
# X-12: Yosys 0.55 has no SAT model of $pow (spec 20.2 of 2F), so the equivalence of a design with
# a $pow cell is unproven at the word, LPM and inst levels; the text legs (signature fixpoint,
# instances) still run, so the cell itself is checked. `lower` has no bit-level form of $pow, so
# the gate and LUT levels cannot take the design.
word cell_pow.v unproven Yosys has no SAT model of $pow
lpm cell_pow.v unproven Yosys has no SAT model of $pow
inst inst_pow.v unproven Yosys has no SAT model of $pow
gate cell_pow.v error:script lower has no bit-level form of $pow
lut cell_pow.v error:script lower has no bit-level form of $pow
